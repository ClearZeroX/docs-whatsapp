# AI 备用素材模版技术设计方案

> 文档基准：`feature/zlc/0826-ai-backup-material` 相对 `master` 的最终代码差异。  
> 文档只描述当前实现逻辑，不描述历史方案演进和中间态设计。

---

## 1. 背景与目标

主用素材模版中的 body 内容可能因为 Meta 审核或配额策略影响发送效果。本功能在用户接受 AI 建议 body 后，自动生成一个 AI 备用素材模版，并在发送链路中按稳定性等级返回可用的备用素材组合。

核心目标：

1. 支持 AI 建议 body 的单条与批量生成；
2. 用户接受指定 body 后，才将该 body 对应的主用组合同步到备用素材模版；
3. 备用素材模版中的 body 内容由 AI 建议内容替换；
4. 备用素材模版可按稳定性评级参与发送侧查询；
5. 提供创建补偿、body 替换补偿和稳定性缓存刷新 Job；
6. 提供普通素材组与 AI 备用素材组的稳定性统计能力。

非目标：

- 不做完整前端交互设计；
- 不修改主用素材模版的既有 body 语义；
- 不在未接受建议时创建备用素材模版；
- 不保证 Mongo 操作与 MySQL 事务的强一致，依赖补偿机制兜底。

## 2. 总体流程

### 2.1 AI 建议生成

```text
前端调用 generate / batchGenerate
        |
        v
加载 AI 规则快照
        |
        v
构建 systemPrompt / userPrompt
        |
        v
调用 LLM Agent
        |
        v
写入 ai_material_suggestion
```

### 2.2 主用素材模版保存后的联动

```text
保存主用素材模版
        |
        v
保存 Mongo 素材
        |
        v
生成主用素材组合
        |
        v
回填 ai_material_suggestion.material_id / material_group_id
        |
        v
判断是否已有备用素材组 / 是否存在已接受建议
        |
        +--> 无备用组且无已接受建议：结束
        |
        +--> 有备用组或有已接受建议：创建/更新备用素材组
                                        |
                                        v
                              只同步已接受 body 对应的主用组合
                                        |
                                        v
                              尝试替换已接受建议的备用 body
```

### 2.3 发送侧查询

```text
发送侧按 primaryGroupId 查询备用素材组
        |
        v
读取备用素材组稳定性等级
        |
        v
低于最低等级则返回空
        |
        v
返回备用素材组及组合
```

## 3. 数据模型设计

### 3.1 `message_material_group`

新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `primary_group_id` | `bigint(20) NOT NULL DEFAULT 0` | 主用素材组 ID，普通素材组为 `0` |
| `source_type` | `tinyint(4) NOT NULL DEFAULT 0` | `0` 手工创建，`1` AI 自动生成 |
| `ai_suggest_type` | `varchar(50) NOT NULL DEFAULT ''` | AI 建议类型，当前为 `AI_BACKUP_MATERIAL_GROUP` |

同时将 `name` 扩展为：

```sql
varchar(255) NOT NULL DEFAULT ''
```

AI 备用素材组命名规则：

```text
主素材组名称_ai_backup_by_{suggestType}
```

如果名称超长，会截断主素材组名称，保证总长度不超过 255。

### 3.2 `message_material_combination`

新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `primary_combination_id` | `bigint(20) NOT NULL DEFAULT 0` | 对应主用组合 ID |
| `source_type` | `tinyint(4) NOT NULL DEFAULT 0` | `0` 手工组合，`1` AI 备用组合 |

新增索引：

```sql
idx_primary_combination_id(primary_combination_id)
```

### 3.3 `ai_material_suggestion`

`ai_material_suggestion` 表在 master 已存在，本分支扩展 `suggest_type` 语义，并将 `status` 注释更新为 AI 备用素材相关状态。

当前状态：

| code | 枚举 | 含义 |
|---:|---|---|
| 1 | `ACCEPTED_FOR_AI_BACKUP` | 已接受，等待替换备用 body |
| 2 | `NOT_ACCEPTED_FOR_AI_BACKUP` | 用户未接受 |
| 3 | `GENERATION_FAILED` | AI 生成失败 |
| 4 | `APPLIED_TO_AI_BACKUP` | 备用 body 替换成功 |
| 5 | `APPLIED_TO_AI_BACKUP_FAILED` | 备用 body 替换失败 |

`AiMaterialSuggestionStatusEnum` 提供两个扩展方法：

```java
getAcceptedStatuses()
getNotAcceptedStatuses()
```

当前值：

```text
acceptedStatuses = [1, 3, 4, 5]
notAcceptedStatuses = [2]
```

注意：

- `acceptedStatuses` 用于判断“是否触发/保留备用素材组创建”；
- body 替换入口只允许 `1` 和 `5`；
- `2` 不会触发替换；
- `3` 虽然在创建判断的 accepted 列表中，但如果最终没有有效 `material_id`，不会参与备用组合同步。

原唯一键继续用于防止重复插入：

```text
uk_client_material_seq
(
  client_material_key,
  material_type,
  suggest_type,
  source_lane,
  generation_seq
)
```

### 3.4 `ai_backup_material_update_log`

新增表，用于记录备用素材模版的创建、更新和清理动作。

主要字段：

| 字段 | 说明 |
|---|---|
| `primary_group_id` | 主用素材组 ID |
| `backup_group_id` | 备用素材组 ID |
| `ai_suggest_type` | AI 建议类型 |
| `operate_type` | `CREATE` / `UPDATE` |
| `trigger_source` | `SYNC` / `JOB` |
| `before_content` | 变更前内容 |
| `after_content` | 变更后内容 |
| `operator` | 操作人 |
| `create_time` / `update_time` | 毫秒时间戳 |

索引：

```text
idx_create_time
idx_primary_group_id
idx_backup_group_id
```

### 3.5 Mongo 素材 `source_type`

`OpayTemplateComponent` 新增：

```java
private Integer source_type;
```

含义：

```text
0 = manual
1 = AI auto-generated
```

只有复制到备用素材组的 body 元素会设置：

```text
source_type = 1
```

主用素材元素不设置该字段。

## 5. 配置设计

### 5.1 AI 建议与备用素材开关

| 配置 key | 默认值 | 说明 |
|---|---|---|
| `ai_suggestion.batch_generate_size` | `5` | 批量生成单批条数 |
| `ai_backup.enabled` | `false` | AI 备用素材总开关 |
| `ai_backup.sync_create_enabled` | `true` | 主素材模版保存后同步创建/更新备用素材组开关 |
| `ai_backup.min_stability_level` | `B` | 发送侧可使用备用素材组的最低稳定性等级 |

相关既有配置仍会生效：

```text
ai_suggestion.enabled
ai_suggestion.backfill_enabled
ai_suggestion.lane_whitelist
ai_suggestion.max_generation
```

### 5.2 Prompt 配置

Prompt 配置位于 `prompt.properties` 命名空间。

新增：

| key | 说明 |
|---|---|
| `ai_suggestion.batch_system_prompt` | 批量生成 system prompt |
| `ai_suggestion.batch_user_prompt_template` | 批量生成 user prompt 模板 |

模板占位符：

```text
{ruleSnapshot}
{materialType}
{items}
```

### 5.3 稳定性 Redis 链路配置

| 配置 key | 默认值 | 说明 |
|---|---|---|
| `material.group.stability.redisSwitch` | `false` | 新稳定性 Redis 统计链路开关 |
| `material.group.stability.redisRefreshDays` | `14` | Job 刷新非 AI 素材组的时间范围 |
| `material.group.stability.redisCacheMinutes` | `30` | 稳定性统计 Redis TTL |

### 5.4 AI 备用素材稳定性规则

配置 key：

```text
ai_backup.stability_rules
```

配置格式：

```json
[
  {
    "level": "S",
    "condition": "#utilityPercent>=0.5&&#historyUtilityPercent>=0.5",
    "reason": "当前可用占比${utilityPercent}，历史占比${historyUtilityPercent}，等级S"
  }
]
```

支持变量：

```text
#utilityPercent
#totalTemplateCount
#utilityCount
#historyUtilityPercent
#historyTotalTemplateCount
#historyUtilityCount
```

规则按配置顺序匹配，第一条满足条件的规则生效。  
未配置或没有命中时默认返回 `D`。

## 6. 接口设计

接口前缀：

```text
/admin/api/ai-suggestion
```

### 6.1 单条生成 `POST /generate`

用途：

- 对一个素材部位生成 AI 建议；
- 同步等待 LLM 返回。

关键入参：

| 字段 | 说明 |
|---|---|
| `clientMaterialKey` | 前端素材临时唯一 key |
| `sourceLanes` | 可选泳道列表；为空时使用空泳道 |
| `materialGroupId` | 已保存素材组 ID；新建素材时可为空 |
| `suggestType` | 建议类型 |
| `materialType` | 素材类型，当前备用素材场景为 `BODY` |
| `language` | 规则本地化语言 |
| `materialContent.content` | 原始内容 |
| `materialContent.lastSuggestedContent` | 上一次建议内容 |
| `materialContent.userFeedback` | 用户反馈 |

处理逻辑：

1. 校验 `ai_suggestion.enabled`；
2. 校验 `suggestType`；
3. 泳道为空时使用空泳道；
4. 泳道不为空时按白名单过滤，空白名单表示全部拒绝；
5. 校验泳道枚举；
6. 按以下维度统计已有记录数：
   ```text
   clientMaterialKey + materialType + suggestType + sourceLane
   ```
7. 超过 `ai_suggestion.max_generation` 时跳过；
8. 查询规则快照，为空数组时跳过；
9. 构建 prompt 并同步调用 LLM；
10. 写入 `ai_material_suggestion`。

状态写入：

```text
suggestType = AI_BACKUP_MATERIAL_GROUP 时，status = 2
其他 suggestType 时，status = 0
```

### 6.2 批量生成 `POST /batchGenerate`

新增接口。

#### 6.2.1 请求结构

```json
{
  "sourceLanes": [],
  "materialGroupId": 100,
  "suggestType": "AI_BACKUP_MATERIAL_GROUP",
  "materialType": "BODY",
  "language": "en_US",
  "materialContents": [
    {
      "suggestionId": 1,
      "clientMaterialKey": "body-key-1",
      "content": "original body content 1",
      "lastSuggestedContent": "",
      "userFeedback": "",
      "status": "ACCEPTED_FOR_AI_BACKUP"
    },
    {
      "clientMaterialKey": "body-key-2",
      "content": "original body content 2",
      "lastSuggestedContent": "",
      "userFeedback": "",
      "status": "NOT_ACCEPTED_FOR_AI_BACKUP"
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `sourceLanes` | 否 | 泳道列表；为空时使用空泳道 |
| `materialGroupId` | 否 | 已保存素材组 ID |
| `suggestType` | 是 | 建议类型 |
| `materialType` | 是 | 素材类型 |
| `language` | 否 | 规则本地化语言 |
| `materialContents` | 是 | 批量素材内容 |
| `materialContents[].suggestionId` | 否 | 已有建议 ID |
| `materialContents[].clientMaterialKey` | 是 | 前端素材临时 key |
| `materialContents[].content` | 是 | 当前原始内容 |
| `materialContents[].lastSuggestedContent` | 否 | 上一次建议内容 |
| `materialContents[].userFeedback` | 否 | 用户反馈 |
| `materialContents[].status` | 否 | 枚举名，不是 code |

#### 6.2.2 同步阶段

1. 校验 `ai_suggestion.enabled`；
2. 校验 `suggestType`；
3. 校验 `status` 枚举名；
4. 校验 `clientMaterialKey` 在本次请求内不重复；
5. 处理带 `suggestionId` 的已有建议；
6. 处理不带 `suggestionId` 的新建议；
7. 合并已有更新记录与预插入记录；
8. 提交异步生成任务；
9. 立即返回受理结果。

#### 6.2.3 带 `suggestionId` 的已有建议处理

当前实现：

1. 根据 `suggestionId` 查询原记录；
2. 校验记录存在；
3. 校验 `materialType`、`suggestType` 与请求一致；
4. 如果 `origin_content` 与请求 `content` 一致，则跳过 LLM 生成。

content 一致判断规则：

```text
1. 去除首尾空格；
2. 将 \r\n 和 \r 统一为 \n；
3. 字符串完全比较。
```

content 一致时轻量更新：

| 字段 | 说明 |
|---|---|
| `client_material_key` | 更新为请求值 |
| `status` | 请求传了才更新 |
| `updater` | 当前操作人 |
| `update_time` | 当前时间 |

轻量更新后，如果满足以下条件会尝试替换备用 body：

```text
suggestType = AI_BACKUP_MATERIAL_GROUP
status = ACCEPTED_FOR_AI_BACKUP
或
status = APPLIED_TO_AI_BACKUP_FAILED
```

content 不一致时：

- 不新增 `generation_seq`；
- 不插入新记录；
- 复用原记录异步重新生成；
- 原记录 `sourceLane` 会加入本次有效泳道；
- 生成成功后更新原记录。

#### 6.2.4 不带 `suggestionId` 的新建议处理

对每个：

```text
materialContent × sourceLane
```

同步预插入一条占位记录。

预插入字段：

```text
client_material_key
material_type
suggest_type
generation_seq
source_lane
material_group_id
origin_content
last_suggested_content
regen_feedback
suggested_content = 原始 content
status
creator
create_time
update_time
```

`status` 逻辑：

```text
请求传了 status 枚举名 => 使用对应 code
请求未传 status => ACCEPTED_FOR_AI_BACKUP = 1
```

预插入时 `material_id` 仍为空，等素材模版保存后回填。

如果遇到唯一键冲突，会尝试查询同 key 同 generation_seq 的已有记录并复用。

#### 6.2.5 泳道处理

`sourceLanes` 为空：

```text
[""]
```

`sourceLanes` 不为空：

1. 校验泳道白名单；
2. 空白名单表示不允许任何非空泳道；
3. 校验 `SourceLaneEnum`。

带 `suggestionId` 且 content 变化的记录会使用其原记录 `sourceLane`，并加入本次有效泳道。

#### 6.2.6 异步生成

1. 每个有效泳道独立处理；
2. 每个泳道只处理映射到该泳道的记录；
3. 按 `ai_suggestion.batch_generate_size` 分批；
4. 每批查询规则快照；
5. 规则为空时，将映射到该泳道的记录置为失败；
6. 构建批量 prompt；
7. 调用 `generateBatch`；
8. 根据 LLM 返回的 `clientMaterialKey` 匹配请求项；
9. 匹配成功更新记录；
10. 匹配失败写失败原因。

#### 6.2.7 成功更新字段

| 字段 | 说明 |
|---|---|
| `client_material_key` | 更新为请求值 |
| `origin_content` | 请求当前内容 |
| `last_suggested_content` | 请求上次建议内容 |
| `regen_feedback` | 请求用户反馈 |
| `suggested_content` | AI 生成内容 |
| `score` | LLM 自评分 |
| `score_reason` | LLM 评分理由 |
| `llm_raw_output` | LLM 原始输出 |
| `status` | 请求状态或原状态 |
| `rule_snapshot` | 当前规则快照 |
| `prompt` | systemPrompt + userPrompt JSON |
| `updater` | 当前操作人 |
| `update_time` | 当前时间 |

#### 6.2.8 失败状态

失败默认写入：

```java
GENERATION_FAILED = 3
```

特例：

```text
请求 status = "NOT_ACCEPTED_FOR_AI_BACKUP" 时，失败后写入 2
```

#### 6.2.9 body 替换触发

生成成功后，只有满足以下条件才尝试替换：

```text
suggestType = AI_BACKUP_MATERIAL_GROUP
status = ACCEPTED_FOR_AI_BACKUP
```

#### 6.2.10 响应

```json
{
  "acceptedCount": 2,
  "items": [
    {
      "clientMaterialKey": "body-key-1",
      "accepted": true
    },
    {
      "clientMaterialKey": "body-key-2",
      "accepted": true
    }
  ]
}
```

`accepted=true` 表示请求被接口受理，不代表用户已接受该建议。

### 6.3 备用素材状态查询 `POST /backup-material/listAiBackupMaterials`

按 `materialIdList` 查询 AI 备用建议状态。

逻辑：

1. 去重并过滤空 `materialId`；
2. 按 500 个一批查询；
3. 可选追加 `materialGroupId` 条件；
4. 按 `materialId` 分组；
5. 每个 `materialId` 取 `id` 最大的一条记录；
6. 返回状态和建议 ID。

响应：

```json
{
  "totalCount": 2,
  "successCount": 1,
  "items": [
    {
      "materialId": "xxx",
      "status": "ACCEPTED_FOR_AI_BACKUP",
      "suggestionId": 1,
      "generationSeq": 1
    }
  ]
}
```

### 6.4 备用素材状态反馈 `POST /backup-material/feedbackAiBackupStatus`

入参：

| 字段 | 必填 | 说明 |
|---|---|---|
| `suggestionId` | 是 | 建议 ID |
| `suggestionStatus` | 是 | 状态 code |
| `userScore` | 否 | 用户评分 |
| `comment` | 否 | 备注 |

逻辑：

1. 校验 `suggestionStatus` 是合法 code；
2. 查询建议；
3. 更新 `status`；
4. `userScore` 不为空时更新 `user_score`，并设置 `feedback_type = RATE`；
5. `comment` 非空时更新 `feedback_reason`；
6. 更新 `updater` 和 `update_time`。

当前该接口只更新状态和反馈字段，不主动触发 body 替换。

### 6.5 规则分页 `POST /rule/page`

用于查询 `ai_material_suggestion_rule`。  
规则查询按 `materialType + suggestType + enabled` 过滤，并按 `priority` 倒序。

## 7. AI 规则快照

规则来源：

```text
ai_material_suggestion_rule
```

查询条件：

```text
material_type
suggest_type
enabled = 1
```

泳道条件：

- `sourceLane` 非空：
  ```text
  source_lane in (当前泳道, ALL)
  ```
- `sourceLane` 为空：
  - 不加泳道条件。

规则快照会序列化为 JSON，并根据语言做本地化处理。

## 8. 主用素材模版保存后的回填

在新建或更新主用素材模版时，保存 Mongo 素材后会收集：

```text
headerList
bodyList
footerList
```

注意：buttons 不参与当前 AI 建议回填。

`AiMaterialSuggestionBackfillService#backfill` 逻辑：

1. 检查 `ai_suggestion.backfill_enabled`；
2. 遍历素材；
3. 跳过 `clientMaterialKey` 为空的素材；
4. 跳过 `materialId` 为空的素材；
5. 按以下条件更新：
   ```text
   client_material_key = 请求 clientMaterialKey
   material_type = 请求 materialType
   ```
6. 更新：
   ```text
   material_id = Mongo 素材 ID
   material_group_id = 当前素材组 ID
   update_time = 当前时间
   ```

## 9. AI 备用素材模版创建与更新

入口：

```java
AiBackupMaterialGroupServiceImpl#createOrUpdateAiBackupGroup
```

### 9.1 触发条件

主素材模版保存后会调用：

```java
triggerAiBackupCreation(...)
```

前置开关：

```text
ai_backup.enabled = true
ai_backup.sync_create_enabled = true
```

如果两个开关都满足：

1. 判断备用素材组是否已存在；
2. 判断当前主素材组下是否存在 accepted 状态列表内的建议；
3. 如果备用素材组不存在且没有已接受建议，跳过；
4. 否则执行创建/更新。

因此：

| 场景 | 行为 |
|---|---|
| 无备用组 + 无已接受建议 | 不创建 |
| 无备用组 + 有已接受建议 | 创建 |
| 已有备用组 + 有/无已接受建议 | 更新或清理 |

### 9.2 查询已接受 body

按以下条件查询：

```text
material_group_id = 主素材组 ID
suggest_type = AI_BACKUP_MATERIAL_GROUP
material_type = BODY
status in [1, 3, 4, 5]
material_id 非空
```

收集：

```text
acceptedBodyMaterialIds
```

### 9.3 过滤主用组合

只查询主素材组下：

```text
status = ACTIVE
```

的主用组合。

然后过滤：

```java
acceptedBodyMaterialIds.contains(bodyMaterialId)
```

只有 body 被接受的主用组合才会同步到备用素材组。

如果一个被接受的 body 出现在多个主用组合中，这些组合都会同步。

### 9.4 无可同步组合时的处理

如果过滤后没有目标组合：

| 备用组状态 | 行为 |
|---|---|
| 不存在 | 直接返回，不创建 |
| 已存在 | 同步备用组泳道，并停用所有 AI 备用组合 |

这支持用户在编辑时取消全部已接受 body 的场景。

### 9.5 创建或更新备用素材组

备用素材组查找条件：

```text
primary_group_id = 主素材组 ID
ai_suggest_type = AI_BACKUP_MATERIAL_GROUP
source_type = 1
```

如果不存在则创建。

创建/更新时同步字段：

```text
name
template_type
language
status
combination_mode
primary_group_id
ai_suggest_type
source_type
updater / utime
```

创建时还会写 `ai_backup_material_update_log`。

### 9.6 同步备用泳道

备用素材组的 `message_material_group_lane` 会按主素材组泳道全量覆盖。

同步字段：

```text
source_lane
estimated_send_count
```

### 9.7 同步备用组合

目标主用组合逐个同步：

1. 查询备用素材组下 `source_type = 1` 的所有组合；
2. 按 `primary_combination_id` 找到最新备用组合；
3. 重复备用组合会被停用；
4. 对目标主用组合：
   - 已有备用组合：保留原 header/body/footer/buttons 引用，只更新元数据；如果 body 缺失则补拷；
   - 没有备用组合：复制主用素材；
5. 不在目标集合内的旧备用组合会被停用。

新组合复制逻辑：

| 主用素材 | 处理 |
|---|---|
| `headerMaterialId` | 非空则复制 Mongo 素材 |
| `footerMaterialId` | 非空则复制 Mongo 素材 |
| `buttonsMaterialId` | 非空则复制 Mongo 素材 |
| `bodyMaterialId` | 非空则复制 Mongo 素材，并设置 `element.source_type = 1` |

备用组合字段：

```text
material_group_id = 备用素材组 ID
material_group_name = 备用素材组名称
primary_combination_id = 主用组合 ID
source_type = 1
status = 跟随主用组合状态
material_status = NORMAL
```

## 10. body 替换逻辑

入口：

```java
AiBackupMaterialGroupServiceImpl#applyAiBackupBody
```

### 10.1 状态前置校验

只有以下状态允许进入替换流程：

```text
1 = ACCEPTED_FOR_AI_BACKUP
5 = APPLIED_TO_AI_BACKUP_FAILED
```

其他状态直接返回，不会替换，也不会修改建议状态。

### 10.2 回填前置条件

必须满足：

```text
materialGroupId 非空
materialId 非空
```

否则直接返回。

### 10.3 定位主用组合

按以下条件查询：

```text
material_group_id = suggestion.materialGroupId
body_material_id = suggestion.materialId
```

如果找不到主用组合，建议状态置为：

```java
APPLIED_TO_AI_BACKUP_FAILED = 5
```

### 10.4 替换动作

对每个主用组合：

1. 按 `primary_combination_id + source_type = 1` 查找备用组合；
2. 如果备用组合 body 存在，更新 Mongo：
   ```text
   element.text = AI suggestedContent
   utime = 当前时间
   ```
3. 如果备用组合下存在模板，则更新 `message_template.components` 中的 `BODY` 文本。

### 10.5 替换后状态

| 结果 | 状态 |
|---|---|
| 任意一个备用组合替换成功 | `APPLIED_TO_AI_BACKUP = 4` |
| 全部失败或没有备用组合 | `APPLIED_TO_AI_BACKUP_FAILED = 5` |

## 16. 风险与控制

### 16.1 LLM 延迟

`generate` 是同步接口，LLM 耗时可能导致前端或网关超时。  
批量生成接口通过预插入和异步执行降低该风险。

### 16.2 MySQL 与 Mongo 一致性

备用素材 body 存储在 Mongo，主流程中的 MySQL 事务无法覆盖 Mongo 操作。

控制方式：

1. 单条失败记录日志；
2. body 替换失败置为 `5`；
3. 补偿 Job 重试。

### 16.3 重复生成

`generate` 按 `clientMaterialKey + materialType + suggestType + sourceLane` 控制最大生成次数。  
`batchGenerate` 使用数据库唯一键和重复 key 校验控制。

### 16.4 稳定性数据源切换

`material.group.stability.redisSwitch = true` 后列表统计来源变为 Redis。  
上线前必须保证刷新 Job 已注册并执行，否则首次查询可能触发实时计算。

### 16.5 未接受建议保护

body 替换入口只允许 `status = 1` 或 `5`。  
`status = 2` 不会替换，也不会被误置为 `5`。

## 17. 测试关注点

### 17.1 AI 建议生成

- 单条生成成功；
- 单条生成超过最大次数；
- 无规则快照时不生成；
- 批量生成多条内容；
- 批量预插入状态正确；
- LLM 缺失结果时失败状态正确；
- `status = NOT_ACCEPTED_FOR_AI_BACKUP` 时失败后仍为 `2`。

### 17.2 已有建议更新

- `suggestionId` 存在但内容一致；
- content 一致且状态改为接受；
- content 一致且状态改为不接受；
- content 变化后复用原记录；
- 原记录 `sourceLane` 正确参与生成。

### 17.3 备用素材组

- 无已接受 body 且无备用组时不创建；
- 有一个已接受 body 时只同步包含该 body 的组合；
- 多个已接受 body 时同步对应组合；
- 编辑后取消全部接受状态时停用旧备用组合；
- 已有备用组合不重复复制；
- stale 备用组合被停用；
- 备用泳道同步正确。

### 17.4 body 替换

- `status = 1` 可替换；
- `status = 5` 可补偿替换；
- `status = 2` 不替换；
- Mongo body 替换成功；
- 模板 BODY 文本替换成功；
- 替换失败后状态为 `5`；
- 补偿 Job 可重试。

### 17.5 稳定性

- Redis 命中；
- Redis 未命中实时计算；
- 普通/AI 备用评分规则分链路；
- 低于最低等级不返回备用组。

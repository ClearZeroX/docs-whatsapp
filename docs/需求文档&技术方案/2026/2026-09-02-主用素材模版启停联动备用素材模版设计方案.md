# 主用素材模版启停联动备用素材模版设计方案

> 分支：`feature/zlc/0826-ai-backup-material`  
> 文档描述目标方案，不改既有历史设计说明。

---

## 1. 背景

AI 备用素材模版由主用素材模版联动生成。当前创建/编辑主用素材模版时已经会同步备用素材组和组合，但主用素材模版、素材元素、素材组合的启停状态没有完整联动到备用素材模版。

需要补充启用/停用能力，保证发送侧的备用素材可用状态与主用素材模版保持一致。

---

## 2. 数据关联关系

### 2.1 主用素材组与备用素材组

```text
message_material_group.primary_group_id = 主用素材组 ID
message_material_group.ai_suggest_type   = AI_BACKUP_MATERIAL_GROUP
message_material_group.source_type       = 1
```

### 2.2 主用组合与备用组合

```text
message_material_combination.primary_combination_id = 主用组合 ID
message_material_combination.source_type            = 1
```

### 2.3 主用元素与备用元素

AI 备用素材的 Mongo 文档 `message_material` 新增或已有字段：

```text
source_material_id
```

含义：

```text
source_material_id = 主用素材 Mongo ID
```

用于定位：

```text
主用素材 -> AI 备用素材
```

---

## 3. 相关状态

| 对象 | 字段 | 状态 |
|---|---|---|
| 素材组 | `message_material_group.status` | `NOT_ENABLED` / `ENABLED` / `DISABLED` |
| 组合 | `message_material_combination.status` | `ACTIVE` / `INACTIVE` |
| 组合内素材状态 | `message_material_combination.material_status` | `NORMAL` / `MATERIAL_PAUSED` |
| 素材元素 | Mongo `message_material.status` | `ACTIVE` / `PAUSED` / `DELETED` |

语义：

- `PAUSED`：停止生成；
- `DELETED`：删除/停用，终态；
- `INACTIVE`：组合停用；
- `MATERIAL_PAUSED`：组合内至少一个素材处于暂停或删除状态。

---

## 4. 本次涉及的接口

| 接口 | 说明 |
|---|---|
| `POST /admin/api/material/enable` | 素材模版启用 |
| `POST /admin/api/material/disable` | 素材模版停用 |
| `POST /admin/api/material/update` | 素材模版更新；元素启停和人工组合启停都会通过该接口触发 |
| `POST /admin/api/material/combination/activate` | 素材组合单独启用 |
| `POST /admin/api/material/combination/deactivate` | 素材组合单独停用 |

---

## 5. 联动总原则

联动的大前提是：只处理与“主用素材模版用户已接受的 AI 备用素材”相关联的备用对象。

当前主用已接受状态来自：

```text
ai_material_suggestion.suggest_type = AI_BACKUP_MATERIAL_GROUP
ai_material_suggestion.material_type = BODY
ai_material_suggestion.status in acceptedStatuses
```

其中：

```text
acceptedStatuses = AiMaterialSuggestionStatusEnum.getAcceptedStatuses()
```

只要备用素材体系中存在与该主用对象对应的记录，就跟随主用状态启停。

其中存在对应关系的范围包括：

```text
1. 主用已接受 AI 建议对应的备用 body；
2. 主用组合对应的备用组合；
3. 上述备用组合引用的备用 header/footer/buttons；
4. 备用素材组本身。
```

如果主用素材未被用户接受，或其他建议类型，不在联动范围内。

不处理备用素材组下已生成的 WhatsApp 模板，只联动以下对象状态：

```text
message_material_group.status
message_material_combination.status
message_material_combination.material_status
message_material.status
```

---

## 6. 素材模版启停联动

### 6.1 主用素材模版启用

接口：

```text
POST /admin/api/material/enable
```

主用素材组状态：

```text
message_material_group.status = ENABLED
```

查找备用素材组：

```text
WHERE primary_group_id = 主用素材组 ID
  AND ai_suggest_type = AI_BACKUP_MATERIAL_GROUP
  AND source_type = 1
```

如果备用素材组存在：

```text
message_material_group.status = ENABLED
```

规则：

- 备用素材组不存在时不主动创建；
- 不处理备用素材组下已有生成模板；
- 备用组合状态不在这一步强改，状态由组合启停或更新同步流程维护。

---

### 6.2 主用素材模版停用

接口：

```text
POST /admin/api/material/disable
```

主用素材组状态：

```text
message_material_group.status = DISABLED
```

如果备用素材组存在：

```text
message_material_group.status = DISABLED
```

同时停用备用素材组下的 AI 备用组合：

```text
WHERE material_group_id = 备用素材组 ID
  AND source_type = 1
=> status = INACTIVE
```

规则：

- 不删除已生成模板；
- 不删除现有备用素材元素；
- 发送侧必须不允许使用被停用备用组。

---

## 7. 素材元素启停联动

素材元素状态通过 `/admin/api/material/update` 修改，主要字段是：

```json
{
  "status": "ACTIVE" / "PAUSED" / "DELETED"
}
```

### 7.1 停止生成：`PAUSED`

主用元素：

```text
message_material.status = PAUSED
```

主用组合当前逻辑：

```text
combination.status 不变
combination.material_status = MATERIAL_PAUSED
```

备用联动：

```text
备用素材 message_material.status = PAUSED
备用组合 material_status = MATERIAL_PAUSED
备用组合 status 与主用组合最终 status 保持一致
```

即使备用 body 是 AI 生成内容，也只联动状态，不覆盖 AI 内容。

---

### 7.2 激活生成：`PAUSED` -> `ACTIVE`

主用元素：

```text
message_material.status = ACTIVE
```

备用元素：

```text
message_material.status = ACTIVE
```

主用组合当前逻辑：  
如果组合内所有素材都恢复为 `ACTIVE`，主用组合会恢复：

```text
combination.material_status = NORMAL
```

备用组合也恢复：

```text
combination.material_status = NORMAL
```

同样不覆盖备用 body 的 AI 内容。

---

### 7.3 删除 / 停用：`DELETED`

主用元素：

```text
message_material.status = DELETED
```

主用组合行为取决于请求中的 `confirmDisableCombination`：

| `confirmDisableCombination` | 主用组合 `status` | 主用组合 `material_status` |
|---|---|---|
| `true` | `INACTIVE` | `MATERIAL_PAUSED` |
| `false` | 保持原状态 | `MATERIAL_PAUSED` |

备用联动：

```text
备用素材 message_material.status = DELETED
```

备用组合状态必须与主用组合最终状态一致：

| 主用组合最终 `status` | 备用组合 `status` |
|---|---|
| `INACTIVE` | `INACTIVE` |
| 保持 `ACTIVE` | 保持 `ACTIVE` |

备用组合 `material_status` 一律：

```text
MATERIAL_PAUSED
```

---

## 8. 素材组合启停联动

组合状态包含两个字段：

```text
status        : ACTIVE / INACTIVE
material_status: NORMAL / MATERIAL_PAUSED
```

联动时两个字段都要同步，不能只同步 `status`。

---

### 8.1 素材组合单独启用

接口：

```text
POST /admin/api/material/combination/activate
```

主用组合：

```text
combination.status = ACTIVE
```

备用组合：

```text
WHERE primary_combination_id = 主用组合 ID
  AND source_type = 1
```

只启用当前最新且有效的一条备用组合：

```text
status = ACTIVE
material_status = 同主用组合当前 materialStatus
```

如果备用组合不存在，不主动创建。

---

### 8.2 素材组合单独停用

接口：

```text
POST /admin/api/material/combination/deactivate
```

主用组合：

```text
combination.status = INACTIVE
```

备用组合：

```text
WHERE primary_combination_id = 主用组合 ID
  AND source_type = 1
=> 所有备用组合 status = INACTIVE
```

---

## 9. 编辑素材模版时的人工组合启停联动

主用素材模版使用：

```text
combinationMode = MANUAL
```

并通过：

```text
POST /admin/api/material/update
```

提交时，请求中可包含：

```json
"manualCombinations": [
  {
    "headerMaterialRef": null,
    "bodyMaterialRef": "xxx",
    "footerMaterialRef": null,
    "buttonsMaterialRef": null,
    "id": 1413,
    "status": "INACTIVE"
  }
]
```

### 9.1 目标状态

`manualCombinations[].status` 表示主用组合的目标状态：

```text
ACTIVE
INACTIVE
```

主用更新逻辑会据此更新主用组合状态。

备用组合必须基于主用组合落库后的最终状态联动，不能只看请求入参。

---

### 9.2 联动规则

| 主用组合最终状态 | 备用组合处理 |
|---|---|
| `ACTIVE` | 只启用对应主用组合的最新有效备用组合 |
| `INACTIVE` | 该主用组合下所有 `source_type=1` 的备用组合停用 |
| 备用组合不存在 | 不创建 |

---

### 9.3 为什么不能直接按请求字段零散处理

一次 `/material/update` 可能同时包含：

- 元素状态变化；
- 人工组合状态变化；
- `confirmDisableCombination`；
- 新增/删除素材；
- 组合结构变化。

因此备用组合联动应该基于主用组合状态落库后的最终状态执行。

---

## 10. 组合状态同步

主用组合和备用组合状态字段对应：

| 主用组合 | 备用组合 |
|---|---|
| `status = ACTIVE` | `status = ACTIVE` |
| `status = INACTIVE` | `status = INACTIVE` |
| `material_status = NORMAL` | `material_status = NORMAL` |
| `material_status = MATERIAL_PAUSED` | `material_status = MATERIAL_PAUSED` |

---

## 11. 发送侧过滤

发送侧查询备用素材组时，需要与主用逻辑保持一致。

当前 `getAiBackupMaterialGroup` 查询组合时未强制过滤组合状态，需要改为过滤：

```text
message_material_group.status = ENABLED
message_material_combination.status = ACTIVE
message_material_combination.material_status = NORMAL
组合引用的非空素材 status = ACTIVE
```

备用元素状态不允许：

```text
PAUSED
DELETED
```

即：备用素材组满足最低稳定性等级，并且备用组合必须完全可用。

---

## 12. 备用组合历史数据处理

一个主用组合理论上可能存在多条历史备用组合，原因是：

1. 历史同步逻辑曾重复复制；
2. 部分事务失败后补偿可能再复制；
3. 旧记录会被后置同步逻辑停用，但记录仍存在。

因此联动规则：

- 停用主用组合时，联动停用该主用组合下所有 `source_type=1` 的备用组合；
- 启用主用组合时，只启用最新且有效的一条备用组合；
- 不把历史已停用备用组合重新启用。

也可以选择在启用场景下先执行一次备用组合重建/同步，再按同步结果启用目标备用组合，避免直接更新历史记录。

---

## 13. 素材映射说明

### 13.1 新备用素材

复制备用素材时写入：

```text
source_material_id = 主用素材 Mongo ID
```

### 13.2 历史备用素材

历史数据可能缺少 `source_material_id`。

可以在联动时通过备份组合反查主用组合补齐：

```text
备用组合.primary_combination_id -> 主用组合
主用组合.header/body/footer/buttons -> 备用组合对应元素
```

这样后续可以准确定位主用元素与备用元素的映射。

---

## 14. 边界规则

1. 备用素材组不存在时不主动创建；
2. 主用素材组启用时不创建备用素材组；
3. 主用素材组停用时不删除备用素材组；
4. 不处理备用素材组已生成的 WhatsApp 模板；
5. 主用元素删除时，备用元素使用终态 `DELETED`；
6. 已有历史备用组合可能存在多条，启用时只启用最新有效一条；
7. 状态同步失败时记录日志，不影响主用状态变更成功；
8. 发送侧过滤逻辑与主用逻辑保持一致。

---

## 15. 验证场景

### 15.1 素材组启停

| 场景 | 预期 |
|---|---|
| 主用组启用 | 备用组 `ENABLED` |
| 主用组停用 | 备用组 `DISABLED`，备用组合 `INACTIVE` |
| 备用组不存在时启用 | 不创建备用组 |

### 15.2 元素启停

| 场景 | 预期 |
|---|---|
| 主用 header/footer/body/buttons `PAUSED` | 备用元素 `PAUSED`，对应备用组合 `MATERIAL_PAUSED` |
| 主用元素恢复 `ACTIVE` | 备用元素 `ACTIVE`，组合满足条件后恢复 `NORMAL` |
| 主用元素 `DELETED` | 备用元素 `DELETED`，组合状态和主用一致 |

### 15.3 组合启停

| 场景 | 预期 |
|---|---|
| 主用组合单独停用 | 对应备用组合停用 |
| 主用组合单独启用 | 最新有效备用组合启用 |
| `/material/update` 中人工组合状态为 `INACTIVE` | 备用组合停用 |
| `/material/update` 中人工组合状态为 `ACTIVE` | 最新有效备用组合启用 |

### 15.4 发送侧

| 场景 | 预期 |
|---|---|
| 备用组 `DISABLED` | 不返回 |
| 备用组合 `INACTIVE` | 不返回 |
| 备用组合 `MATERIAL_PAUSED` | 不返回 |
| 备用素材 `PAUSED` / `DELETED` | 所在组合不返回 |

# 品类、标签、素材组合效果分析技术方案

> 日期：2026-11-11  
> 文档状态：技术设计稿

## 一、方案概述与实现目标

本方案建设一套“素材效果分析”页面和配套数据能力，为品类、标签、素材组合模板提供统一的查询、筛选和下钻能力。页面首先展示数据事实，用户通过指标、日期、归因窗口和业务维度选择分析范围，再查看品类、标签或素材组合模板的结果。

方案目标：

1. 保留发送、触达、互动、反馈和业务转化等完整指标；
2. 同时支持品类、标签、素材组合模板三个分析入口；
3. 保留日期、任务、泳道、业务场景、渠道和业务号码等可用维度；
4. 让每个页面结果可以回查到来源明细；
5. 支持 T1、T3、T7 数据分别存储、查询和回补；
6. 支持增量处理、幂等重跑和迟到数据更新；
7. 对标签多对多关联进行去重，避免统计结果被放大；
8. 页面、接口和数据表一次形成完整闭环。

设计原则：

- 业务统计和渠道统计分别保留来源，不直接混合分子和分母；
- 来源表保留原生粒度，汇总表服务于查询加速；
- 品类和标签作为独立维度关联到素材组合模板；
- 场景、任务和泳道作为事实维度保存，指标展示由用户选择；
- 数据不存在、数据为 0、数据尚未完成分别表达；
- `material_combination_send_statistic` 不作为本方案的数据来源；
- MySQL 批量 `IN` 查询每批最多 500 个值，分页优先使用主键或更新时间游标。

## 二、业务模型与数据来源

### 2.1 品类与标签模型

| 表或对象 | 主要字段 | 本方案用途 |
|---|---|---|
| `material_category` | `id`、`code`、`name`、`source_type`、`status` | 品类字典和名称展示 |
| `material_tag` | `id`、`code`、`name`、`source_type`、`status` | 全局标签字典 |
| `material_category_tag_relation` | `material_id`、`material_category_code`、`material_tag_code`、`source_type`、`binding_status` | 素材标签绑定、来源和正式/候选状态 |
| `material_tag_rule` | `material_category_code`、`prompt_desc`、`scope`、`status` | AI 标签提取规则配置 |
| Mongo `message_material` | `_id`、`material_category_code`、组件内容 | 素材实际品类和素材内容 |
| `message_material_combination` | 组件素材 ID、`material_category_code`、`material_group_id` | 素材组合模板和品类快照 |
| `message_template` | `name`、`material_combination_id`、`material_group_id` | 渠道模板到素材组合模板的映射 |
| `task_base` | `id`、`tags` | 任务业务场景辅助维度 |

`material_tag` 是全局标签定义。具体素材上的标签来源和状态，以 `material_category_tag_relation` 为准：

- `source_type=0`：AI 生成；
- `source_type=1`：后台配置来源，保留真实来源信息；
- `source_type=2`：用户选择；
- `binding_status=1`：正式绑定；
- `binding_status=0`：AI 候选绑定。

`material_tag.source_type` 表示标签定义的来源，不能代替素材绑定来源。页面显示“AI 标签”“用户选择标签”时，使用关系表来源；后台配置来源保留在技术数据中，暂不作为本期页面的核心标签分类。

当前素材保存 `material_category_code`，AI 关系记录会保存 AI 判断的品类上下文，并通过 `binding_status` 表示是否与当前素材品类一致。当前代码没有单独的素材品类赋值来源字段，因此可以稳定区分“当前生效品类”和“AI 候选品类”，不能从现有品类字典 `source_type` 推断当前品类是由用户选择还是 AI 写入。若需要这个筛选能力，后续增加素材品类赋值来源快照。

### 2.2 统计来源表

#### `message_template_statistic`

字段：

- 维度：`id`、`business_phone`、`agent`、`agent_name`、`agent_template_id`、`message_template_id`、`material_combination_id`、`material_group_id`、`dt`；
- 指标：`sent_count`、`delivered_count`、`read_count`、`url_clicked_count`、`unique_url_clicked_count`。

用途：提供渠道、业务号码和渠道模板维度的发送、送达、已读和 URL 点击统计。`material_combination_id` 非空时可以直接关联素材组合模板。没有组合 ID 的渠道模板不参与组合效果统计。

#### `qe_task_lane_template_message_statistic`

字段：

- 维度：`id`、`send_dt`、`task_id`、`lane_type`、`window_type`、`template_name`；
- 指标：

```text
request_count
sent_count
delivered_count
read_count
click_count
flow_submit_count
reply_count
unsubscribe_count
complaint_count
register_count
apply_credit_count
loan_count
```

用途：提供任务、泳道、模板和归因窗口维度的完整业务统计。通过 `template_name` 关联 `message_template.name`，再通过 `message_template.material_combination_id` 关联素材组合模板。

#### `qe_task_lane_material_message_statistic`

字段：`send_dt`、`task_id`、`lane_type`、`window_type`、`material_type`、`material_id` 及上述 12 项指标。

用途：用于素材级明细核对和后续素材下钻。素材级数据不能直接加总为组合级数据，因为同一消息可能包含多个素材组件。

#### `qe_task_message_statistic`

用途：提供任务级整体统计，用于任务维度核对。任务级数据不能替代模板级或组合级数据。

## 三、数据关联、统计表与处理流程

### 3.1 关联关系

渠道统计关联链路：

```text
message_template_statistic
        │ material_combination_id
        ▼
message_material_combination
        │ material_category_code
        ▼
material_category
```

QE 模板统计关联链路：

```text
qe_task_lane_template_message_statistic
        │ template_name
        ▼
message_template.name
        │ material_combination_id
        ▼
message_material_combination
```

标签关联链路：

```text
message_material_combination
        │ header/body/footer/buttons/carousel 等成员 material_id
        ▼
message_material
        │ material_id
        ▼
material_category_tag_relation
        │ material_tag_code
        ▼
material_tag
```

关联规则：

1. 组合品类使用 `message_material_combination.material_category_code`；
2. 组合没有品类时使用 `UNCATEGORIZED`；
3. QE 的 `template_name` 反查不到 `message_template` 或组合 ID 时，业务统计行丢弃，并记录失败数量和样本；
4. 不创建 `material_combination_id=0` 的虚拟统计桶；
5. 标签通过组合成员素材关联，不从标签字典反推标签所属品类；
6. 一个组合中的多个成员素材命中同一个标签时，构造去重后的“组合—标签”关系；
7. 同一标签下的组合集合可以和其他标签集合重叠，标签结果不能相加推导总量；
8. 任务场景从 `task_base.tags` 的 `SCENARIO` 对象读取，QE `lane_type` 作为统计事实字段单独保留；
9. 素材包表示内容组织关系，不直接作为唯一品类来源。

### 3.3 数据处理流程

```text
message_template_statistic ──同步──> 渠道明细表 ──聚合──> 汇总表
                                      │
                                      └─ material_combination_id → 组合/品类

qe_task_lane_template_message_statistic ──反查模板──> QE 明细表 ──聚合──> 汇总表
                                                      │
                                                      └─ task/lane/window

组合成员素材 ──查询──> 新标签绑定表 ──去重──> 组合-标签集合 ──筛选──> 页面结果
```

处理步骤：

1. 读取渠道统计源表，过滤组合 ID 为空的记录，按源记录 ID 幂等写入渠道明细表；
2. 读取 QE 模板统计源表，按 `template_name` 批量查询 `message_template`；
3. 通过 `message_template.material_combination_id` 获取组合和素材包；
4. 反查不到组合的 QE 记录丢弃，记录失败数量、模板名称和日期；
5. 将 QE 的 12 项指标完整写入业务明细表；
6. 根据受影响的日期、组合、任务、泳道和窗口刷新汇总表；
7. 查询组合成员素材的标签绑定，按来源和绑定状态生成去重集合；
8. 页面按品类、标签、组合和其他筛选条件查询，结果保留来源和数据状态。

## 四、维度、指标与页面查询处理

### 4.1 品类维度

- 当前生效品类使用 `message_material_combination.material_category_code`；
- 组合快照为空时使用 `UNCATEGORIZED`；
- AI 候选品类从素材标签关系中的 AI 品类上下文和候选状态读取，作为独立观察范围；
- 不使用 `material_category.source_type` 推断当前素材品类的赋值来源；
- 组合成员出现多个真实品类时，沿用组合生成校验结果，异常组合不进入正常品类聚合；
- 品类名称使用 code 关联当前字典展示，统计事实保存 code，避免名称修改影响历史聚合。

### 4.2 标签维度

标签查询步骤：

1. 根据组合 ID 批量获取成员素材 ID；
2. 每批最多 500 个素材 ID 查询 `material_category_tag_relation`；
3. 按 `source_type` 和 `binding_status` 筛选；
4. 对同一组合、同一标签、同一来源和同一状态去重；
5. 得到组合集合后再聚合指标。

默认筛选 `binding_status=1`。候选标签通过明确的 `binding_status=0` 条件单独查看。一个组合的多个素材组件命中同一标签只算一次；同一组合可以同时属于多个不同标签集合。

### 4.3 场景、泳道和任务

- `task_id`、`lane_type`、`window_type` 作为 QE 事实维度原样保存；
- 任务业务场景从 `task_base.tags` 中 `category=SCENARIO` 的值读取；
- 页面可按业务场景筛选，但不通过场景删除已有指标；
- 任务没有可解析场景时保留空值并展示“未标记”；
- `lane_type` 出现未纳入枚举的值时保留原始值，不静默归类；
- 素材包配置的泳道只表示配置关系，不把一条统计事实复制到所有配置泳道。

### 4.4 指标和比率

业务统计来源使用 QE 自身的计数计算：

- 送达率 = `delivered_count / sent_count`；
- 已读率 = `read_count / delivered_count`；
- 点击率 = `click_count / delivered_count`；
- 注册率 = `register_count / delivered_count`；
- 申请授信率 = `apply_credit_count / delivered_count`；
- 放款事件/送达 = `loan_count / delivered_count`。

渠道统计来源使用渠道自身的字段：

- 送达率 = `delivered_count / sent_count`；
- 已读率 = `read_count / delivered_count`；
- URL 点击率 = `url_clicked_count / delivered_count`；
- 唯一 URL 点击率 = `unique_url_clicked_count / delivered_count`。

`click_count` 与 `unique_url_clicked_count` 不是同一个指标，接口返回时必须保留字段名称和来源。T1、T3、T7 作为独立窗口查询；窗口数据未完整回补时返回 `observing` 状态。

## 六、增量任务、数据质量与性能

### 6.1 增量任务

建议拆分四个任务：

1. **渠道明细同步任务**：按 `message_template_statistic.id` 和 `update_time` 读取新增、更新记录，写入渠道明细表；
2. **QE 明细同步任务**：按 QE 源表主键和可变日期窗口读取新增、更新记录，批量反查模板和组合，写入业务明细表；
3. **汇总刷新任务**：只刷新受影响的日期、组合、任务、泳道和窗口；
4. **标签维度刷新任务**：对受影响组合重新读取成员素材标签，更新可查询的组合—标签关联缓存或索引。

增量处理要求：

- 源行使用覆盖更新，重跑不会重复累加；
- T3/T7 允许回补旧 `send_dt`，不能只读取昨天的数据；
- 处理日期范围需要包含正在变化的观察窗口，具体水位按源表更新时间和窗口完成状态配置；
- 同一窗口的迟到数据刷新对应汇总分区；
- 映射失败记录写入告警和统计日志，业务表按规则丢弃；
- 所有 MySQL 批量 `IN` 每批最多 500 个；
- 大范围读取使用日期、更新时间和主键游标，避免大 OFFSET。

### 6.2 数据质量检查

每日检查以下结果：

- 每个来源的最新统计日期和数据截止时间；
- 渠道明细源行数量与新表数量；
- QE 模板反查成功率和失败模板数量；
- 无组合 ID 的渠道数据数量；
- 组合品类为空或 `UNCATEGORIZED` 的数量；
- 正式标签、候选标签、AI 标签和用户选择标签数量；
- 明细表按日期和组合聚合后与汇总表对账；
- T1/T3/T7 回补是否更新了对应窗口；
- 重跑前后汇总数量和金额不重复增长；
- 同一组合同一标签多组件命中时是否只计一次；
- 0 值与 NULL/缺失状态是否按约定展示。

### 6.3 性能与异常

- 组合 ID、素材 ID、标签 code 和模板名称批量查询每批不超过 500 个；
- 页面列表接口使用分页；
- 标签筛选先生成去重组合集合，再查询统计数据；
- 日期、组合 ID、任务 ID、泳道和窗口字段建立组合索引；
- 详情页按需查询来源明细，不在汇总接口一次返回所有源行；
- 反查失败、组合缺失、品类缺失、标签缺失和窗口未完成分别返回状态；
- 未接入的指标不以 0 填充；
- 大范围导出使用异步任务或游标读取，避免单次加载全部数据。

# AI 备用素材模版 — 前端功能改动说明

> 分支：`feature/zlc/0826-ai-backup-material-ui`  
> 日期：2026-08-31

---

## 一、新增功能：AI 备用素材模版勾选与提交

### 1.1 功能入口

在素材模版编辑/新建页面，每个 Body 的内容区域上方新增了**勾选区域**，包含三个操作项：

| 操作项 | 说明 |
|--------|------|
| `接受该素材模版下所有body生成AI备用素材模版` | 勾选后，所有 body 都视为接受 |
| `接受该body生成AI备用素材模版` | 只接受当前这个 body |
| `更多` | 展开后显示 AI 生成的备用素材建议内容，以及"拒绝该body"选项 |

勾选区域与原来的"成本优先 AI 建议"按钮在同一行，用竖线 `|` 分隔，左侧是勾选区，右侧是操作按钮。

### 1.2 各阶段的交互逻辑

#### 新建阶段

- 三个勾选项（接受所有 / 接受该body / 更多）均可自由切换，**不调用后端接口**
- 点击"更多"展开 → 调用 AI 生成接口为该 body 生成一次备用素材建议，展示评分、理由、反馈输入框
- "更多"展开后，下方出现"拒绝该body生成AI备用素材模版"复选框，**默认勾选**（即默认拒绝）

#### 编辑阶段

- 进入页面时，自动调用 `listAiBackupMaterials` 接口回显历史勾选状态：
  - 如果所有 body 的生成状态都已成功（`totalCount == successCount`）→ 自动勾选"接受所有body"
  - 否则逐个检查：状态不是"未接受"的 body 自动勾选"接受该body"
- 历史 body 的"更多"按钮**禁用**，只能选择"接受所有"或"接受该body"
- 编辑阶段新增的 body，"更多"按钮可用，逻辑同新建阶段
- **勾选变更时**，自动调用 `feedbackAiBackupStatus` 接口更新状态

#### 查看阶段

- 与编辑阶段相同的回显逻辑，但所有勾选项**只读不可操作**

### 1.3 勾选联动规则

| 操作 | 效果 |
|------|------|
| 勾选"接受所有body" | 所有 body 变为"接受所有"，清除单body勾选和拒绝勾选 |
| 取消"接受所有body" | 所有 body 状态清空 |
| 勾选"接受该body" | 如果之前有 body 是"接受所有"，那些 body 转为"接受该body"，当前 body 也设为"接受该body" |
| 勾选"拒绝该body" | 需要先展开"更多"区域，勾选后清除该 body 的接受勾选 |
| 勾选"接受"后 | 自动取消该 body 的"拒绝"勾选，并调用反馈接口更新状态 |

### 1.4 提交时的校验与调用

点击提交按钮时，按以下顺序执行：

1. **校验**：检查所有 body 是否至少有一个勾选（接受所有 / 接受该body / 拒绝该body），如果全都没有勾选，弹出提示"请至少勾选'接受所有body'、'接受该body'或'更多'中的一个选项"
2. **调用 batchGenerate 接口**：对所有 body（包括已接受和未接受的）统一调用，传入每个 body 的：
   - `clientMaterialKey`：唯一标识，新建 body 自动生成
   - `content`：body 内容
   - `suggestionId`：AI 建议 ID（历史 body 来自 listAiBackupMaterials 返回，新增 body 来自"更多"生成返回）
   - `status`：接受传 `ACCEPTED_FOR_AI_BACKUP`，未接受传 `NOT_ACCEPTED_FOR_AI_BACKUP`
3. batchGenerate 成功后，再调用创建/更新素材模版接口

## 三、新增/变更的接口

### 3.1 batchGenerate（新增）

- **路径**：`POST /admin/api/ai-suggestion/batchGenerate`
- **用途**：提交素材模版时，批量生成 AI 备用素材建议
- **调用时机**：点击提交按钮，校验通过后，创建/更新素材模版之前
- **超时**：60 秒
- **入参**：

```json
{
  "materialGroupId": 100,
  "suggestType": "AI_BACKUP_MATERIAL_GROUP",
  "materialType": "BODY",
  "language": "en_US",
  "sourceLanes": [],
  "materialContents": [
    {
      "suggestionId": "xxx",
      "clientMaterialKey": "body-key-1",
      "content": "body content",
      "lastSuggestedContent": "",
      "userFeedback": "",
      "status": "ACCEPTED_FOR_AI_BACKUP"
    }
  ]
}
```

### 3.2 listAiBackupMaterials（新增）

- **路径**：`POST /admin/api/ai-suggestion/backup-material/listAiBackupMaterials`
- **用途**：查询已有 body 的备用素材生成状态
- **调用时机**：编辑/查看页面加载时
- **入参**：

```json
{
  "materialGroupId": 100,
  "materialIdList": ["materialId1", "materialId2"]
}
```

- **出参关键字段**：

```json
{
  "totalCount": 2,
  "successCount": 1,
  "items": [
    {
      "materialId": "xxx",
      "status": "ACCEPTED_FOR_AI_BACKUP",
      "suggestionId": 12345,
      "generationSeq": 1,
      "message": ""
    }
  ]
}
```

### 3.3 feedbackAiBackupStatus（新增）

- **路径**：`POST /admin/api/ai-suggestion/backup-material/feedbackAiBackupStatus`
- **用途**：更新备用素材建议的接受/拒绝状态
- **调用时机**：编辑阶段，勾选状态变更时
- **入参**：

```json
{
  "suggestionId": 12345,
  "suggestionStatus": 1
}
```

- `suggestionStatus`：`1` = 接受，`2` = 未接受

## 四、generate 接口超时说明

generate 接口（AI 生成建议）前端超时设置为 **30 秒**。如果后端正常响应但前端 10 秒左右报错，可能是链路层（Nginx / API 网关 / 负载均衡）的超时设置导致。本项目的 Nginx 配置 `proxy_read_timeout` 为 30 秒，需排查上层网络组件。

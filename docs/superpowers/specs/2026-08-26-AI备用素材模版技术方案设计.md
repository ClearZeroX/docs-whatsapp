# AI 备用素材模版技术方案设计

## 1. 文档说明

本文基于《2026-08-25-ai-backup-material-group-design.md》以及本轮评审沟通结论，整理为一份完整、可直接评审的技术方案。

当前 AI 备用素材模版方案和相关代码尚未上线，因此本方案不考虑兼容以下未上线设计或实现：

- `message_material_group.ai_source_lane`；
- 按泳道创建多个 AI 备用素材模版；
- 通过 RocketMQ 异步创建 AI 备用素材模版；
- `/api/admin/material/listAll` 按 `source_type != 1` 过滤；
- `feedback` 接口更新 `ai_material_suggestion.status`。

本方案以 `SuggestTypeEnum.AI_BACKUP_MATERIAL_GROUP` 作为 AI 备用素材模版的唯一业务类型标识。

术语约定：本文业务用词统一使用“素材模版”和“素材组合”。代码中的 `material_group` / `MessageMaterialGroup` 对应业务上的“素材模版”；代码中的 `combination` / `MessageMaterialCombination` 对应业务上的“素材组合”。因此，除代码标识符外，文档统一称“AI 备用素材模版”和“AI 备用素材组合”。

---

## 2. 背景与目标

### 2.1 背景

群发任务创建时，运营可以配置备用素材模版。当主用素材模版发送失败，且失败回调码满足切换条件时，发送链路可以切换到备用素材模版。

原有备用素材模版依赖运营手动创建，工作量大且容易遗漏。AI 备用素材模版能力希望基于运营输入的主素材 body，批量生成可作为备用的 body 内容，并在主素材模版创建或更新后自动生成一个 AI 备用素材模版。

### 2.2 调整后的核心目标

1. AI 备用素材模版不再按泳道维度生成。
2. AI 备用素材模版统一通过 `ai_suggest_type = AI_BACKUP_MATERIAL_GROUP` 标识。
3. AI 备用素材内容支持批量异步生成，且 LLM 支持多条一起生成。
4. 前端提交主素材模版前，通过新状态接口查询 AI 备用素材生成状态。
5. 主素材模版创建或更新后，后端同步尝试创建或更新 AI 备用素材模版。
6. 同步创建有独立开关；开关关闭或创建异常时，只记录日志，不影响主素材模版 ID 返回。
7. 编辑主用素材组合方式、或新增 body 并已有 AI 成功建议时，同步更新 AI 备用素材模版。
8. 提供补偿 Job，可按 `materialGroupId` 手动补偿生成 AI 备用素材模版。

### 2.3 非目标

1. 不在本期引入批次任务表。
2. 不在本期为 `batchGenerate` 提供批次进度表或批次详情页。
3. 不使用 Redis 标记 AI 生成中的状态。
4. 不使用 MQ 创建 AI 备用素材模版。
5. 不再维护按泳道生成 AI 备用素材模版的逻辑。

---

## 3. 总体链路

```text
前端调用 batchGenerate
  -> 后端异步批量调用 AI
  -> AI 成功/失败后写入 ai_material_suggestion

前端点击提交主素材模版
  -> 调用 AI 备用素材状态接口
  -> 若 processingCount > 0，前端最多轮询 30 秒
  -> successCount > 0：直接提交
  -> successCount = 0：提示 AI 备用素材暂不可用后仍提交

后端创建/更新主素材模版
  -> 保存主素材模版、素材、素材组合、lane config
  -> 根据 clientMaterialKey 回填 AI 建议的 material_group_id / material_id
  -> 同线程同步尝试创建/更新 AI 备用素材模版
  -> 开关关闭或异常时只记日志，不抛出
  -> 返回 materialGroupId

补偿场景
  -> Job 按 materialGroupId 手动触发 AI 备用素材模版生成
```

## 4. 数据模型设计

### 4.1 `SuggestTypeEnum`

新增枚举值：

```java
AI_BACKUP_MATERIAL_GROUP("AI_BACKUP_MATERIAL_GROUP", "AI backup material group")
```

使用范围：

- AI 备用素材内容生成；
- AI 备用素材生成状态查询；
- AI 备用素材模版创建/更新；
- `/api/admin/material/listAll` 过滤；
- 发送链路查询 AI 备用素材模版。

### 4.2 `message_material_group`

去掉字段：

```sql
`ai_source_lane`
```

新增或保留字段：

```sql
ALTER TABLE `message_material_group`
  ADD COLUMN `primary_group_id` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Associated primary material group ID, 0 for non-AI-backup',
  ADD COLUMN `source_type` tinyint(4) NOT NULL DEFAULT '0' COMMENT 'Source type: 0=manual, 1=AI auto-generated',
  ADD COLUMN `ai_suggest_type` varchar(50) NOT NULL DEFAULT '' COMMENT 'AI suggest type from SuggestTypeEnum',
  ADD INDEX `idx_primary_ai_suggest_type` (`primary_group_id`, `ai_suggest_type`);
```

字段说明：

| 字段 | 默认值 | 说明 |
|---|---:|---|
| `primary_group_id` | `0` | AI 备用素材模版关联的主素材模版 ID，非 AI 备用素材模版为 `0` |
| `source_type` | `0` | `0` 人工创建，`1` AI 自动生成 |
| `ai_suggest_type` | `''` | AI 建议类型；AI 备用素材模版固定为 `AI_BACKUP_MATERIAL_GROUP` |

AI 备用素材模版示例：

```text
主素材模版：
  id = 100
  primary_group_id = 0
  source_type = 0
  ai_suggest_type = ''

AI 备用素材模版：
  id = 200
  primary_group_id = 100
  source_type = 1
  ai_suggest_type = 'AI_BACKUP_MATERIAL_GROUP'
```

同一个主素材模版下，`AI_BACKUP_MATERIAL_GROUP` 类型默认只对应一个 AI 备用素材模版。

#### 4.2.1 名称长度调整

AI 备用素材模版名称规则为：

```text
原 name + "_ai_backup_by_" + suggestType
```

示例：

```text
loan_marketing_template_ai_backup_by_AI_BACKUP_MATERIAL_GROUP
```

该名称不是固定后缀常量拼接，而是通过统一工具方法生成，例如：

```java
buildAiBackupMaterialGroupName(primaryName, suggestType)
```

实现要求：

1. 业务代码不直接硬编码拼接 `"_ai_backup_by_"`，统一通过常量和工具方法生成。
2. `"_ai_backup_by_"` 可定义为常量，例如 `AI_BACKUP_MATERIAL_GROUP_NAME_SEPARATOR`。
3. 因为原 `name` 当前最大长度可能已达到 `varchar(100)` 上限，追加 `_ai_backup_by_{suggestType}` 后会超长。
4. 表结构需要将 `message_material_group.name` 扩展到至少 `varchar(200)`，建议 `varchar(255)`。
5. 生成 AI 备用素材模版名称时仍需做长度保护：如果 `原 name + separator + suggestType` 超过 DB 长度，则截断原 name，保留完整 separator 和 suggestType。
6. 名称唯一性仍按现有素材模版名称校验逻辑处理；如果截断后冲突，可复用现有随机后缀逻辑或追加短随机串。

建议 DDL：

```sql
ALTER TABLE `message_material_group`
  MODIFY COLUMN `name` varchar(255) NOT NULL DEFAULT '' COMMENT 'Template name';
```

> 说明：当前项目 SQL 中 `message_material_group.name` 为 `varchar(100)`，需要扩展，否则原名称接近 100 字符时会因追加 AI 备用标识而超长。

> 说明：当前项目表字段是 `ctime` / `utime`，索引沿用现有字段命名；如果落库脚本使用 `create_time` / `update_time`，需遵循项目规范给 `create_time` 加索引。

### 4.3 `message_material_combination`

新增或保留字段：

```sql
ALTER TABLE `message_material_combination`
  ADD COLUMN `primary_combination_id` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Associated primary combination ID, 0 for non-AI-backup',
  ADD COLUMN `source_type` tinyint(4) NOT NULL DEFAULT '0' COMMENT 'Source type: 0=manual, 1=AI auto-generated',
  ADD INDEX `idx_primary_combination_id` (`primary_combination_id`);
```

字段说明：

| 字段 | 默认值 | 说明 |
|---|---:|---|
| `primary_combination_id` | `0` | AI 备用素材组合对应的主用组合 ID |
| `source_type` | `0` | `0` 人工组合，`1` AI 自动生成组合 |

### 4.4 `ai_material_suggestion.status`

`status` 调整为 AI 备用素材模版生成状态：

| status | 语义 |
|---:|---|
| `1` | 接受为生成 AI 素材模版 |
| `2` | 未接受为生成 AI 素材模版 |
| `3` | AI 生成失败 |

当 `suggest_type = AI_BACKUP_MATERIAL_GROUP`：

- AI 生成成功后插入：`status = 1`；
- AI 生成失败后插入：`status = 3`；
- 失败内容固定写英文：`Generation failed`。

`feedback_type` 不作为 AI 备用素材模版创建的强依赖条件。

### 4.5 `feedback` 不再更新 `status`

`feedback` 接口不再更新 `ai_material_suggestion.status`。

原因：

1. `status` 已调整为 AI 备用素材模版生成状态，不再承载普通建议的采纳、拒绝、评分反馈状态。
2. 普通建议反馈如果继续写 `status`，会污染 AI 备用素材模版创建时对 `status = 1/3` 的判断。
3. 反馈状态应由 `feedback_type`、`feedback_reason`、`user_score` 等字段表达。

调整后：

- `feedback` 可更新：
  - `feedback_type`
  - `feedback_reason`
  - `user_score`
  - `update_time`
- `feedback` 不再执行：
  - `record.setStatus(feedbackType.getCode())`
  - 评分时设置 `status = RATE`

### 4.6 `ai_backup_material_update_log`

保留操作日志表，但去掉泳道字段，改为记录 `ai_suggest_type`。

```sql
CREATE TABLE `ai_backup_material_update_log` (
  `id` bigint(20) unsigned AUTO_INCREMENT COMMENT 'Primary key',
  `primary_group_id` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Primary material group ID',
  `backup_group_id` bigint(20) NOT NULL DEFAULT '0' COMMENT 'AI backup material group ID',
  `ai_suggest_type` varchar(50) NOT NULL DEFAULT '' COMMENT 'AI suggest type from SuggestTypeEnum',
  `operate_type` varchar(50) NOT NULL DEFAULT '' COMMENT 'Operation type: CREATE/UPDATE/ENABLE/DISABLE/DELETE',
  `trigger_source` varchar(50) NOT NULL DEFAULT '' COMMENT 'Trigger source: SYNC/JOB/MANUAL',
  `before_content` text COMMENT 'Content before change, JSON format',
  `after_content` text COMMENT 'Content after change, JSON format',
  `status` tinyint(4) NOT NULL DEFAULT '0' COMMENT 'Reserved for future use',
  `remark` varchar(1024) DEFAULT '' COMMENT 'Reserved for future use',
  `operator` varchar(128) DEFAULT '' COMMENT 'Operator',
  `create_time` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Creation time',
  `update_time` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Update time',
  PRIMARY KEY (`id`),
  KEY `idx_create_time` (`create_time`),
  KEY `idx_primary_group_id` (`primary_group_id`),
  KEY `idx_backup_group_id` (`backup_group_id`),
  KEY `idx_ai_suggest_type` (`ai_suggest_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI backup material group update history log';
```

## 5. 配置设计

### 5.1 AI 备用素材模版开关

```text
ai_backup.enabled=true
ai_backup.sync_create_enabled=true
ai_backup.min_stability_level=C
```

| 配置 | 说明 |
|---|---|
| `ai_backup.enabled` | AI 备用素材模版总开关 |
| `ai_backup.sync_create_enabled` | 主素材模版提交后是否同步尝试创建或更新 AI 备用素材模版 |
| `ai_backup.min_stability_level` | 发送链路可使用 AI 备用素材模版的最低稳定性评级 |

开关关闭时：

- 跳过 AI 备用素材模版创建；
- 记录 info 日志；
- 创建接口仍返回 `materialGroupId`；
- 更新接口仍返回成功。

### 5.2 AI 批量生成配置

```text
ai_suggestion.batch_generate_size=5
```

| 配置 | 说明 |
|---|---|
| `ai_suggestion.batch_generate_size` | 单次 LLM 批量生成最多包含的内容条数 |

### 5.3 AI 批量生成 Prompt 配置

AI 批量生成不复用原单条生成的 user prompt。

原因：

1. 原单条 prompt 面向一个素材内容，输出结构是单个 `suggestedContent`、`score`、`scoreReason`。
2. 批量 prompt 面向多个素材内容，必须要求 LLM 返回数组，并且每个结果必须带 `clientMaterialKey`，否则无法稳定匹配写库。
3. 如果在同一个 prompt 模板中通过分支兼容单条和批量，会增加模板复杂度，并提高破坏原 `generate` 行为的风险。

配置建议：

```text
ai_suggestion.batch_user_prompt_template
```

可选配置：

```text
ai_suggestion.batch_system_prompt
```

推荐实现：

- 单条 `generate` 继续使用现有 `ai_suggestion.system_prompt` 和 `ai_suggestion.user_prompt_template`；
- 批量 `batchGenerate` 使用新增 `ai_suggestion.batch_user_prompt_template`；
- 批量 system prompt 默认复用 `ai_suggestion.system_prompt`；如果配置了 `ai_suggestion.batch_system_prompt`，则优先使用批量专用 system prompt。

批量 user prompt 必须明确输出格式，例如：

```json
[
  {
    "clientMaterialKey": "body-key-1",
    "suggestedContent": "AI generated content",
    "score": 4.5,
    "scoreReason": "Reason text"
  }
]
```

`AgentPromptConfig` 需要新增批量 prompt 配置字段，并支持 Apollo 动态刷新。

### 5.4 稳定性评级配置

保留原方案的独立稳定性评级规则：

```text
ai_backup.stability_rules
```

示例：

```json
[
  {"level": "A", "condition": "utilityPercent >= 0.7", "reason": "Utility rate >= 70%, stable"},
  {"level": "B", "condition": "utilityPercent >= 0.5", "reason": "Utility rate >= 50%, relatively stable"},
  {"level": "C", "condition": "utilityPercent >= 0.3", "reason": "Utility rate >= 30%, acceptable"},
  {"level": "D", "condition": "true", "reason": "Utility rate < 30%, needs improvement"}
]
```

Redis 缓存：

```text
Key: material_group_stability:{materialGroupId}
TTL: 可配置，默认 30 分钟
刷新方式：XXL-Job 定时刷新
```

## 6. 常量与枚举设计

实现时该用常量的加常量，该用枚举的加枚举，避免在业务代码中散落硬编码字符串或数字。

### 6.1 枚举

#### `SuggestTypeEnum`

新增：

```java
AI_BACKUP_MATERIAL_GROUP("AI_BACKUP_MATERIAL_GROUP", "AI backup material group")
```

所有 AI 备用素材模版类型判断、查询、写库、过滤都使用 `SuggestTypeEnum.AI_BACKUP_MATERIAL_GROUP.getCode()`，不直接写字符串。

#### `AiMaterialSuggestionStatusEnum`

新增 AI 素材建议生成状态枚举：

```java
ACCEPTED_FOR_AI_BACKUP(1, "Accepted for AI backup material template"),
NOT_ACCEPTED_FOR_AI_BACKUP(2, "Not accepted for AI backup material template"),
GENERATION_FAILED(3, "Generation failed")
```

使用范围：

- `batchGenerate` 成功/失败写库；
- AI 备用素材状态接口状态判断；
- AI 备用素材模版创建时筛选 `status = 1`；
- 失败记录写入 `status = 3`。

#### `AiBackupMaterialGenerateStatusEnum`

新增状态接口返回枚举：

```java
SUCCESS,
FAILED,
PROCESSING
```

状态接口响应中的 `items[].status` 使用该枚举 name，不直接写字符串。

### 6.2 常量

建议新增常量类或放入现有合适常量类，例如 `AiMaterialSuggestionConstants`：

```java
public static final String SOURCE_LANE_ALL = "ALL";
public static final String EMPTY_SOURCE_LANE = "";
public static final String GENERATION_FAILED_CONTENT = "Generation failed";
public static final String MISSING_BATCH_RESULT_REASON = "Missing batch result";
public static final String AI_BACKUP_MATERIAL_GROUP_NAME_SEPARATOR = "_ai_backup_by_";
public static final String TRIGGER_SOURCE_SYNC = "SYNC";
public static final String TRIGGER_SOURCE_JOB = "JOB";
public static final String OPERATE_TYPE_CREATE = "CREATE";
public static final String OPERATE_TYPE_UPDATE = "UPDATE";
```

使用要求：

1. 传泳道时，规则查询里的通用泳道值使用 `SOURCE_LANE_ALL`。
2. 不传泳道时，规则查询不加 `source_lane` 条件；生成记录落库值使用 `EMPTY_SOURCE_LANE`。
3. 失败内容使用 `GENERATION_FAILED_CONTENT`。
4. 批量返回缺失原因使用 `MISSING_BATCH_RESULT_REASON`。
5. AI 备用素材模版名称格式使用统一工具方法生成，不在业务代码拼接硬编码。
6. 操作日志的 `trigger_source`、`operate_type` 使用常量或枚举，不硬编码。

### 6.3 配置 key 常量

Apollo / Spring 配置 key 应统一收敛到配置类或常量，避免散落字符串：

```text
ai_backup.enabled
ai_backup.sync_create_enabled
ai_backup.min_stability_level
ai_suggestion.batch_generate_size
ai_suggestion.batch_user_prompt_template
ai_suggestion.batch_system_prompt
ai_backup.stability_rules
```

`BusinessConfig`、稳定性配置类、批量生成逻辑统一引用这些配置项，不在业务方法中重复硬编码 key。


## 7. 接口设计

### 7.1 单条生成接口 `generate`

接口：

```text
POST /api/admin/ai-suggestion/generate
```

保留原同步单条生成能力。

调整点：

1. `sourceLanes` 传值时：
   - 按传入泳道生成；
   - 查询规则：`source_lane IN (sourceLane, 'ALL')`；
   - 保留泳道白名单和 `SourceLaneEnum` 校验；
   - 生成记录写入对应 `source_lane`。
2. `sourceLanes` 不传或为空时：
   - 不按泳道生成；
   - 规则查询不加 `source_lane` 条件；
   - 生成记录 `source_lane = ''`；
   - 不做泳道白名单校验。
3. `AiSuggestionGenerateReqDTO.MaterialContent#materialType` 删除。
4. 顶层 `materialType` 保留，用于规则查询、prompt 填充和落库。

### 7.2 批量异步生成接口 `batchGenerate`

接口：

```text
POST /api/admin/ai-suggestion/batchGenerate
```

用途：为 AI 备用素材模版批量生成建议内容。

请求示例：

```json
{
  "materialGroupId": 100,
  "suggestType": "AI_BACKUP_MATERIAL_GROUP",
  "materialType": "BODY",
  "language": "en_US",
  "sourceLanes": [],
  "materialContents": [
    {
      "clientMaterialKey": "body-key-1",
      "content": "original body content 1",
      "lastSuggestedContent": "",
      "userFeedback": ""
    },
    {
      "clientMaterialKey": "body-key-2",
      "content": "original body content 2",
      "lastSuggestedContent": "",
      "userFeedback": ""
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `materialGroupId` | 否 | 已保存主素材模版 ID；新建素材模版时可为空，后续通过 backfill 回填 |
| `suggestType` | 是 | AI 备用素材模版固定传 `AI_BACKUP_MATERIAL_GROUP` |
| `materialType` | 是 | 当前为 `BODY` |
| `language` | 否 | 规则本地化语言，默认 `en_US` |
| `sourceLanes` | 否 | 传值时按泳道生成；为空时不按泳道生成，规则查询不加 `source_lane` 条件 |
| `materialContents` | 是 | 待生成内容列表 |
| `materialContents[].clientMaterialKey` | 是 | 唯一标识；同一次请求内必须唯一 |
| `materialContents[].content` | 是 | 原始 body 内容 |
| `materialContents[].lastSuggestedContent` | 否 | 上一次 AI 生成内容 |
| `materialContents[].userFeedback` | 否 | 用户重新生成反馈 |

响应示例：

```json
{
  "acceptedCount": 2,
  "items": [
    {
      "clientMaterialKey": "body-key-1",
      "accepted": true
    },
    {
      "clientMaterialKey": "body-key-2",
      "accepted": true
    }
  ]
}
```

接口行为：

1. 不预插入 `ai_material_suggestion`。
2. 校验通过后提交后台异步任务并立即返回。
3. 后台异步任务批量调用 AI。
4. AI 成功后插入 `status = 1` 的成功记录。
5. AI 失败后插入 `status = 3` 的失败记录。

### 7.3 AI 备用素材生成状态接口

接口：

```text
POST /api/admin/ai-suggestion/backup-material/status
```

用途：前端提交主素材模版前，查询 AI 备用素材生成结果统计。

请求示例：

```json
{
  "materialGroupId": 100,
  "clientMaterialKeys": ["body-key-1", "body-key-2", "body-key-3"]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `materialGroupId` | 否 | 已保存主素材模版 ID；有值时可作为额外过滤条件 |
| `clientMaterialKeys` | 是 | 需要检查的 body key 列表 |

查询条件：

```text
suggest_type = AI_BACKUP_MATERIAL_GROUP
client_material_key IN (...)
```

如果 `clientMaterialKeys` 数量较大，必须分批 `IN` 查询。

状态判断：

| 状态 | 判断规则 |
|---|---|
| `SUCCESS` | 该 key 存在成功记录：`status = 1` 且 `suggested_content` 有效 |
| `FAILED` | 该 key 不存在成功记录，但存在失败记录：`status = 3` |
| `PROCESSING` | 该 key 查不到成功或失败记录 |

有效内容：

```text
suggested_content IS NOT NULL
suggested_content != ''
suggested_content != 'Generation failed'
```

同一个 `clientMaterialKey` 有多条成功记录时，使用最后一条成功记录：

```text
generation_seq DESC, create_time DESC, id DESC
```

响应示例：

```json
{
  "totalCount": 3,
  "successCount": 1,
  "failedCount": 1,
  "processingCount": 1,
  "items": [
    {
      "clientMaterialKey": "body-key-1",
      "status": "SUCCESS",
      "suggestionId": 1001,
      "generationSeq": 2
    },
    {
      "clientMaterialKey": "body-key-2",
      "status": "FAILED",
      "suggestionId": 1002,
      "message": "Generation failed"
    },
    {
      "clientMaterialKey": "body-key-3",
      "status": "PROCESSING"
    }
  ]
}
```

前端提交策略：

1. 用户点击提交时调用状态接口。
2. 如果 `processingCount > 0`，前端轮询状态接口，建议每 2 秒一次，最多等待 30 秒。
3. 等待结束后：
   - `successCount > 0`：直接提交主素材模版；
   - `successCount = 0`：提示后仍提交主素材模版。

提示文案：

```text
AI备用素材模版创建出现异常，本次AI备用素材模版暂时不可用
```

### 7.4 `feedback` 接口

接口：

```text
POST /api/admin/ai-suggestion/feedback
```

调整点：

1. 不再更新 `ai_material_suggestion.status`。
2. 只维护反馈相关字段：
   - `feedback_type`
   - `feedback_reason`
   - `user_score`
   - `update_time`
3. 普通 AI 建议的采纳、拒绝、评分不影响 AI 备用素材模版创建判断。

### 7.5 素材模版列表接口 `listAll`

接口：

```text
POST /api/admin/material/listAll
```

过滤逻辑从原未上线设计的 `source_type != 1` 改为：

```text
ai_suggest_type IS NULL
OR ai_suggest_type = ''
OR ai_suggest_type != AI_BACKUP_MATERIAL_GROUP
```

目标：只过滤 AI 备用素材模版，不误伤其他可能的 `source_type = 1` 数据。

## 8. AI 批量生成设计

### 8.1 批量生成分组

`batchGenerate` 后台任务按规则上下文分组：

```text
sourceLane 或空泳道
materialType
suggestType
language
ruleSnapshot
```

同组内按 `ai_suggestion.batch_generate_size` 拆小批。

### 8.2 Prompt 使用策略

单条生成和批量生成不使用同一个 user prompt。

- 单条 `generate`：继续使用现有 `ai_suggestion.user_prompt_template`，输出单个 JSON 对象。
- 批量 `batchGenerate`：使用新增 `ai_suggestion.batch_user_prompt_template`，输出 JSON 数组。
- system prompt 默认复用现有 `ai_suggestion.system_prompt`；如果配置了 `ai_suggestion.batch_system_prompt`，批量生成优先使用该配置。

原单条生成逻辑只做必要抽取复用，例如规则加载、规则本地化、prompt 变量构造，不改变原输出协议。批量生成新增独立的 prompt 构造和结果解析逻辑，避免影响现有 `generate`。

### 8.3 批量 prompt 格式

请求给 LLM 的每个 item 必须带 `clientMaterialKey`：

```json
[
  {
    "clientMaterialKey": "body-key-1",
    "content": "original body content 1"
  },
  {
    "clientMaterialKey": "body-key-2",
    "content": "original body content 2"
  }
]
```

LLM 返回格式：

```json
[
  {
    "clientMaterialKey": "body-key-1",
    "suggestedContent": "AI generated content 1",
    "score": 4.5,
    "scoreReason": "Reason text"
  },
  {
    "clientMaterialKey": "body-key-2",
    "suggestedContent": "AI generated content 2",
    "score": 4.2,
    "scoreReason": "Reason text"
  }
]
```

### 8.4 成功写库

AI 返回成功后插入：

```text
client_material_key = item.clientMaterialKey
material_type = request.materialType
suggest_type = request.suggestType
source_lane = sourceLane 或 ''
material_group_id = request.materialGroupId，可为空
origin_content = item.content
last_suggested_content = item.lastSuggestedContent
regen_feedback = item.userFeedback
suggested_content = result.suggestedContent
score = result.score
score_reason = result.scoreReason
status = 1
create_time = now
update_time = now
```

`generation_seq` 计算：

```text
按 client_material_key + material_type + suggest_type + source_lane 查询当前最大 generation_seq，再 +1
```

涉及批量 key 查询时，必须分批 `IN`。

### 8.5 失败写库

整批调用失败、单个 key 结果缺失、解析失败时，对应 key 插入失败记录：

```text
suggested_content = Generation failed
status = 3
score_reason = 失败原因或 Missing batch result
```

不做单条降级重试，避免后台任务耗时不可控。前端可重新触发批量生成。

## 9. 主素材模版提交后同步创建 AI 备用素材模版

### 9.1 不使用 MQ

主素材模版创建/更新成功后，不再发送 MQ，也不再通过 Consumer 创建 AI 备用素材模版。

移除或不再使用：

```text
AiBackupMaterialGroupCreateConsumer
rocketmq.topic.aiBackupMaterialGroupCreate
rocketmq.consumer.aiBackupMaterialGroupCreate.groupName
ai_backup.create_async
```

### 9.2 同步创建流程

主素材模版创建/更新流程：

```text
1. 保存主素材模版
2. 保存或更新素材
3. 保存或更新主素材组合
4. 保存 lane config
5. backfill ai_material_suggestion 的 material_group_id / material_id
6. 同线程同步尝试创建或更新 AI 备用素材模版
7. 返回 materialGroupId
```

同步创建必须在 backfill 之后执行。

### 9.3 异常与开关

触发前检查：

```text
ai_backup.enabled = true
ai_backup.sync_create_enabled = true
```

任一开关关闭：

- 跳过 AI 备用素材模版创建；
- 记录 info 日志；
- 创建接口仍返回 `materialGroupId`；
- 更新接口仍返回成功。

同步创建异常：

- catch 异常；
- 记录 error 日志；
- 不抛出；
- 不影响主素材模版返回。

### 9.4 事务边界

推荐使用 `TransactionSynchronization.afterCommit()` 在主事务提交后同线程执行 AI 备用素材模版创建。

原因：

1. 确保主素材模版、主素材组合、backfill 数据已提交后再查询。
2. AI 备用素材模版创建失败不会回滚主素材模版事务。
3. 不依赖 MQ，仍属于提交后的同步尝试创建。

如果不存在事务上下文，则直接执行并捕获异常。

## 10. AI 备用素材模版创建/更新算法

### 10.1 查询主素材模版

根据 `materialGroupId` 查询主素材模版。如果不存在，记录 warn 并返回。

### 10.2 查询最新成功 AI 建议

查询条件：

```text
material_group_id = materialGroupId
suggest_type = AI_BACKUP_MATERIAL_GROUP
status = 1
suggested_content 有效
```

有效内容：

```text
suggested_content IS NOT NULL
suggested_content != ''
suggested_content != 'Generation failed'
```

按 `clientMaterialKey` 分组，每组取最后一条成功记录：

```text
generation_seq DESC, create_time DESC, id DESC
```

没有成功建议时，记录 info 并返回，不影响主流程。

### 10.3 创建或更新 AI 备用素材模版

查询 AI 备用素材模版：

```text
primary_group_id = materialGroupId
ai_suggest_type = AI_BACKUP_MATERIAL_GROUP
source_type = 1
```

不存在则创建：

```text
name = buildAiBackupMaterialGroupName(主素材模版名称, aiSuggestType)
template_type = 主素材模版 templateType
language = 主素材模版 language
status = 主素材模版状态或默认 ACTIVE
combination_mode = 主素材模版 combinationMode
primary_group_id = materialGroupId
source_type = 1
ai_suggest_type = AI_BACKUP_MATERIAL_GROUP
```

已存在则更新：

- `name`
- `template_type`
- `language`
- `combination_mode`
- `updater`
- `utime`

### 10.4 构建目标 AI 备用素材组合

对每条最新成功建议：

1. 通过 `material_id` 找到主 body 素材。
2. 查询当前主素材模版中使用该 body 的所有有效主素材组合。
3. 对每个主素材组合构建一个目标 AI 备用素材组合。
4. 复制主素材组合 header/footer/buttons 到 AI 备用素材模版。
5. 用 AI 建议内容创建 AI body 素材。
6. 设置：
   ```text
   primary_combination_id = 主素材组合 ID
   source_type = 1
   material_group_id = AI 备用素材模版 ID
   ```

如果同一个 body 出现在多个主素材组合中，需要为每个主素材组合生成对应 AI 备用素材组合。

### 10.5 幂等更新

以 `primary_combination_id` 作为 AI 备用素材组合的幂等键。

处理规则：

1. 已存在相同 `primary_combination_id` 的 AI 备用素材组合：更新素材引用、状态、更新时间。
2. 不存在：新增 AI 备用素材组合。
3. 当前 AI 备用素材模版中存在但本次目标集合不存在的组合：置为 inactive 或不再参与返回。
4. 组合状态和主素材组合保持一致：主素材组合停用时，对应 AI 备用素材组合也停用。

## 11. 编辑主素材模版联动

编辑主素材模版时，通过同一个幂等同步方法更新 AI 备用素材模版：

```java
createOrUpdateAiBackupGroup(materialGroupId, operator, SuggestTypeEnum.AI_BACKUP_MATERIAL_GROUP.getCode())
```

### 11.1 编辑主用素材组合方式联动

当主素材模版 `combination_mode` 变更、或手动组合调整时：

1. 同步更新 AI 备用素材模版 `combination_mode`。
2. 重新基于当前主素材组合和最新成功 AI 建议生成目标 AI 备用素材组合。
3. 保持 `primary_combination_id` 指向当前主素材组合。
4. 不再存在的主素材组合，对应 AI 备用素材组合停用或不返回。

### 11.2 新增 body 联动

运营编辑主素材模版，新增 body 素材；新增 body 已通过 `batchGenerate` 生成 `AI_BACKUP_MATERIAL_GROUP` 成功建议时：

1. 主素材模版保存后，`AiMaterialSuggestionBackfillService` 根据 `clientMaterialKey` 回填新增 body 的 `material_id` 和 `material_group_id`。
2. 同步创建或更新 AI 备用素材模版时，查询到该新增 body 的最新成功建议。
3. 根据新增 body 所在主素材组合创建或更新对应 AI 备用素材组合。
4. 如果 AI 备用素材模版已存在，则新增或更新受影响的备用素材组合。
5. 如果 AI 备用素材模版不存在，则创建 AI 备用素材模版并生成组合。
6. 如果新增 body 没有成功建议，则跳过该 body，不影响主素材模版提交。

新增 body 联动不再按泳道处理。

## 15. 测试方案

### 15.1 单元测试

1. `generate`：
   - 传泳道时查 `sourceLane + ALL` 规则；
   - 不传泳道时规则查询不加 `source_lane` 条件；
   - 无泳道时不做白名单校验，生成记录 `source_lane` 为空字符串。
2. `feedback`：
   - 采纳、拒绝、忽略、评分时只更新反馈字段；
   - 不更新 `status`。
3. `batchGenerate`：
   - 同一请求内 `clientMaterialKey` 重复时校验失败；
   - 批量成功后插入 `status = 1`；
   - 批量失败后插入 `status = 3` 和 `Generation failed`；
   - 返回缺失 key 时插入失败记录；
   - 批量 `generation_seq` 计算正确。
4. 状态接口：
   - 有成功记录返回 `SUCCESS`；
   - 无成功但有失败返回 `FAILED`；
   - 无成功和失败返回 `PROCESSING`；
   - 多条成功取最新成功记录；
   - 大量 `clientMaterialKeys` 分批查询。
5. AI 备用素材模版创建：
   - 不按泳道查询；
   - 只使用 `AI_BACKUP_MATERIAL_GROUP + status = 1`；
   - 同 key 多成功取最新；
   - 无成功建议时跳过不抛异常；
   - 一个 body 出现在多个主素材组合时生成多条 AI 备用素材组合；
   - 已有 AI 备用素材组合时按 `primary_combination_id` 幂等更新。
6. 编辑联动：
   - 主素材组合方式变更后 AI 备用素材模版 `combination_mode` 同步；
   - 新增 body 且有成功建议时新增或更新 AI 备用素材组合；
   - 新增 body 无成功建议时跳过；
   - 主素材组合停用时 AI 备用素材组合同步停用或不返回。
7. 同步创建降级：
   - 开关关闭时主素材模版仍返回 ID；
   - AI 备用素材模版创建异常时主素材模版仍返回 ID；
   - 异常日志包含 `materialGroupId`、`aiSuggestType`、operator。
8. 常量与枚举：
   - `AI_BACKUP_MATERIAL_GROUP`、`Generation failed`、`ALL`、`SUCCESS/FAILED/PROCESSING` 等不在业务代码硬编码；
   - 状态判断使用枚举 code/name。
9. AI 备用素材模版名称：
   - 名称按 `原name_ai_backup_by_{suggestType}` 生成；
   - 原 name 接近 DB 上限时不会超长；
   - 截断后名称冲突时可正常生成唯一名称。
10. Prompt 配置：
   - 单条生成仍使用原 user prompt；
   - 批量生成使用新增 batch user prompt；
   - 批量返回按 `clientMaterialKey` 解析；
   - 批量 prompt 配置缺失时有明确异常或降级策略。

## 16. 风险与降级

| 风险 | 处理 |
|---|---|
| AI 批量生成耗时较长 | 前端状态接口轮询，最多等待 30 秒 |
| AI 全部失败 | 前端提示 AI 备用素材暂不可用，仍提交主素材模版 |
| 同步创建 AI 备用素材模版异常 | catch 后记录日志，不影响主素材模版 ID 返回 |
| 开关关闭 | 跳过 AI 备用素材模版创建，主流程正常返回 |
| 主素材模版新增 body 无 AI 成功建议 | 跳过该 body，不影响主素材模版 |
| `clientMaterialKeys` 数量过大 | 分批 `IN` 查询 |
| 多次生成同一 key | 取最新成功记录 |
| 主素材组合变化导致备用素材组合不一致 | 同步方法每次基于当前主素材组合重建目标集合并幂等更新 |

## 17. 评审关注点

1. `ai_material_suggestion.status` 新语义是否需要同步通知前端和数据分析使用方。
2. `batchGenerate` 不预插入时，状态接口将无记录视为 `PROCESSING` 是否满足前端交互。
3. 前端最多等待 30 秒后仍提交的产品行为是否确认。
4. 同步创建 AI 备用素材模版是否接受 afterCommit 同线程执行。
5. `sourceLanes` 为空时，规则查询不加 `source_lane` 条件是否满足规则配置预期。
6. AI 备用素材模版同步时，旧 AI 备用素材和旧 AI 备用素材组合是否需要物理删除；本方案建议逻辑停用或不返回，避免误删历史。

# 素材品类、标签与组合稳定性后端实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. All steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变现有发送链路的前提下，完成普通素材品类、标签来源与 AI 候选、组合品类校验、后端组合预览和组合维度稳定性评级。

**Architecture:** 复用现有 `category/tag/tag_relation`、Mongo `message_material` 和固定槽位组合模型。把品类收口抽成独立服务，组合预览使用只读请求 DTO 和与保存逻辑一致的候选生成规则；组合稳定性复用素材模板级 Utility 占比计算链路，新增组合维度缓存和批量接口。

**Tech Stack:** Java 8、Spring Boot 2.2、MyBatis-Plus、Spring Data MongoDB、Redis、RocketMQ、XXL-Job、JUnit 5。

## Global Constraints

- 所有回复使用中文；不提交 Git，不创建 commit。
- 不读取、分析或修改 `.trae/`。
- 所有代码注释使用英文。
- LTO 和轮播素材本期不支持素材品类和标签；普通 HEADER/BODY/FOOTER/BUTTONS 才参与本期品类与标签链路。
- 历史素材缺少品类按 `UNCATEGORIZED` 读取；历史组合新增快照字段默认 `UNCATEGORIZED`，不批量重算。
- 新素材品类使用 Mongo `message_material.material_category_code` 顶层字段，创建后不可修改。
- `category` 的 `source_type` 为 `0=AI、1=管理员维护、2=运营（当前禁止）`；`category_type` 为 `BUSINESS_MATERIAL` 或 `TAG_ONLY`。
- AI 新分类返回 `categoryName` 和语义化 `categoryCode`；命中已有分类时复用数据库 code，新分类 code 必须由后端校验后入库。
- 同一素材、同一标签的 AI/运营等多条 `tag_relation` 必须保留，不建立关系唯一索引，不合并来源。
- 跨品类 AI 标签保留为 `binding_status=0` 候选，不进入正式标签筛选和效果统计。
- MySQL 大批量 `IN` 每批最多 500 个值，批量任务使用分批查询。
- 新表必须包含 `create_time`、`update_time`，非空字段有明确默认值，并创建 `idx_create_time`。
- 合并或引入 `test3` 改动均禁止；出现冲突时停止并报告，不自行解决。

**Request contract:**

```json
{
  "materialGroupId": null,
  "combinationMode": "RANDOM",
  "current": 1,
  "size": 10,
  "memberFilter": {"tempKey": "body-1"},
  "materials": {
    "headerList": [],
    "bodyList": [],
    "footerList": [],
    "buttons": null,
    "limitedTimeOfferList": [],
    "carouselBodyList": [],
    "cardIds": []
  }
}
```

**Response contract:**

- Existing combinations first, new candidates last.
- New candidates have null persisted-only fields and `exists=false`.
- Conflicting candidates are omitted, not returned as rows.
- `typeSummary.NORMAL/LTO/CAROUSEL` contains `hasMaterials`, `combinationCount`, `newCount`, `blocked`, `blockedReason`.

**Steps:**

- [ ] Load existing group combinations in paginated batches and map them to preview rows.
- [ ] Implement NORMAL candidate expansion using existing header/body/footer/button rules and combination keys.
- [ ] Implement LTO candidate expansion using existing `LimitedTimeOfferSupport` validation; change both preview and formal generation so no qualifying IMAGE/VIDEO header means no LTO combination, not an empty-header combination.
- [ ] Implement CAROUSEL candidate expansion using carousel body and ordered card groups; retain current 2–10 card and card-button validation behavior.
- [ ] Return `typeSummary` independently from page pagination so the right panel and submit confirmation can show total counts.

## Known Decisions

- LTO and carousel are excluded from the category/tag feature in this phase.
- No qualifying IMAGE/VIDEO header means no LTO combination; preview and formal generation must match.
- Existing combinations are displayed before new candidates; new candidates are always last.
- Preview list has no action column; persisted activation/deactivation remains on the combination-template page.
- Static type illustration images are frontend assets supplied later; backend returns only type summaries and preview data.

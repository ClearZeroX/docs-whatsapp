# 图片理解模型替换、AI标签规则打标及页面内容优化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成图片理解、AI 标签、规则打标和页面内容优化，保证前后端接口、页面展示、来源字段和模型流程保持一致。

**Architecture:** 图片素材先生成结构化 `image_content_info`，普通 AI 标签和规则 AI 判定复用当前标签模型配置但使用不同 Prompt 和结果来源。页面优化沿用现有接口，只有缺少字段时补充后端返回，避免改变既有分流计算和素材标签消费逻辑。

**Tech Stack:** Java/Spring Boot/MyBatis-Plus、Vue 2、Element UI、Apollo、Ark Responses、RocketMQ、Maven、Jest。

## Global Constraints

- 所有改动不提交 Git、不 push。
- 不读取、不分析、不修改 `.trae/`。
- 代码注释使用英文。
- 修改代码后完成对应编译或测试验证。
- `material_tag.source_type` 表示标签定义创建来源；`material_category_tag_relation.source_type` 表示素材标签关系产生来源。
- `scope=RULE` 只用于规则打标，`material_category_code` 必须为空；规则关系品类使用运营创建素材时保存的品类。
- 不新增规则表、规则标签关联表、`rule_id` 字段。
- 任务按权重分流的组合稳定性使用现有 `stabilityLevel`。

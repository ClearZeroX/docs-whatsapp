# 印尼生产日志与数据库工具实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 创建一个与测试环境 MCP 完全分离的生产诊断 MCP Server，仅在用户明确说明“印尼生产”时提供日志、MySQL 和 MongoDB 只读查询能力。

**Architecture:** 新建独立的 Python stdio MCP Server，不修改现有 `business-diagnostic-mcp`。通过本地 Chrome 会话读取 `log.rupiahcepatweb.com` 和 `dbs.rupiahcepatweb.com` 的临时登录态，在内存中请求固定接口；工具层只暴露结构化参数，日志走 Kibana 查询适配器，数据库走 DBS `/query/` 适配器，MySQL 与 MongoDB 使用独立的查询构造器和只读校验器。

**Tech Stack:** Python 3、标准库 JSON-RPC/HTTP、`requests`、`browser_cookie3`、pytest。

## Global Constraints

- 所有生产工具名称以 `idn_prod_` 开头，与测试环境工具名称明确区分。
- 只有用户明确说明“印尼生产 / IDN 生产 / Indonesia production / idn-prod”时，生产 Skill 才允许调用生产工具。
- 日志工具只接受关键词或 traceId，不接受任意 KQL；用户指定时间段必须被保留并校验。
- MySQL 只允许结构化生成 `SELECT`、`COUNT`、`EXPLAIN`；不接受原始 SQL。
- MongoDB 只允许结构化生成 `db.<collection>.find(filter, projection).sort(sort).limit(limit)`；不接受原始 Mongo 命令、任意 JavaScript 或聚合管道。
- MySQL 与 MongoDB 的实例固定为 `10.95.6.3-ob_collection` 和 `10.95.6.240-whatsapp-crm`，数据库固定为 `whatsapp_crm`。
- MySQL 的 `IN`、MongoDB 的 `$in/$nin` 超过批量阈值时必须分批执行。
- 不读取或保存明文密码；会话信息只在进程内存中使用，不写入配置、日志或结果文件。
- 不修改 `.trae` 或 `trae-docs` 内容，不提交 Git。
- 所有代码注释使用英文。

# AI 素材伪装：优化规则与提示词

> 日期：2026-09-11
> 说明：当前仅处理 BODY 文本素材；本文档规则以印尼环境为例（语言键为 `zh_CN` / `en_US` / `id`）；若为尼日利亚环境，会使用带 `en_GB` 说明的对应规则。
> 变更点：
> 1. OJK 声明改为“有则合规保留、无则不新增”，消除原 `OJK_CONS_016`（无条件必须包含）与 `OJK_REDLINE_028` 的冲突。
> 2. 模板变量只要求数量一致，允许顺序调整（原 `GEN_CONS_001` 要求顺序不变，已放宽）。
> 3. 删除建议 `AI_SUGG_002`（添加中立免责声明），与“不得新增免责声明”红线冲突。
> 4. 删除纯图片/人物类规则 `OJK_REDLINE_019`（货币展示）、`OJK_REDLINE_020`（广告角色），后续支持图片素材时再补齐。
> 5. 合并去重：保证性/绝对化/无依据/无风险表述合并；OJK 声明相关 8 条合并；时效/流程、额度/分期、信息真实披露等归类合并。
> 6. 规则数由 59 条收敛为 24 条。

## 二、提示词说明（generate 与 batchGenerate 共用）

当前代码中，`/generate`（单条）与 `/batchGenerate`（批量）共用同一套提示词结构：

| 配置项 | 用途 |
|---|---|
| `ai_suggestion.batch_system_prompt` | system prompt（批量与单条共用，**日常维护只改这里**） |
| `ai_suggestion.batch_user_prompt_template` | user prompt（配置里写死固定文案，无需改动） |

> 必须配置以上两个配置项，任一缺失时接口直接报错，不再降级到单条配置或默认值。

说明：

- **系统提示词**：配置的静态部分 + 代码自动追加的动态内容（已按 `ruleType` 分类）：
  - 规则按 `RED_LINE / CONSTRAINT / SUGGESTION` 分组拼接（未知类型作为 Reference 兜底）；
  - 追加内容示例：

    ```text
    Rules:
    {ruleSnapshot}
    
    Material Type: {materialType}
    
    Source Text:
    {items}
    ```

- **user prompt**：仍从配置读取，配置中写死固定指令即可，**不含任何动态占位符**，以后提示词调整不用改它；
- `/generate`：`{items}` 为只有 1 项的数组；
- `/batchGenerate`：`{items}` 为多条素材数组；
- LLM 统一返回 JSON 数组；单条接口解析时取数组第一条作为结果。

## 三、可维护的 systemPrompt（Apollo 配置内容）

```text
你是 WhatsApp UTILITY 模版内容伪装专家。

核心策略：Keep MARKETING Purpose, Wear UTILITY Skin。
把营销话术包装成系统自动通知/账户事务公告，保留业务意图、消除营销感知。

背景：Meta 会检测并降级 MARKETING 风格的模版，导致失去 UTILITY 发送配额和更高的消息频率；目标是通过 UTILITY 风格（服务通知、事务性消息）通过审核，同时保持用户转化效果。

【最高原则】
1. 规则高于一切：红线绝对不可违反；约束必须满足；建议仅作风格参考；与红线/约束冲突时以规则为准。
2. 不新增原文没有的信息：原文不含的监管声明、免责声明、OJK 表述及额外承诺不得新增；原文已含的按对应规则处理。
3. 除规则明确允许的替换和伪装策略外，保持原文信息保真。

【伪装策略】（具体细则以【规则】为准）
用"系统通知/状态更新/额度提醒/账户变更"替代促销话术；用陈述句替代祈使句，把行动号召隐含在信息告知中；保留额度、利率、时效等核心利益点但用通知口吻；不新增促销/活动类表述，原文已有的促销信息按规则披露处理。

【规则说明】（当前规则仅包含三类）
- Red-line Rules：绝对不可违反；
- Constraint Rules：必须满足；
- Positive Suggestions：推荐方向，仅作风格参考。

【动态内容说明】
系统提示末尾会追加以下动态内容：
- Rules: 已按 Red-line / Constraint / Positive Suggestions 分组的规则；
- Material Type: 素材类型；
- Source Text: 待改写的原文。
改写时需同时满足上述规则与约束。

【处理流程】
1. 先阅读全部红线并牢记。
2. 逐条把原文改写为 UTILITY 风格。
3. 改写后逐条对照红线自查，违反立即修正并重新自查。
4. 按输出格式返回。

【输出要求】
- 输出语言与每条原始内容语言一致。
- 只输出纯 JSON 数组，不含 markdown 标记或 thinking 标签。
- 规则仅用于指导改写，不得照搬规则文字；如需 OJK/监管表述，按 OJK 红线的"有则保留并规范、无则不新增"执行。
- 返回数组长度必须与 items 长度一致，clientMaterialKey 与输入一一对应；单条输入也会以 1 项数组下发。
- 如有 userFeedback，必须在本次伪装中体现。

【输出格式】
[
  {
    "clientMaterialKey": "对应的 clientMaterialKey",
    "suggestedContent": "伪装后的 UTILITY 风格内容",
    "score": 0.00-5.00,
    "scoreReason": "评分理由，简述生成策略即可，不要过长"
  }
]
```

> 说明：systemPrompt 配置的是静态部分；代码调用时会在末尾追加 `Rules:` / `Material Type:` / `Source Text:` 动态内容（标签为英文）。

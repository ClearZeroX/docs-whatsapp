# 素材品类、标签、组合稳定性与页面优化一期需求

> 日期：2026-11-06 ｜ 状态：需求修订稿 ｜ 面向：业务、产品、前后端及数据团队

## 一、背景与目标

背景：

1. 当前创建素材模板时，可以配置头部、正文等素材并生成素材组合，但缺少业务用途约束，不同用途的素材可能被组合。
2. 运营无法在新建素材时直接指定标签，素材品类与标签没有明确关联。
3. 查看素材关联的组合及其稳定性需要跨页面查找。
4. 素材模板创建页较长，各类素材各自带“添加”按钮，组合生成结果在保存前不可见。

目标：

1. 按素材品类安全组合，支持运营在建素材时完成打标，使素材使用更精细。
2. 在素材模板页面直接预览可生成的组合，并查看组合稳定性。
3. 重新组织内容管理菜单和素材模板页面，降低运营操作成本。
4. 为后续按品类、标签、组合分析发送和转化效果及 AI 优化保留条件。

一期需求按三部分组织：

1. **品类、标签支持**：品类约束与打标能力；
2. **组合维度稳定性评级**：把现有素材模板级稳定性扩展到组合；
3. **页面优化**：内容管理菜单重构与素材模板页交互改造。

## 二、新增术语

1. **素材品类**：比 WhatsApp 模板分类（如 UTILITY、MARKETING）更细的业务分类，示例 `repay-1-day`（1 天内还款）、`repay-2-day`（2 天内还款）、`user-acquisition`（获客拉新）。品类由运营提供、研发维护。
2. **标签**：描述素材特征或意图的全局细分标记；一条素材可以有多个标签，也可以没有。同一个标签可以被不同素材品类的素材使用。
3. **AI 候选标签**：AI 判断与该素材已选品类不一致时保留的标签，仅供查看和差异分析，不作为正式标签使用。
4. **组合稳定性评级**：按组合维度计算 **S > A > B > C > D**，S 最高。
5. **素材包 / 素材组合模板 / 渠道模板**：内容管理菜单调整后的页面新名称。

## 三、需求详情

### 第一部分：品类、标签支持

本次在一期需求基础上重建素材品类和素材标签的数据模型。旧的 `category`、`tag`、`tag_relation`、`tag_rule` 表保持不变；新功能直接使用素材专用的新表，不读取旧表，不迁移旧数据，不提供旧新表兼容逻辑。

#### 1.1 素材品类和标签模型

新增四张素材专用表：

- `material_category`：素材品类定义，包含英文 `code` 和中文 `name`。
- `material_tag`：全局素材标签定义，包含英文 `code` 和中文 `name`。
- `material_category_tag_relation`：素材、素材品类和标签的关系，记录运营关系或 AI 关系。
- `material_tag_rule`：素材品类对应的 AI 提取规则。

素材标签不再归属于某个素材品类。同一个全局标签可以被不同素材品类的素材使用。

页面和接口均同时返回 `code`、`name`：

- 中文环境显示中文 `name`；
- 英文环境显示英文 `code`；
- 创建和编辑时同时录入英文 code 和中文 name；
- code 创建后不可修改，避免影响 AI 返回、历史关系和分析数据。

#### 1.2 Code 规则

素材品类 code 和素材标签 code 统一使用小写英文、数字和横线，长度 1～64，必须以小写英文开头。

- 素材品类 code：允许小写英文、数字和横线，例如 `repay-1-day`。
- 素材标签 code：在上述规则基础上允许冒号，例如 `disguise-system:notice`。
- 两类 code 均不允许空格、中文和大写字母。
- 素材品类 code 正则：`^[a-z][a-z0-9-]{0,63}$`。
- 素材标签 code 正则：`^[a-z][a-z0-9-:]{0,63}$`。
- 品类 code 和标签 code 均需全局唯一；标签中文 name 也需全局唯一。

当前代码中素材品类的下划线规则需要改成横线规则；旧标签名称的校验规则不直接复用，素材标签 code 使用新增的标签 code 规则。

#### 1.3 素材品类

- Mongo `message_material` 增加顶层字段 `material_category_code`。
- 新建普通素材必须选择一个启用的素材品类；创建后不允许修改。
- LTO 素材和轮播素材本期仍不支持品类和打标，不写素材品类字段，也不写新标签关系。
- 组合品类仍取成员素材自身的 `material_category_code`；真实品类去重后不超过一个才允许生成。
- `message_material_combination.material_category_code` 继续保存组合品类快照。

#### 1.4 全局素材标签

- 运营在创建普通素材时可以从全局素材标签中多选标签，也可以不选。
- 新建标签时同时填写英文 code 和中文 name，不再绑定当前素材品类。
- 标签管理页不提供素材品类筛选，也不展示标签所属品类。
- 素材编辑器中素材品类和标签是两个独立选择器；切换素材品类不清空已选标签。
- AI 标签和运营标签都引用 `material_tag.code`，不使用旧 `tag_id`。

#### 1.5 素材品类标签关系

`material_category_tag_relation` 同时记录运营手动绑定和 AI 识别关系，核心字段为：

- `material_id`：Mongo 素材 ID。
- `material_category_code`：当前关系携带的素材品类 code，必填。运营关系写素材实际品类；AI 关系写 AI 最终判断的品类。
- `material_tag_code`：全局素材标签 code，必填。
- `source_type`：`0=AI`、`1=管理员`、`2=运营`。
- `binding_status`：`1=正式`、`0=候选`；运营关系固定为正式，AI 关系按 AI 品类和素材实际品类是否一致判断。
- `accuracy_score`：标签在该素材上的准确度评分，默认 5，允许值为 1、2、3、4、5；只对 AI 关系参与 AI 准确率统计。
- `extract_log_id`：AI 提取日志 ID，非 AI 关系写 0。

不设置关系业务唯一约束。同一素材可以同时存在运营正式关系、AI 正式关系和 AI 候选关系。AI 重提只替换该素材的 AI 来源关系，不影响运营关系。

#### 1.6 AI 品类选择与 AI 打标

AI 对每个素材的素材品类选择继续使用当前三段式逻辑：

1. 优先判断运营创建素材时选择的 `materialCategoryCode` 是否符合素材内容；符合时沿用该品类。
2. 如果运营品类不符合或没有运营品类，从全部有效素材品类中选择最匹配的已有品类。
3. 只有运营品类不符合且已有品类均不匹配时，才允许新增素材品类。

AI 返回的素材品类字段为：

```json
{
  "materialCategoryCode": "repay-1-day",
  "materialCategoryName": "1天内还款"
}
```

命中已有品类时复用数据库中的 code/name；新增品类时后端校验 code 格式、长度、唯一性和名称语义。

AI 标签返回：

```json
{
  "tagCode": "disguise-system:notice",
  "tagName": "系统通知伪装",
  "confidence": 0.95
}
```

标签不再从素材品类下的标签中选择，而是从全局标签列表中选择。AI Prompt 中的品类列表保留 `exampleTags: []` 空字段作为后续扩展位，不表达标签属于品类；全局标签列表单独提供 `tagCode`、`tagName`、`aiDemoLevel`。

AI 关系的 `binding_status` 规则保持不变：AI 最终品类与素材实际品类相同为正式，不同为候选。候选关系可查看并参与差异分析，但不进入正式标签筛选和正式效果统计。

#### 1.7 素材标签规则

- `material_tag_rule` 使用 `material_category_code` 绑定素材品类，不使用分类 ID。
- 规则表达某个素材品类的 AI 提取要求，不表示标签属于该品类。
- 本期不新增规则与标签的直接关联表。
- 规则页面不展示“该品类下的全部标签”，保留规则名称、素材品类、必打标记、规则描述、适用范围、排序和状态。

#### 1.8 分类管理和数据分析

- 素材品类支持新建、编辑、停用和列表查询；停用品类不能用于新建素材或写入新关系。
- 标签支持新建、编辑、停用和全局列表查询。
- 运营手动标签默认准确度评分为 5，但不计入 AI 准确率。
- 后续分析可以按素材品类、标签 code、关系来源、正式/候选状态和准确度评分统计。
- 差异分析比较素材实际品类与 AI 关系携带品类，不自动修改素材品类、不自动转正候选标签。

### 第二部分：组合维度稳定性评级

#### 2.1 计算口径

- 等级沿用现有素材模板评级顺序 **S > A > B > C > D**。
- 数据来源与素材模板一致：`message_template.material_combination_id` → `message_template_waba` 的当前可用/历史 UTILITY 占比；
- 由 `material_group_id` 收窄到 `material_combination_id`，普通、AI 备份素材均覆盖。

#### 2.2 缓存与刷新

- Redis 前缀 `material_combination_stability:{combinationId}`，保存完整统计和评级。
- 新增/扩展 `RefreshMaterialCombinationStabilityCacheJob`，刷新近期更新、有模板变更、AI 备份相关组合；批量 `IN` 每批不超过 500。

#### 2.3 接口

- `POST /admin/api/material/combination/stability/batch`：按组合 ID 批量返回评级；组合列表批量补充，不逐行查询。

#### 2.4 前端展示

- 素材组合模板页、素材模板查看/编辑弹窗的“查看关联组合”浮层、素材模板列表展开区，组合列表均增加稳定性列显示 S/A/B/C/D。
- 查看模式只读，不提供启用、停用等写操作。

### 第三部分：页面优化

#### 3.1 内容管理菜单

新增【内容管理】父菜单，三项子菜单重命名并迁移：

```text
内容管理
├── 素材包（原素材模板）-一级内容
├── 素材组合模板（原素材组合）-二级内容
└── 渠道模板（原模板管理）
```

#### 3.2 素材模板列表

- 点击素材模板 ID，展开该素材模板的组合列表；分页加载、复用“素材组合模板”页结构与字段，并增加组合品类、稳定性列。

#### 3.3 素材模板新建/编辑页

> 组件名称说明：本期页面组件区域名称变更，旧称 → 新称及适用范围如下：
> - 模板头部 → **头部素材**（经典模板、限时优惠模板可使用）；
> - 模板内容 → **内容素材**（经典模板、限时优惠模板可使用）；
> - 模板脚部 → **脚部素材**（经典模板可使用）；
> - 模板按钮 → **按钮素材**（经典模板、限时优惠模板可使用）；
> - 限时优惠 → **限时优惠素材**（限时优惠模板使用）；
> - 轮播内容 → **轮播内容素材**（轮播模板使用）；
> - 轮播卡片 → **轮播卡片素材**（轮播模板使用）。

1. **区域顺序**：上下顺序：基础配置 → 组合方式 → 素材内容。|  右侧固定区域：模板类型要素说明区
2. **组件选择器**：顶部横排按钮 `[头部素材] [内容素材] [脚部素材] [按钮素材] [限时优惠素材] [轮播内容素材] [轮播卡片素材]` + 一个【添加】按钮；点选按钮高亮，点【添加】展开该区域并追加一条空项。各组件适用模板：
   - 头部素材：经典模板、限时优惠模板可使用；
   - 内容素材：经典模板、限时优惠模板可使用；
   - 脚部素材：经典模板可使用；
   - 按钮素材：经典模板、限时优惠模板可使用；
   - 限时优惠素材：限时优惠模板使用。
3. **组合方式区域**：
   - 随机组合显示组合预览列表；人工组合显示当前人工组合行。
   - 列表字段：`组合ID | 组合类型 | 是否存在 | 组合预览 | 组合状态 | 素材状态 | 品类 | 创建时间 | 已读率 | 近7日日均送达 | 覆盖泳道`；不展示素材模板名称，不设操作列。
   - 已存在组合排在前面，新增候选全部排在最后；分页默认 10 条/页，区域高度随分页伸缩；提供【刷新】按钮。
   - 新建行只在落库后才有的字段显示为空；冲突组合不展示。
4. **组合预览数据来源**：一律请求后端计算，新建阶段未保存素材用虚拟键（`tempKey/clientMaterialKey`）；编辑/查看阶段同时取已存在组合与编辑态新增候选。本期实现后端组合预览接口，规则校验统一在后端。
5. **LTO 预览**：若无符合条件的 HEADER，本期不生成 LTO 组合（需与后端确认规则改动）；预览 LTO 时校验按钮等组件搭配，不满足时弹出提示，如“请先添加对应按钮后再预览 LTO 素材”。
6. **素材【预览】按钮**：点击后请求后端，刷新上方组合预览列表，并浮层展示包含该素材的组合（列与分页同上行）；轮播卡片组同样支持。
7. **组合行预览**：点击组合预览列，弹手机模拟器预览，样式与“素材组合模板”页一致，覆盖普通、LTO、轮播三种形态。
8. **右侧固定说明区**：固定展示三幅静态图（经典模板、LTO 模板、轮播模板三种组合类型），每幅图下方配简短说明；图片由设计/运营后续提供静态资源，前端先以占位接入。
   - 每张图**下方**放三态标识（图标 + 短标签）：绿色 `✔ 可生成`、黄色 `! 待完善`、灰色 `− 未配置`；悬停显示原因（如“需 IMAGE/VIDEO 头部素材”）。
   - 标识判定来源于组合预览接口返回的 `typeSummary`：绿色=该类型组合数 > 0；黄色=已有该类型素材要素但组合数为 0（blocked）；灰色=无该类型素材要素。
   - 标识区带小圆圈刷新按钮 `⟳`；点【添加】【删除】【预览】也会自动刷新标识与组合预览列表。
9. **提交前组合确认浮层**：点【创建/更新】且通过前端必填校验后，先调用组合预览接口并弹出浮层：按 `经典模板 / LTO 模板 / 轮播模板` 纵向分段，段标题为 `共 X 个（新增 Y）`，每段默认展开；该类型数量为 0 时显示空态提示；`已存在` 行不计入新增；【取消】仅关闭浮层回到编辑页，【确认提交】才真正保存素材模板。

#### 3.4 素材模板查看页

- 展示内容与新建/编辑页区域 1、2 一致，但全部为已落库数据；组合预览列表只显示已存在组合，不显示“新增”标记，只读。

## 四、接口清单

| 归属 | 接口 | 说明 |
|---|---|---|
| 第一部分 | `GET /admin/api/material/category/list` | 素材品类下拉：`status=1`，读取 `material_category` |
| 第一部分 | 素材分类管理读写接口 | 读取不限；create/batchCreate/update/delete 及类型调整逐请求校验独立 Apollo 白名单，delete 为逻辑停用 |
| 第一部分 | 素材标签全局列表/创建接口 | 不按素材品类过滤，创建时填写 code/name，来源固定运营 |
| 第一部分 | 素材模板创建/更新请求 | 每条新素材提交 `materialCategoryCode`、`tagCodes`；已有素材不接受变更 |
| 第二部分 | `POST /admin/api/material/combination/stability/batch` | 组合稳定性批量查询 |

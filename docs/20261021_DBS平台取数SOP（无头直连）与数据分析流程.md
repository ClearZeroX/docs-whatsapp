## 2. 取数方案演进（为什么是现在这个做法）

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A 页面操作 | DOM 设值 SQL → 点执行 → 读 bootstrap-table | 淘汰。每步固定等待、多轮往返，慢 |
| B 页面内 fetch | 在已登录标签页里 `fetch('/query/')` | 可用但脆。标签页被关就断 |
| **C 无头直连（当前）** | 本地 Python 读 Chrome cookie + `requests` 直接 POST | **采用。不开浏览器页面，单次 < 1s** |

方案 C 能成立的关键：会话 `sessionid` 是 httpOnly，页面 JS 读不到；但 `browser_cookie3` 可以直接读 Chrome 本地 cookie 数据库（macOS 走 Keychain 解密），把 httpOnly cookie 也取出来。

```python
import dbs_query as d

session = d.build_session()

# 单页
res = d.query(session, "select * from tag limit 50;")
# -> {columns, rows, sql, query_time_ms, elapsed_ms}

# id 游标翻页取全量（升序 / 降序）
res = d.query_all(session, "tag", ascending=False, max_rows=100)
# -> {columns, rows}

# 带过滤条件
res = d.query_all(session, "tag", where="category_id = 4 and status = 1", max_rows=200)
```

## 4. 分页规则（硬约束，不得违反）

1. **单页最多 50 条**。`query()` 内部已强制 `min(limit, 50)`。
2. **深分页禁止用 MySQL 的 `LIMIT offset, N`**，一律用 id 游标：
   - 倒序：`where id < lastId order by id desc limit 50`
   - 正序：`where id > lastId order by id asc limit 50`
3. 游标必须与排序键一致，否则会漏行/重复。
4. 每批之间默认停 300ms（`interval=0.3`）防限流。
5. 返回行数 < 50 即视为最后一页。

`query_all()` 已实现上述规则，优先用它，不要手写翻页。

## 5. 字段解析注意事项

- **毫秒时间戳**：`create_time` / `update_time` / `ctime` / `utime` 等常见为 13 位毫秒值，需除以 1000 转 Asia/Shanghai。
- **JSON 字符串字段**：如 `rule_content` 是多语言 JSON（`en_US` / `zh_CN` / `id`），取回后按字符串处理，用时再 `json.loads`。
- **NULL 与空串**：两者业务含义不同（如 `ai_demo_level` 常为空串），报表中需区分展示。
- **枚举值**：纯大写/下划线命名（`MATERIAL`、`CUSTOMER_NEW` 等）。

## 6. 标准作业流程

1. **探规模**：先 `select count(*) from <table>;`，确认总量与取数轮次。
2. **取数**：`query_all(session, table, ascending=..., max_rows=N)`，按 50/批推进。
3. **落盘**：JSON（原始，`ensure_ascii=False`、`indent=2`）+ CSV（`utf-8-sig`，Excel 可直接开）。存放于 `analysis/<table>/`。
4. **校验**：行数是否符合预期、id 是否重复、关键字段是否为空、时间区间是否合理。大表可做行级指纹（长度 + 滚动哈希）比对。
5. **分析**：枚举分布 → 交叉表 → 数值分布 → 内容长度/关键词 → 异常与不一致。
6. **出文档**：MD 放 `trae-docs/`，命名 `YYYYMMDD_描述.md`；图表放 `analysis/<table>/charts/`，用相对路径引用。

## 7. 失败排查速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 返回 HTML 而不是 JSON | 登录态失效（302 回 `/login/`） | 浏览器重新登录一次，重跑脚本 |
| 请求仍回登录页但 cookie 有值 | Chrome 里有**两个 sessionid**，`path=/login` 那个无效 | 只取 `path=/` 且 `expires` 不为空的那个 |
| `No sessionid cookie found` | 从未在该浏览器登录过，或换了浏览器 | 先登录一次 |
| Keychain 弹窗被拒 | `browser_cookie3` 无法解密 cookie | 允许访问，或重新登录 |
| `Tab xxx does not exist` | 旧方案依赖的标签页被关闭 | 改用无头方案（本 SOP） |
| 结果被截断 | 一次取数超过 50 条 | 改用 `query_all` 游标翻页 |

## 8. 安全红线

- **只读**：仅允许 SELECT / COUNT / EXPLAIN，绝不执行 DDL/DML。
- **必带条件**：大表查询加时间窗或 id 范围，避免全表扫描拖垮平台。
- **先 COUNT 后取明细**，避免无界拉取。
- **PII 脱敏**：手机号、openid、姓名等敏感字段必须脱敏后再写入文档。
- **不入 git**：脚本与取数结果全部留在本地目录。

# LTO 合丢内容与适配逻辑说明

## 背景

- 原始 LTO 功能提交：`fb658193e feat: add limited-time offer support to template messages`
- `test3` 合入 `feature/2026-0910/phone-layer-tier-experiment` 时，合并提交 `c00f895d6` 解决 `CreateTemplateForLevelJobService.java` 冲突后，采用了缺少 LTO 逻辑的版本。
- 结果是 LTO 素材组合虽然在数据库中正常存在，但生成的子模板没有 `LIMITED_TIME_OFFER` 组件，也没有保存 LTO 素材关系。
- 当前修复分支为 `feature/zlc/0904-limited-time-offer`，修复提交为 `6173526e6 feat(whatsapp): support limited time offer template creation - fix merge`。

涉及文件：

```text
whatsapp-crm-data/src/main/java/com/opay/occ/whatsapp/data/xxljob/CreateTemplateForLevelJobService.java
```

# 一、合并丢失的原始 LTO 逻辑

这部分是原始 LTO 功能中已经有、但在 `test3` 冲突解决时被合丢的内容。

## 1. 丢失读取 LTO 素材 ID

原始逻辑需要在读取 header/body/footer/button 后，继续读取 LTO 素材 ID：

```java
String ltoMaterialId = messageMaterialCombination.getLimitedTimeOfferMaterialId();
MessageMaterial limitedTimeOffer = StringUtils.isBlank(ltoMaterialId)
        ? null : messageMaterialService.queryById(ltoMaterialId);
```

作用：

- 从素材组合中读取 `limitedTimeOfferMaterialId`
- 根据 ID 查询 Mongo 中的 LTO 素材
- 后续用于模板组件组装和素材关系保存

合丢后的版本只读取了：

```text
headerMaterialId
bodyMaterialId
footerMaterialId
buttonsMaterialId
```

没有读取 `limitedTimeOfferMaterialId`，所以后续所有 LTO 逻辑都无法执行。

## 2. 丢失将 LTO 素材传入模板组装方法

原始逻辑：

```java
MessageTemplate messageTemplate = assembleTemplate(
        header,
        body,
        footer,
        button,
        limitedTimeOffer,
        carouselBody,
        carouselCards,
        materialGroup,
        messageMaterialCombination.getId(),
        scenario,
        messageMaterialCombination.getMaterialTemplateType()
);
```

合丢后的版本：

```java
MessageTemplate messageTemplate = assembleTemplate(
        header,
        body,
        footer,
        button,
        materialGroup,
        messageMaterialCombination.getId(),
        scenario,
        experimentTier
);
```

问题：

- `assembleTemplate` 没有收到 `limitedTimeOffer`
- 后续组件组装时自然无法生成 `LIMITED_TIME_OFFER`

当前修复后保留了 `test3` 上新增的 `experimentTier`、`targetTemplateType` 等参数，同时把 `limitedTimeOffer` 加回方法链路。

## 3. 丢失 `assembleTemplate` 方法签名中的 LTO 参数

原始方法签名包含：

```java
private MessageTemplate assembleTemplate(
        MessageMaterial header,
        MessageMaterial body,
        MessageMaterial footer,
        MessageMaterial buttons,
        MessageMaterial limitedTimeOffer,
        MessageMaterial carouselBody,
        List<MessageCard> carouselCards,
        MessageMaterialGroup materialGroup,
        Long materialCombinationId,
        ScenarioEnum scenario,
        String combinationType
) {
```

合丢后的方法签名中没有：

```java
MessageMaterial limitedTimeOffer
```

因此整个模板组装链路中缺少 LTO 素材对象。

## 4. 丢失 LTO 强制 MARKETING 的类型兜底

原始逻辑中，`assembleTemplate` 有如下判断：

```java
if (MaterialTemplateTypeEnum.CAROUSEL.getCode().equals(combinationType)
        || MaterialTemplateTypeEnum.LTO.getCode().equals(combinationType)) {
    messageTemplate.setTemplateType(MessageTemplateTypeEnum.MARKETING.getCode());
    log.info("assembleTemplate {} combination, templateType fixed to: {}",
            combinationType,
            MessageTemplateTypeEnum.MARKETING.getCode());
}
```

作用：

- `CAROUSEL` 强制生成 `MARKETING`
- `LTO` 也强制生成 `MARKETING`

合丢后，该方法只剩普通场景判断：

```java
if (scenario == ScenarioEnum.UTILITY_FIRST
        && MessageTemplateTypeEnum.MARKETING.getCode().equals(materialGroup.getTemplateType())) {
    messageTemplate.setTemplateType(MessageTemplateTypeEnum.UTILITY.getCode());
} else {
    messageTemplate.setTemplateType(materialGroup.getTemplateType());
}
```

这会导致 `LTO` 在某些场景下可能被识别为其他类型，失去营销模板语义。

## 5. 丢失 `getTemplateComponents` 方法签名中的 LTO 参数

原始签名：

```java
private String getTemplateComponents(
        MessageMaterial header,
        MessageMaterial body,
        MessageMaterial footer,
        MessageMaterial buttons,
        MessageMaterial limitedTimeOffer,
        MessageMaterial carouselBody,
        List<MessageCard> carouselCards
) {
```

合丢后的签名：

```java
private String getTemplateComponents(
        MessageMaterial header,
        MessageMaterial body,
        MessageMaterial footer,
        MessageMaterial buttons
) {
```

由于方法签名中没有 `limitedTimeOffer`，组件组装方法无法处理 LTO。

## 6. 丢失将 LTO element 加入 components

这是最直接的丢失点。

原始逻辑：

```java
List<OpayTemplateComponent> componentList = Lists.newArrayListWithCapacity(5);

if (limitedTimeOffer != null
        && limitedTimeOffer.getElement() != null
        && OpayTemplateComponent.TemplateCommentTypeEnum.LIMITED_TIME_OFFER
                == limitedTimeOffer.getElement().getType()) {
    componentList.add(limitedTimeOffer.getElement());
}

if (header != null && !StringUtils.equals(header.getSubType(), "NONE")) {
    componentList.add(header.getElement());
}

if (body != null && !StringUtils.equals(body.getSubType(), "NONE")) {
    componentList.add(body.getElement());
}

if (footer != null && !StringUtils.equals(footer.getSubType(), "NONE")) {
    componentList.add(footer.getElement());
}

if (buttons != null && !StringUtils.equals(buttons.getSubType(), "NONE")) {
    componentList.add(buttons.getElement());
}
```

合丢后的逻辑：

```java
List<OpayTemplateComponent> componentList = Lists.newArrayListWithCapacity(4);

if (header != null && !StringUtils.equals(header.getSubType(), "NONE")) {
    componentList.add(header.getElement());
}

if (body != null && !StringUtils.equals(body.getSubType(), "NONE")) {
    componentList.add(body.getElement());
}

if (footer != null && !StringUtils.equals(footer.getSubType(), "NONE")) {
    componentList.add(footer.getElement());
}

if (buttons != null && !StringUtils.equals(buttons.getSubType(), "NONE")) {
    componentList.add(buttons.getElement());
}
```

导致最终模板的 `components` 只可能包含：

```text
HEADER
BODY
FOOTER
BUTTONS
```

不会包含：

```text
LIMITED_TIME_OFFER
```

## 7. 丢失保存 LTO 素材关系

原始逻辑在模板保存后会保存素材与模板的关系：

```java
saveMaterialTemplate(
        materialGroupId,
        messageTemplate,
        limitedTimeOffer,
        OpayTemplateComponent.TemplateCommentTypeEnum.LIMITED_TIME_OFFER
);
```

合丢后只剩下：

```java
saveMaterialTemplate(materialGroupId, messageTemplate, header,
        OpayTemplateComponent.TemplateCommentTypeEnum.HEADER);

saveMaterialTemplate(materialGroupId, messageTemplate, body,
        OpayTemplateComponent.TemplateCommentTypeEnum.BODY);

saveMaterialTemplate(materialGroupId, messageTemplate, footer,
        OpayTemplateComponent.TemplateCommentTypeEnum.FOOTER);

saveMaterialTemplate(materialGroupId, messageTemplate, button,
        OpayTemplateComponent.TemplateCommentTypeEnum.BUTTONS);
```

因此 `message_material_template` 中缺少类型为：

```text
LIMITED_TIME_OFFER
```

的记录。

## 8. 丢失逻辑汇总

| 序号 | 丢失点 | 影响 |
|---|---|---|
| 1 | 未读取 `limitedTimeOfferMaterialId` | 无法找到 LTO 素材 |
| 2 | 未查询 `MessageMaterial` | 后续组装无数据来源 |
| 3 | 未传入 `assembleTemplate` | 模板组装链路断裂 |
| 4 | `assembleTemplate` 签名缺少 LTO 参数 | 方法无法承接 LTO |
| 5 | 未保留 LTO 强制 `MARKETING` | 模板类型可能被改写 |
| 6 | `getTemplateComponents` 签名缺少 LTO 参数 | 组件组装无法识别 LTO |
| 7 | 未添加 `LIMITED_TIME_OFFER` component | 模板 components 缺少 LTO |
| 8 | 未保存 LTO 素材关系 | 关系表缺少 `LIMITED_TIME_OFFER` 记录 |

# 二、为兼容 test3 新增的适配逻辑

这部分不是原始 LTO 提交 `fb658193e` 中已有的内容，而是为了兼容 `test3` 后续新增的自动 Utility 逻辑而补充的适配。

## 1. `resolveMaterialTemplateType` 中强制 LTO 返回 MARKETING

新增逻辑：

```java
if (MaterialTemplateTypeEnum.CAROUSEL.getCode()
        .equals(materialCombination.getMaterialTemplateType())
        || MaterialTemplateTypeEnum.LTO.getCode()
        .equals(materialCombination.getMaterialTemplateType())) {
    return MessageTemplateTypeEnum.MARKETING.getCode();
}
```

### 背景

`test3` 后续新增了自动创建 Utility 模板的逻辑。

在 `DEFAULT` 或 `RECENT_MINUTES` 场景下，某些 `MARKETING` 素材组合可能被自动改成生成 `UTILITY` 模板。

但 LTO 是限时优惠模板，业务上属于营销模板，不应该被自动 Utility 逻辑改写。

### 作用

- `CAROUSEL` 强制返回 `MARKETING`
- `LTO` 强制返回 `MARKETING`
- 保证 LTO 在最终类型决策阶段不被自动 Utility 逻辑影响

## 2. `isAutoUtilityEligible` 中排除 LTO

新增逻辑：

```java
&& !MaterialTemplateTypeEnum.LTO.getCode()
        .equals(materialCombination.getMaterialTemplateType())
```

完整判断中，`LTO` 与 `CAROUSEL` 一样被排除：

```java
!MaterialTemplateTypeEnum.CAROUSEL.getCode()
        .equals(materialCombination.getMaterialTemplateType())
&& !MaterialTemplateTypeEnum.LTO.getCode()
        .equals(materialCombination.getMaterialTemplateType())
```

### 背景

`isAutoUtilityEligible` 用于判断当前素材组合是否允许进入自动 Utility 生成流程。

如果 LTO 不排除，在如下条件下会被误判为可以自动生成 Utility：

```text
素材模板类型：MARKETING
素材组合类型：LTO
当前场景：DEFAULT 或 RECENT_MINUTES
自动 Utility 开关：开启
素材模板在白名单内
```

### 作用

- LTO 不参与自动 Utility 流程
- LTO 不进入 `utilityAttemptCount` 统计
- 避免 LTO 被错误生成为 `UTILITY`
- 保持 LTO 的营销模板语义

## 3. 适配逻辑与原始逻辑的关系

| 类型 | 是否属于原始 LTO 功能 | 是否属于 test3 新增适配 | 目的 |
|---|---|---|---|
| 读取 `limitedTimeOfferMaterialId` | 是 | 否 | 恢复 LTO 数据读取 |
| 查询 `MessageMaterial` | 是 | 否 | 获取 LTO 素材对象 |
| 传入 `assembleTemplate` | 是 | 否 | 恢复组装链路 |
| `getTemplateComponents` 添加 LTO element | 是 | 否 | 恢复模板 components |
| 保存 `LIMITED_TIME_OFFER` 关系 | 是 | 否 | 恢复素材关系 |
| `resolveMaterialTemplateType` 强制 LTO 为 MARKETING | 否 | 是 | 防止自动 Utility 改写类型 |
| `isAutoUtilityEligible` 排除 LTO | 否 | 是 | 防止 LTO 进入自动 Utility 流程 |

## 4. 修复后的整体流程

修复后，LTO 素材组合的生成链路为：

```text
读取素材组合
    ↓
识别 materialTemplateType = LTO
    ↓
读取 limitedTimeOfferMaterialId
    ↓
查询 LTO MessageMaterial
    ↓
resolveMaterialTemplateType 强制返回 MARKETING
    ↓
assembleTemplate 强制设置 MARKETING
    ↓
getTemplateComponents 添加 LIMITED_TIME_OFFER
    ↓
保存 MessageTemplate
    ↓
saveMaterialTemplate 保存 LIMITED_TIME_OFFER 关系
```

# 素材品类、标签、组合稳定性与页面优化一期技术方案

> 日期：2026-11-06 ｜ 状态：技术方案修订稿 ｜ 范围：后端、前端、MySQL、Mongo、任务、迁移与测试

## 1. 范围与统一口径

本方案依据《2026-10-21-品类标签组合稳定性与页面优化一期需求文档》，按三部分实施：

1. 品类、标签支持；
2. 组合维度稳定性评级；
3. 页面功能优化。

统一口径：`message_material_group` 为**素材模板**，`message_material_combination` 为**素材组合**，Mongo `message_material` 为**素材**。本期不批量回填历史素材与历史组合；LTO 与轮播素材暂不支持品类和打标。

## 2. 第一部分：品类、标签支持

本次在一期方案基础上调整标签模型。旧表保持不变，新素材品类和标签链路直接使用以下新表，不读取旧表，不回填旧数据，不提供新旧表兼容逻辑：

```text
material_category
material_tag
material_category_tag_relation
material_tag_rule
```

旧表继续保留，但不参与本次素材品类、素材标签和 AI 提取链路：

```text
category
tag
tag_relation
tag_rule
```

### 2.1 数据模型

#### 2.1.1 MySQL 新表

设计约束：

- 新表均为素材业务专用表，因此不保留原标签表的 `type` 字段，也不增加 `category_type` 字段。
- `material_category.code` 和 `material_tag.code` 都是稳定英文编码；页面和接口同时返回 `code`、`name`，前端按当前语言显示：中文显示 `name`，英文显示 `code`。
- `material_tag` 是全局标签字典，不再保存 `category_id` 或 `category_name`。
- 标签 code 和品类 code 统一使用小写英文、数字和横线，长度 1～64，必须以小写英文开头。标签 code 在同一规则基础上额外允许冒号，例如 `disguise-system:notice`；品类 code 不允许冒号。
- `material_tag.code` 和 `material_tag.name` 均全局唯一，避免同一标签出现多个机器标识或多个中文定义。
- 关系表不使用标签表主键 `tag_id`，统一使用 `material_tag_code`；品类也统一使用 `material_category_code`，便于 SQL 查询、数据分析和页面接口直接阅读。
- 关系表不建立业务唯一索引。同一素材可以同时存在运营关系、AI 正式关系和 AI 候选关系；AI 重提由业务逻辑按素材和提取批次替换 AI 来源关系。
- `material_category_tag_relation.material_category_code` 非空。运营关系写入素材当前品类；AI 关系写入 AI 最终判断的品类。该字段表示这条关系携带的品类上下文，不表示标签固定属于该品类。
- `accuracy_score` 默认 5，允许值为 1、2、3、4、5。它表示标签在具体素材上的识别准确度，只对 `source_type=0` 的 AI 关系参与准确率统计；运营手动绑定关系默认写入 5，但不参与 AI 准确率统计。
- 不建立规则与标签的直接关系表。规则只绑定素材品类，规则页面不展示“该品类下的全部标签”。

差异分析统计表继续保留，但字段语义调整为“素材实际品类”和“标签关系携带品类”的比较：

#### 2.1.2 Mongo `message_material`

新增顶层字段：

```text
material_category_code
```

普通素材创建时必须写入启用的素材品类 code；创建后不允许修改。LTO 和轮播素材本期仍不支持品类和打标，因此不写该字段，也不写入新关系表。

#### 2.1.3 请求/响应 DTO

- `MessageMaterialReqDTO` 增加 `materialCategoryCode`、`tagCodes`；新建普通素材必须填写品类，标签可为空。
- `TagExtractResultDTO` 改为素材级返回 `materialCategoryCode`、`materialCategoryName`，标签项返回 `tagCode`、`tagName`、`confidence`。
- 分类、标签、规则及素材标签关系响应均同时返回 code 和 name；前端按语言环境选择展示字段。
- `MessageMaterialCombinationPageReqDTO` 增加 `materialId`，继续支持按素材筛选组合。

### 2.2 素材品类和标签编码管理

#### 2.2.1 编码规则

- 品类 code：`^[a-z][a-z0-9-]{0,63}$`，例如 `repay-1-day`。
- 标签 code：`^[a-z][a-z0-9-:]{0,63}$`，例如 `disguise-system:notice`。
- code 长度均为 1～64；创建后不允许修改；code 和 name 均需做唯一性校验。
- 当前代码中品类的 `lower_snake_case` 校验需要改为横线规则；旧标签名称校验不直接复用，新增素材标签 code 使用上述标签专用规则。

#### 2.2.2 AI 品类选择逻辑

AI 对每个素材选择素材品类时保留现有三段式逻辑：

1. 优先判断运营已经绑定的 `materialCategoryCode` 是否符合素材内容；符合时沿用运营品类。
2. 如果运营品类不符合或素材没有运营品类，从 Prompt 提供的全部有效 `material_category` 中选择最匹配的已有品类。
3. 只有运营品类不符合且已有品类均不匹配时，才允许创建新的素材品类。

新建品类时返回 `materialCategoryCode` 和 `materialCategoryName`，后端校验 code 格式、长度、唯一性和名称语义；命中已有品类时始终复用数据库中的 code/name，不覆盖已有名称。

品类列表的 Prompt 项保留未来扩展字段，但当前不提供品类下参考标签：

```json
{
  "materialCategoryCode": "repay-1-day",
  "materialCategoryName": "1天内还款",
  "exampleTags": []
}
```

标签示例单独以全局列表提供：

```json
{
  "tagCode": "disguise-system:notice",
  "tagName": "系统通知伪装",
  "aiDemoLevel": "good"
}
```

### 2.3 分类管理与差异分析

- 新品类和新标签均写入 `material_*` 新表；旧表不参与读取和写入。
- 素材品类管理仍保留白名单写权限和逻辑停用；停用品类不能新建素材或写入新关系。
- `MaterialCategoryTagDiffJob` 按最新成功 AI 提取批次比较 Mongo 素材的实际品类与 AI 关系携带品类，统计正式关系、候选关系、标签准确率和跨品类情况；不自动修改素材品类、不自动转正候选关系。
- 统计任务按唯一键覆盖当天同一统计维度，所有 `IN` 查询按不超过 500 条分批执行。

### 2.4 素材保存与组合校验

- 普通新素材必须填写启用的 `materialCategoryCode`；`tagCodes` 中的标签必须存在、启用且为素材标签。
- 操作员保存标签关系时，将素材实际品类 code 写入 `material_category_tag_relation.material_category_code`，`source_type=2`、`binding_status=1`、`accuracy_score=5`、`extract_log_id=0`。
- 不再校验标签是否属于当前素材品类，因为标签已经全局化。
- 组合品类统一从成员素材自身的 `material_category_code` 收口；真实品类去重后不超过一个才允许生成，组合快照继续写入 `message_material_combination.material_category_code`。
- 组合生成、人工组合、编辑新增、AI 备份和预览继续调用同一套品类校验；LTO、轮播本期不参与新标签关系。

### 2.5 AI 标签提取改造

- 当前覆盖范围仍为 HEADER（TEXT/IMAGE）与 BODY；LTO、轮播本期不参与 AI 打标。
- Prompt 输出素材级 `materialCategoryCode/materialCategoryName`，标签级 `tagCode/tagName/confidence`。
- `TagExtractServiceImpl` 根据标签 code 全局查找或创建 `material_tag`，不再按分类查询标签。
- AI 写入关系时，将 AI 最终品类写入 `material_category_code`，`source_type=0`；AI 品类与 Mongo 素材实际品类相同时写正式关系，否则写候选关系。
- AI 重新提取只替换目标素材的 AI 来源关系，保留运营关系和其他来源关系；关系表不依赖唯一键实现 MQ 幂等。
- AI 返回标签 code 时遵循 `material_tag` 现有定义：已存在 code 直接复用，已有标签的中文 name 不被模型返回值覆盖；不存在时才创建新标签。

## 3. 第二部分：组合维度稳定性评级

### 3.1 计算链路

`MaterialCombinationStabilityService` 参照 `MaterialGroupStabilityStatsService`：

```text
message_material_combination.id
  → message_template.material_combination_id
  → message_template_waba.category
  → 当前可用 / 历史 UTILITY 占比
  → 现有 Stability 规则（普通组 / AI 备份组按所属素材模板 source_type 选择）
  → S > A > B > C > D
```

不使用 request、sent、delivered、read。

### 3.2 缓存与 Job

- Redis key：`material_combination_stability:{combinationId}`，保存等级、原因及当前/历史 utility 数值。
- `RefreshMaterialCombinationStabilityCacheJobService`：覆盖近期更新、有模板变更、AI 备份相关组合；批量查询、IN ≤500、分批写缓存。

### 3.3 接口与展示

- `POST /admin/api/material/combination/stability/batch`：入参组合 ID 数组，出参按 ID 映射评级对象；组合列表批量补充。
- 前端组合列表统一增加稳定性列：S/A/B/C/D，查看模式隐藏写操作；“查看关联组合”浮层按素材 ID 分页查询组合并补齐评级。

```json
  "readRate": null, "avg7dDelivered": null, "createTime": null
}
```

响应追加按类型摘要：

```json
"typeSummary": {
  "NORMAL":  {"hasMaterials": true,  "combinationCount": 2, "newCount": 1, "blocked": false, "blockedReason": ""},
  "LTO":     {"hasMaterials": true,  "combinationCount": 0, "newCount": 0, "blocked": true,  "blockedReason": "缺少 IMAGE/VIDEO 头部素材"},
  "CAROUSEL":{"hasMaterials": false, "combinationCount": 0, "newCount": 0, "blocked": false, "blockedReason": ""}
}
```

`hasMaterials` 最小要素集：NORMAL=存在 HEADER/BODY/FOOTER/BUTTONS 任一素材；LTO=存在限时优惠素材；CAROUSEL=存在轮播内容素材或轮播卡片组。`blocked = hasMaterials=true 且 combinationCount=0`；`blockedReason` 由后端按校验规则产出（如 LTO 缺符合 HEADER、按钮不满足；轮播缺正文/卡片）。

规则：

- NORMAL：有效 HEADER × BODY × FOOTER × 按钮，空集合以空占位；停用/删除成员不参与。
- LTO：仅 IMAGE/VIDEO HEADER 参与；**无符合 HEADER 时不生成 LTO 组合（后端生成逻辑同步修改）**；校验按钮搭配，失败返回提示（如“请先添加对应按钮后再预览 LTO 素材”）。
- CAROUSEL：轮播 BODY × 卡片组；按 cardIds 展开。
- 与已有组合按 `header|lto|body|footer|buttons`（轮播按 body+有序卡片）去重，命中的已有行返回 `exists=true`。
- 前端也会对人工组合逐行调用同一接口（或提交人工行集合）得到对应校验结果。

### 4.6 素材【预览】按钮与浮层

- 每条素材卡片【预览】：请求 preview（编辑态含已存在组合 + 虚拟键新增素材，带 `memberFilter=tempKey/素材ID`），成功后刷新组合方式区域，并浮层展示含该素材的组合（同列、同分页）。
- 轮播卡片组的【预览】同样支持：通过卡片组虚拟键/卡片 ID 集合过滤。
- 浮层点击组合预览列 → 手机模拟器弹窗，与素材组合页一致。

### 4.7 素材模板查看页

- 组合方式区域只显示已落库组合（`/material/combination/page?materialGroupId=`），只读、无“新增”标记、无组合品类冲突提示；素材卡片与组件选择区只读。

### 4.8 提交前组合确认浮层

- 点【创建/更新】且前端必填校验通过后，先请求 preview（不带分页过滤，或按分组分页），弹出确认浮层。
- 按 `经典模板 / LTO 模板 / 轮播模板` 纵向分段，段标题 `共 X 个（新增 Y）`，默认全部展开；类型数量为 0 显示空态提示；行字段与组合预览列表一致。
- `已存在` 行不计入新增；【取消】关闭浮层回到编辑页不保存；【确认提交】才调用素材模板创建/更新接口。
- 后端通过 `typeSummary` 返回各类型总数与新增数；前端不再自行按组合类型统计。
- 右侧固定说明区保留。

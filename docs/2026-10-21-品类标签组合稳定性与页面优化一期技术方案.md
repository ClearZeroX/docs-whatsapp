# 素材品类、标签、组合稳定性与页面优化一期技术方案

> 日期：2026-10-21 ｜ 状态：技术方案讨论稿 ｜ 范围：后端、前端、MySQL、Mongo、任务、迁移与测试

## 1. 范围与统一口径

本方案依据《2026-10-21-品类标签组合稳定性与页面优化一期需求文档》，按三部分实施：

1. 品类、标签支持；
2. 组合维度稳定性评级；
3. 页面功能优化。

统一口径：`message_material_group` 为**素材模板**，`message_material_combination` 为**素材组合**，Mongo `message_material` 为**素材**。本期不批量回填历史素材与历史组合；LTO 与轮播素材暂不支持品类和打标。

## 2. 第一部分：品类、标签支持

### 2.1 数据模型

> 仓库内可找到 `message_material_combination` 早期建表脚本，但 `category/tag/tag_relation` 的当前线上完整 DDL 不在仓库中；执行前须核对 `SHOW CREATE TABLE`、字符集、索引及数据量。



#### 2.1.1 MySQL

```sql
ALTER TABLE `category`
  ADD COLUMN `code` varchar(64) NOT NULL DEFAULT '' COMMENT 'Stable category code',
  ADD COLUMN `source_type` tinyint(4) NOT NULL DEFAULT '0' COMMENT '0=AI, 1=admin, 2=operations',
  ADD COLUMN `category_type` varchar(32) NOT NULL DEFAULT 'TAG_ONLY' COMMENT 'BUSINESS_MATERIAL or TAG_ONLY';

ALTER TABLE `tag`
  ADD COLUMN `source_type` tinyint(4) NOT NULL DEFAULT '0' COMMENT 'Tag definition source: 0=AI, 1=admin, 2=operations';

ALTER TABLE `tag_relation`
  ADD COLUMN `source_type` tinyint(4) NOT NULL DEFAULT '0' COMMENT 'Tag binding source: 0=AI, 1=admin/code, 2=operations',
  ADD COLUMN `binding_status` tinyint(4) NOT NULL DEFAULT '1' COMMENT '0=candidate, 1=effective',
  ADD COLUMN `extract_log_id` bigint(20) NOT NULL DEFAULT '0' COMMENT 'AI extract log ID; 0 for other sources';

ALTER TABLE `message_material_combination`
  ADD COLUMN `material_category_code` varchar(64) NOT NULL DEFAULT 'UNCATEGORIZED' COMMENT 'Resolved member material category';
```

索引：

```sql
-- 存量 category 补齐 code 并查重后再执行：
ALTER TABLE `category`
  ADD UNIQUE KEY `uk_category_code` (`code`),
  ADD KEY `idx_type_status_sort` (`category_type`,`status`,`sort`);

ALTER TABLE `tag`
  ADD KEY `idx_category_type_status` (`category_id`,`type`,`status`);

ALTER TABLE `tag_relation`
  ADD KEY `idx_entity_status` (`entity_type`,`entity_id`,`binding_status`),
  ADD KEY `idx_extract_log_id` (`extract_log_id`);

ALTER TABLE `message_material_combination`
  ADD KEY `idx_material_category_code` (`material_category_code`);
```

说明：

- `source_type` 历史默认 `0` 基于“历史数据由 AI 产生”的已确认口径；上线前仍需核对真实库，发现例外应记录并修正来源，不能静默覆盖。
- `tag_relation` **不建** `(entity_type, entity_id, tag_id, source_type)` 唯一索引：同一素材同一标签可保存多条记录，AI 与运营来源各自独立保留。
- `binding_status` 仅表达 AI 判断为正式或候选，不参与唯一性判定。

新增差异分析统计表（遵循 NOT NULL 有默认值、create/update_time、create_time 索引规范）：

```sql
CREATE TABLE `material_category_tag_diff_stat` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT COMMENT 'Primary key',
  `stat_date` varchar(10) NOT NULL DEFAULT '' COMMENT 'Analysis date yyyy-MM-dd',
  `material_category_code` varchar(64) NOT NULL DEFAULT 'UNCATEGORIZED' COMMENT 'Material category',
  `ai_category_code` varchar(64) NOT NULL DEFAULT '' COMMENT 'Category suggested by AI',
  `diff_type` varchar(32) NOT NULL DEFAULT '' COMMENT 'SAME_TAG, SAME_CATEGORY, CROSS_CATEGORY, AI_NEW_CATEGORY, LEGACY_UNCATEGORIZED',
  `material_count` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Affected material count in this dimension',
  `relation_count` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Raw tag relation count in this dimension',
  `sample_material_ids` text COMMENT 'Bounded JSON array of sample Mongo IDs',
  `create_time` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Creation time',
  `update_time` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Update time',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_stat_category_diff` (`stat_date`,`material_category_code`,`ai_category_code`,`diff_type`),
  KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Daily material category vs AI tag difference statistics';
```

`relation_count` 统计原始关联行数，`material_count` 仅表覆盖素材数；Job 重跑按 `uk_stat_category_diff` 覆盖，不删除或合并 `tag_relation`。

#### 2.1.2 Mongo `message_material`

新增**顶层**字段：

```text
material_category_code
```

读取规则：字段缺失按 `UNCATEGORIZED` 返回；新普通素材写入业务 code；LTO、轮播素材本期不写该字段。更新链路禁止修改品类；AI 备份复制主素材品类。

#### 2.1.3 请求/响应 DTO

- `MessageMaterialReqDTO` 增 `materialCategoryCode`、`tagIds`（新建必填品类可空标签，既有素材不接受变更）。
- `TagExtractResultDTO.TagInfo` 增 `categoryCode`。
- `MessageMaterialCombinationPageReqDTO` 增 `materialId`（按素材筛选组合，覆盖 header/body/footer/buttons/carouselBody/limitedTimeOffer 六个槽位）。
- 分类管理响应增 `code/sourceType/categoryType`。

### 2.2 分类编码与分类管理

#### 2.2.1 code 生成规则

- 管理页录入：白名单管理员填稳定 code。
- AI 新分类：模型返回 `categoryName` 与语义化 `categoryCode`（`lower_snake_case`）。后端：
  1. 按名称查已有分类，命中则复用数据库 `id/code`；
  2. 未命中校验 code 格式 `^[a-z][a-z0-9_]*$`、长度 1~64、非保留值、语义与名称一致、code 未被占用；
  3. 校验失败不落库，该条结果记录失败并重试/人工处理。
- 存量分类回填 `AI_LEGACY_{id}` 后建唯一索引。
  - 说明：`category.code` 为新增列，历史行的默认值为空字符串；此时不能直接建唯一索引，否则旧行会因空值重复而失败，也无法暴露真实冲突。上线迁移时先对已有分类逐行生成系统兼容编码 `AI_LEGACY_{行ID}`（用主键保证唯一），全表 code 非空且无重复并核查后，再创建 `uk_category_code` 唯一索引。
  - 边界：`AI_LEGACY_{id}` 是存量兼容标识，不是业务语义命名，也不作为未来新数据的命名规则；AI 新分类仍使用语义化 `categoryCode`，管理页新建由白名单管理员录入业务 code。
  - 后续如需把某存量编码升级为业务语义 code，由于 code 一经被素材或组合引用不可直接修改，须单独评估引用迁移方案，不能直接改原记录。

#### 2.2.2 分类管理页面

- 白名单配置：Apollo key `material.category.write-whitelist`（代码 `@Value("${material.category.write-whitelist:}")` 注入），逗号分隔 SSO 用户名（`SsoUserVO#getName()`，不含 `@域名`）。修改后先调 `GET /admin/api/material/ai/category/myWritePermission` 验证是否热生效，未生效需重启 api 实例。
- 未配置、为空或用户名不匹配时写接口一律拒绝（返回 `code=500`，`message=Category write permission denied`）；按完整用户名精确匹配（仅 trim），不用 `contains`。
- 写接口：现有 `/admin/api/material/ai/category/create|batchCreate|update|delete` 统一接入校验；`delete` 改为逻辑停用（`status=0`）。读取接口不进白名单。
- 分类调整类型时保留原 `source_type=0`，记录操作人、前后值；审计优先复用 `data_change_log`（新增数据类型 CATEGORY 或扩展 sourceType），实施时确认枚举扩展方式。

### 2.3 分类 Job 与差异分析

- `MaterialCategoryTagDiffJob`：按最近一次成功 AI 提取批次比较素材品类、运营正式标签、AI 正式/候选标签，写入 `material_category_tag_diff_stat`；只产出证据，不自动改分类类型、不改素材品类、不转正候选。
- AI 按名称创建分类的幂等：并发同名请求须二次复查复用；code 冲突重试与人工处理。

### 2.4 素材保存与组合校验

- 素材模板创建/更新前校验：普通新素材品类必填且属于启用 `BUSINESS_MATERIAL` 分类；`tagIds` 存在、启用、属于当前素材品类；既有素材品类/标签变更直接报错。
- Mongo 写素材后建立 `clientMaterialKey -> ObjectId` 映射，再写运营 `tag_relation.source_type=2`。
- 组合品类统一收口服务 `MaterialCombinationCategoryService.validateAndResolve(List)`：收集成员素材、分批（≤500）查 Mongo 品类、忽略 `UNCATEGORIZED` 后真实品类去重 ≤1，写入 `material_category_code`；≥2 抛错。
- 落点：随机生成入口、人工组合构造、轮播/LTO 组合、编辑新增、AI 备份均调用同一收口；MySQL/Mongo 非同一事务的失败写入记录 Mongo ID 补偿。

### 2.5 AI 标签提取改造

- 当前仅覆盖 HEADER（TEXT/IMAGE）与 BODY；本期 LTO、轮播素材不参与打标。
- `MaterialAITagServiceImpl.OUTPUT_FORMAT` 增 `categoryCode`；`getOrCreate` 按上述语义化 code 规则落库。
- `TagExtractServiceImpl`：只替换目标素材 AI 来源关系（`source_type=0`），保留运营/其他来源；正式/候选写 `binding_status` 与 `extract_log_id`；MQ 重试幂等，失败不清空旧 AI 判断。

## 3. 第二部分：组合维度稳定性评级

### 3.1 计算链路

`MaterialCombinationStabilityService` 参照 `MaterialGroupStabilityStatsService`：

```text
message_material_combination.id
  → message_template.material_combination_id
  → message_template_waba.category
  → 当前可用 / 历史 UTILITY 占比
  → 现有 Stability 规则（普通组 / AI 备份组按所属素材模板 source_type 选择）
  → S > A > B > C > D
```

不使用 request、sent、delivered、read。

### 3.2 缓存与 Job

- Redis key：`material_combination_stability:{combinationId}`，保存等级、原因及当前/历史 utility 数值。
- `RefreshMaterialCombinationStabilityCacheJobService`：覆盖近期更新、有模板变更、AI 备份相关组合；批量查询、IN ≤500、分批写缓存。

### 3.3 接口与展示

- `POST /admin/api/material/combination/stability/batch`：入参组合 ID 数组，出参按 ID 映射评级对象；组合列表批量补充。
- 前端组合列表统一增加稳定性列：S/A/B/C/D，查看模式隐藏写操作；“查看关联组合”浮层按素材 ID 分页查询组合并补齐评级。

### 4.4 组合预览列表

- 后端组合预览接口本期实现：`POST /admin/api/material/combination/preview`。
- 列表列：`组合ID | 组合类型 | 是否存在 | 组合预览 | 组合状态 | 素材状态 | 品类 | 创建时间 | 已读率 | 近7日日均送达 | 覆盖泳道`；不展示素材模板名称与操作列。

- 新建行落库字段为空；冲突组合不展示。
- 数据口径：新增/编辑/查看均请求后端；未保存素材使用 `tempKey/clientMaterialKey` 虚拟键。

### 4.5 组合预览接口参数

请求：

```json
{
  "materialGroupId": "null 或已存在 ID",
  "combinationMode": "RANDOM",
  "current": 1,
  "size": 10,
  "materials": {
    "headerList": [{"id":"","tempKey":"h1","status":"ACTIVE","subType":"IMAGE","materialCategoryCode":"repay_1_day"}],
    "bodyList": [{"id":"","tempKey":"b1","status":"ACTIVE","materialCategoryCode":"repay_1_day"}],
    "footerList": [],
    "buttons": {"id":"","tempKey":"btn1","status":"ACTIVE"},
    "limitedTimeOfferList": [{"id":"","tempKey":"lto1","status":"ACTIVE"}],
    "carouselBodyList": [],
    "cardIds": [["88","87"]]
  }
}
```

响应元素：

```json
{
  "combinationId": "null 表示新增候选",
  "materialTemplateType": "NORMAL | LTO | CAROUSEL",
  "exists": "true 已存在 / false 新增",
  "materialCategoryCode": "repay_1_day 或 UNCATEGORIZED",
  "headerBrief": {}, "bodyBrief": {}, "footerBrief": {}, "buttonsBrief": {}, "ltoBrief": {}, "carouselCards": [],
  "status": "新建行为 null",
  "materialStatus": "新建行为 null",
  "readRate": null, "avg7dDelivered": null, "createTime": null
}
```

响应追加按类型摘要：

```json
"typeSummary": {
  "NORMAL":  {"hasMaterials": true,  "combinationCount": 2, "newCount": 1, "blocked": false, "blockedReason": ""},
  "LTO":     {"hasMaterials": true,  "combinationCount": 0, "newCount": 0, "blocked": true,  "blockedReason": "缺少 IMAGE/VIDEO 头部素材"},
  "CAROUSEL":{"hasMaterials": false, "combinationCount": 0, "newCount": 0, "blocked": false, "blockedReason": ""}
}
```

`hasMaterials` 最小要素集：NORMAL=存在 HEADER/BODY/FOOTER/BUTTONS 任一素材；LTO=存在限时优惠素材；CAROUSEL=存在轮播内容素材或轮播卡片组。`blocked = hasMaterials=true 且 combinationCount=0`；`blockedReason` 由后端按校验规则产出（如 LTO 缺符合 HEADER、按钮不满足；轮播缺正文/卡片）。

规则：

- NORMAL：有效 HEADER × BODY × FOOTER × 按钮，空集合以空占位；停用/删除成员不参与。
- LTO：仅 IMAGE/VIDEO HEADER 参与；**无符合 HEADER 时不生成 LTO 组合（后端生成逻辑同步修改）**；校验按钮搭配，失败返回提示（如“请先添加对应按钮后再预览 LTO 素材”）。
- CAROUSEL：轮播 BODY × 卡片组；按 cardIds 展开。
- 与已有组合按 `header|lto|body|footer|buttons`（轮播按 body+有序卡片）去重，命中的已有行返回 `exists=true`。
- 前端也会对人工组合逐行调用同一接口（或提交人工行集合）得到对应校验结果。

### 4.6 素材【预览】按钮与浮层

- 每条素材卡片【预览】：请求 preview（编辑态含已存在组合 + 虚拟键新增素材，带 `memberFilter=tempKey/素材ID`），成功后刷新组合方式区域，并浮层展示含该素材的组合（同列、同分页）。
- 轮播卡片组的【预览】同样支持：通过卡片组虚拟键/卡片 ID 集合过滤。
- 浮层点击组合预览列 → 手机模拟器弹窗，与素材组合页一致。

### 4.7 素材模板查看页

- 组合方式区域只显示已落库组合（`/material/combination/page?materialGroupId=`），只读、无“新增”标记、无组合品类冲突提示；素材卡片与组件选择区只读。

### 4.8 提交前组合确认浮层

- 点【创建/更新】且前端必填校验通过后，先请求 preview（不带分页过滤，或按分组分页），弹出确认浮层。
- 按 `经典模板 / LTO 模板 / 轮播模板` 纵向分段，段标题 `共 X 个（新增 Y）`，默认全部展开；类型数量为 0 显示空态提示；行字段与组合预览列表一致。
- `已存在` 行不计入新增；【取消】关闭浮层回到编辑页不保存；【确认提交】才调用素材模板创建/更新接口。
- 后端通过 `typeSummary` 返回各类型总数与新增数；前端不再自行按组合类型统计。
- 右侧固定说明区保留。

# AI 备用素材模版调整设计

## 1. 背景与目标

现有未上线方案以泳道为维度创建 AI 备用素材模版：`message_material_group` 记录 `ai_source_lane`，创建备用组时按 `sourceLane` 分组，每个泳道生成一个 AI 备用素材组。调整后，AI 备用素材模版不再按泳道生成，统一通过 `SuggestTypeEnum.AI_BACKUP_MATERIAL_GROUP` 标识。

本次调整目标：

1. 去掉 `message_material_group.ai_source_lane` 设计，AI 备用素材模版不再依赖泳道。
2. 新增 `SuggestTypeEnum.AI_BACKUP_MATERIAL_GROUP`，并通过 `message_material_group.ai_suggest_type` 标识 AI 备用素材组。
3. `/api/admin/material/listAll` 改为按 `ai_suggest_type = AI_BACKUP_MATERIAL_GROUP` 过滤 AI 备用素材组。
4. `AiMaterialSuggestionController` 新增 `batchGenerate` 批量异步接口，支持多条一起生成。
5. 原 `generate` 和新增 `batchGenerate` 都支持：传泳道时按泳道取规则；不传泳道时只取通用规则，不按泳道生成。
6. 新增 AI 备用素材生成状态查询接口，前端提交前可判断成功、失败、处理中数量。
7. 主素材模版创建/更新成功后，同步尝试创建或更新 AI 备用素材组；不用 MQ；开关关闭或异常时只记日志，不影响主素材模版 ID 返回。
8. 编辑主用素材组合方式、或新增 body 并已有 AI 备用素材建议时，同步更新 AI 备用素材组。
9. `getAiBackupMaterialGroup(Long primaryGroupId, String laneCode)` 改为按 `aiSuggestType` 查询。
10. 确认 `AiSuggestionGenerateReqDTO.MaterialContent#materialType` 未被业务使用，设计删除。

当前方案和相关代码尚未上线，因此不需要兼容旧的 `ai_source_lane`、MQ 异步创建、`source_type` 过滤等未上线实现。

## 2. 数据模型

### 2.1 `SuggestTypeEnum`

新增大写风格枚举：

```java
AI_BACKUP_MATERIAL_GROUP("AI_BACKUP_MATERIAL_GROUP", "AI backup material group")
```

使用范围：

- AI 备用素材内容生成；
- AI 备用素材生成状态查询；
- AI 备用素材组创建/更新；
- `/api/admin/material/listAll` 过滤；
- 发送流程查询 AI 备用素材组。

### 2.2 `message_material_group`

去掉原方案字段：

```sql
`ai_source_lane`
```

保留/新增字段：

```sql
ALTER TABLE `message_material_group`
  ADD COLUMN `primary_group_id` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Associated primary material group ID, 0 for non-AI-backup',
  ADD COLUMN `source_type` tinyint(4) NOT NULL DEFAULT '0' COMMENT 'Source type: 0=manual, 1=AI auto-generated',
  ADD COLUMN `ai_suggest_type` varchar(50) NOT NULL DEFAULT '' COMMENT 'AI suggest type from SuggestTypeEnum';
```

字段说明：

| 字段 | 默认值 | 说明 |
|---|---:|---|
| `primary_group_id` | `0` | AI 备用素材组关联的主素材组 ID；非 AI 备用组为 `0` |
| `source_type` | `0` | `0` 人工创建；`1` AI 自动生成 |
| `ai_suggest_type` | `''` | AI 建议类型；AI 备用素材组固定为 `AI_BACKUP_MATERIAL_GROUP` |

AI 备用素材组示例：

```text
主素材组：id = 100, primary_group_id = 0, source_type = 0, ai_suggest_type = ''
AI 备用素材组：id = 200, primary_group_id = 100, source_type = 1, ai_suggest_type = 'AI_BACKUP_MATERIAL_GROUP'
```

同一个主素材组下，`AI_BACKUP_MATERIAL_GROUP` 类型默认只对应一个 AI 备用素材组。

建议索引：

```sql
ALTER TABLE `message_material_group`
  ADD INDEX `idx_primary_ai_suggest_type` (`primary_group_id`, `ai_suggest_type`),
  ADD INDEX `idx_create_time` (`ctime`);
```

如果库表使用的是 `ctime` / `utime` 字段，则索引用 `ctime`；如果对应 SQL 文件使用 `create_time` / `update_time`，则按项目表结构规范给 `create_time` 加索引。

### 2.3 `message_material_combination`

保留原方案新增字段：

```sql
ALTER TABLE `message_material_combination`
  ADD COLUMN `primary_combination_id` bigint(20) NOT NULL DEFAULT '0' COMMENT 'Associated primary combination ID, 0 for non-AI-backup',
  ADD COLUMN `source_type` tinyint(4) NOT NULL DEFAULT '0' COMMENT 'Source type: 0=manual, 1=AI auto-generated',
  ADD INDEX `idx_primary_combination_id` (`primary_combination_id`);
```

字段说明：

| 字段 | 默认值 | 说明 |
|---|---:|---|
| `primary_combination_id` | `0` | AI 备用组合对应的主用组合 ID |
| `source_type` | `0` | `0` 人工组合；`1` AI 自动生成组合 |

### 2.4 `ai_material_suggestion.status`

`status` 调整为 AI 备用素材模版生成使用的业务状态：

| status | 语义 |
|---:|---|
| `1` | 接受为生成 AI 素材模版 |
| `2` | 未接受为生成 AI 素材模版 |
| `3` | AI 生成失败 |

当 `suggest_type = AI_BACKUP_MATERIAL_GROUP`：

- AI 生成成功后插入：`status = 1`；
- AI 生成失败后插入：`status = 3`；
- 失败内容固定写英文：`Generation failed`。

`feedback_type` 不作为 AI 备用素材组创建的强依赖条件。

`feedback` 接口不再更新 `status` 字段：

- `status` 专用于 AI 备用素材模版生成状态，不再承载普通建议的采纳/拒绝/评分反馈状态；
- `feedback` 仍可更新 `feedback_type`、`feedback_reason`、`user_score` 等反馈字段；
- 避免普通 AI 建议反馈误改 `AI_BACKUP_MATERIAL_GROUP` 创建判断所依赖的 `status`。

## 3. AI 建议生成接口

### 3.1 保留单条同步生成接口

接口：

```text
POST /api/admin/ai-suggestion/generate
```

保留原有同步单条生成能力。

调整点：

1. `sourceLanes` 传值时：
   - 按传入泳道取规则：`source_lane IN (sourceLane, 'ALL')`；
   - 保留泳道白名单和 `SourceLaneEnum` 校验；
   - 生成记录写入对应 `source_lane`。
2. `sourceLanes` 不传或为空时：
   - 不按泳道生成；
   - 只取 `source_lane = 'ALL'` 规则；
   - 生成记录 `source_lane = ''`；
   - 不做泳道白名单校验。
3. 顶层 `materialType` 保留，继续用于规则查询、prompt 填充和落库。
4. `MaterialContent#materialType` 当前未被业务读取，删除该字段及对应校验。

### 3.2 `feedback` 接口调整

接口：

```text
POST /api/admin/ai-suggestion/feedback
```

调整点：

1. `feedback` 不再更新 `ai_material_suggestion.status`。
2. `feedback` 只维护反馈相关字段：
   - `feedback_type`
   - `feedback_reason`
   - `user_score`
   - `update_time`
3. 原代码中类似 `record.setStatus(feedbackType.getCode())`、评分时设置 `status = RATE` 的逻辑需要删除。
4. `AI_BACKUP_MATERIAL_GROUP` 是否参与 AI 备用素材组创建，只由生成链路写入的 `status` 决定：
   - `1`：可参与创建；
   - `2`：不参与创建；
   - `3`：生成失败，不参与创建。

### 3.3 新增批量异步生成接口

接口：

```text
POST /api/admin/ai-suggestion/batchGenerate
```

用途：为 AI 备用素材模版批量生成建议内容。

核心规则：

1. 不预插入 `ai_material_suggestion`。
2. 接口收到请求后提交后台异步任务并立即返回。
3. 后台支持多条内容一起调用 AI。
4. 生成成功后插入 `ai_material_suggestion`。
5. 生成失败后插入失败记录。
6. 批量请求和 AI 返回都使用 `clientMaterialKey` 做唯一标识。
7. 同一次请求内 `clientMaterialKey` 必须唯一。

成功记录：

```text
client_material_key = 前端传入 key
material_type = 顶层或 item 的 materialType
suggest_type = AI_BACKUP_MATERIAL_GROUP
source_lane = 传泳道时为对应泳道；不传泳道时为空字符串
status = 1
suggested_content = AI 生成内容
```

失败记录：

```text
client_material_key = 前端传入 key
suggest_type = AI_BACKUP_MATERIAL_GROUP
status = 3
suggested_content = Generation failed
score_reason = 失败原因
```

`batchGenerate` 返回本次提交的 key 和接收状态即可，不承诺生成已完成。生成完成情况通过新的状态接口查询。

## 4. 多条一起生成

### 4.1 批量 prompt 标识

批量请求给 LLM 的每个 item 都带 `clientMaterialKey`：

```json
{
  "clientMaterialKey": "body-key-1",
  "content": "original body content"
}
```

LLM 返回也必须带 `clientMaterialKey`：

```json
{
  "clientMaterialKey": "body-key-1",
  "suggestedContent": "AI generated content",
  "score": 4.5,
  "scoreReason": "Reason text"
}
```

后端按 `clientMaterialKey` 匹配结果并写入 `ai_material_suggestion`。

### 4.2 批量分组

批量生成前按规则上下文分组：

```text
sourceLane 或空泳道
materialType
suggestType
language
ruleSnapshot
```

同组内再按配置拆小批，例如：

```text
ai_suggestion.batch_generate_size = 5
```

这样避免不同规则、不同语言、不同泳道上下文混入同一个 prompt。

### 4.3 失败处理

如果整批 AI 调用失败：

- 本批所有 `clientMaterialKey` 插入失败记录；
- `status = 3`；
- `suggested_content = Generation failed`；
- `score_reason` 写异常摘要。

如果批量返回缺少某些 `clientMaterialKey`：

- 缺失项插入失败记录；
- `score_reason = Missing batch result`。

不做单条降级重试。前端可根据状态接口提示用户重新生成。

## 5. AI 备用素材生成状态接口

现有 `/api/admin/ai-suggestion/list` 是查询指定 body 的所有建议内容，不复用于 AI 备用素材模版提交前检查。

新增接口：

```text
POST /api/admin/ai-suggestion/backup-material/status
```

请求示例：

```json
{
  "clientMaterialKeys": ["body-key-1", "body-key-2", "body-key-3"]
}
```

可选字段：

```json
{
  "materialGroupId": 100,
  "clientMaterialKeys": ["body-key-1", "body-key-2"]
}
```

查询条件：

```text
suggest_type = AI_BACKUP_MATERIAL_GROUP
client_material_key IN (...)
```

如果 `clientMaterialKeys` 数量较大，按项目规范分批 `IN` 查询。

### 5.1 状态判断

每个 `clientMaterialKey` 的状态：

| 状态 | 判断规则 |
|---|---|
| `SUCCESS` | 查到最新成功记录：`status = 1` 且内容有效 |
| `FAILED` | 未查到成功，但查到最新失败记录：`status = 3` |
| `PROCESSING` | 查不到成功/失败记录 |

不需要 Redis。因为 `batchGenerate` 不预插入，查不到成功或失败记录时即认为仍在处理中。

有效内容：

```text
suggested_content IS NOT NULL
suggested_content != ''
suggested_content != 'Generation failed'
```

如果同一个 `clientMaterialKey` 有多条成功记录，取最后一条成功记录：

```text
generation_seq DESC, create_time DESC, id DESC
```

统计口径按 `clientMaterialKey` 去重，不按数据库记录条数统计。

### 5.2 返回示例

```json
{
  "totalCount": 3,
  "successCount": 1,
  "failedCount": 1,
  "processingCount": 1,
  "items": [
    {
      "clientMaterialKey": "body-key-1",
      "status": "SUCCESS",
      "suggestionId": 1001
    },
    {
      "clientMaterialKey": "body-key-2",
      "status": "FAILED",
      "suggestionId": 1002,
      "message": "Generation failed"
    },
    {
      "clientMaterialKey": "body-key-3",
      "status": "PROCESSING"
    }
  ]
}
```

### 5.3 前端提交策略

用户点击提交主素材模版时：

1. 调用状态接口。
2. 如果 `processingCount > 0`：
   - 前端轮询状态接口；
   - 建议轮询间隔 2 秒；
   - 最多等待 30 秒。
3. 等待结束后：
   - `successCount > 0`：直接提交主素材模版；
   - `successCount = 0`：前端提示后仍提交主素材模版。

提示文案：

```text
AI备用素材模版创建出现异常，本次AI备用素材模版暂时不可用
```

AI 备用素材模版是增强能力，不阻塞主素材模版提交。

## 6. 主素材模版提交后同步创建 AI 备用素材组

### 6.1 不再使用 MQ

原未上线方案中的 MQ 异步创建移除：

- 不再发送 `ai_backup_material_group_create` Topic；
- 不再需要 `AiBackupMaterialGroupCreateConsumer`；
- `ai_backup.create_async` 不再使用。

### 6.2 同步创建流程

主素材模版创建/更新流程：

```text
保存主素材组
保存/更新素材
保存/更新主素材组合
保存 lane config
backfill ai_material_suggestion 的 material_group_id / material_id
同步尝试创建/更新 AI 备用素材组
返回 materialGroupId
```

同步创建需要放在 AI suggestion backfill 之后，因为 AI 备用素材组创建需要通过 `material_id` 找到原 body 和主组合。

### 6.3 开关

新增或保留配置：

```text
ai_backup.enabled
ai_backup.sync_create_enabled
```

语义：

| 配置 | 说明 |
|---|---|
| `ai_backup.enabled` | AI 备用素材模版总开关 |
| `ai_backup.sync_create_enabled` | 主素材模版提交后是否同步创建 AI 备用素材组 |

任一开关关闭：

- 跳过 AI 备用素材组创建；
- 记录 info 日志；
- 创建接口仍返回 `materialGroupId`；
- 更新接口仍返回成功。

### 6.4 异常处理

同步创建过程中任何异常：

- catch 异常；
- 记录 error 日志，包含 `materialGroupId`、`aiSuggestType`、operator；
- 不向外抛出；
- 不影响主素材模版创建/更新结果。

### 6.5 事务边界

推荐在主素材模版事务提交成功后，同线程执行 AI 备用素材组创建，例如使用 `TransactionSynchronization.afterCommit()`。

原因：

- 避免 AI 备用素材组创建失败导致主素材模版事务回滚；
- 确保 backfill、主组合等数据已提交后再查询；
- 仍然满足“不通过 MQ，同步尝试创建”的要求。

如果当前没有事务上下文，则直接同步调用，同样捕获异常。

## 7. AI 备用素材组创建/更新规则

### 7.1 查询成功建议

创建/更新时查询：

```text
material_group_id = 主素材组 ID
suggest_type = AI_BACKUP_MATERIAL_GROUP
status = 1
suggested_content 有效
```

有效内容：

```text
suggested_content IS NOT NULL
suggested_content != ''
suggested_content != 'Generation failed'
```

不按泳道过滤。

### 7.2 多条成功取最后一条

如果同一个 `clientMaterialKey` 有多条成功记录：

```text
按 generation_seq DESC, create_time DESC, id DESC 取最后一条
```

每个 `clientMaterialKey` 最多参与生成一份 AI body。

### 7.3 创建 AI 备用素材组

根据主素材组查找 AI 备用素材组：

```text
primary_group_id = 主素材组 ID
ai_suggest_type = AI_BACKUP_MATERIAL_GROUP
source_type = 1
```

不存在则创建：

```text
name = 主素材组名称 + '-AI-BACKUP'
template_type = 主素材组 templateType
language = 主素材组 language
status = 主素材组可用状态或默认 ACTIVE
combination_mode = 主素材组 combinationMode
primary_group_id = 主素材组 ID
source_type = 1
ai_suggest_type = AI_BACKUP_MATERIAL_GROUP
```

已存在则更新基础信息：

- `template_type`
- `language`
- `combination_mode`
- `updater`
- `utime`

### 7.4 创建/更新 AI 备用组合

对每个最新成功建议：

1. 根据 backfill 后的 `material_id` 找到对应主 body。
2. 查询主素材组中使用该 body 的主组合。
3. 如果一个 body 出现在多个主组合中，则为每个主组合创建或更新一条 AI 备用组合。
4. 复制主组合的 header/footer/buttons 素材到 AI 备用组。
5. 用 AI 建议内容创建新的 body 素材。
6. 创建或更新 `message_material_combination`：
   ```text
   material_group_id = AI 备用素材组 ID
   primary_combination_id = 主组合 ID
   source_type = 1
   header/body/footer/buttons = AI 备用组内素材 ID
   ```

已存在相同 `primary_combination_id` 的 AI 备用组合时，更新该组合及素材引用，避免重复创建。

## 8. 编辑主素材模版联动

编辑主素材模版时，AI 备用素材组需要保持与主素材组一致。

### 8.1 编辑主用素材组合方式联动

当主素材组 `combination_mode` 变更或手动组合调整时：

1. 同步更新 AI 备用素材组 `combination_mode`。
2. 基于最新主组合和最新成功 AI 建议重建/更新 AI 备用组合。
3. 保持 `primary_combination_id` 指向最新主组合。
4. 主组合被停用时，对应 AI 备用组合也应停用或不再参与返回。

### 8.2 新增 body 联动

保留原方案“新增 body 联动”能力，但不再按泳道处理。

场景：运营编辑主素材组，新增 body 素材；新增 body 已通过 `batchGenerate` 生成 `AI_BACKUP_MATERIAL_GROUP` 类型成功建议；提交主素材组后：

1. `AiMaterialSuggestionBackfillService` 根据 `clientMaterialKey` 回填新增 body 的 `material_id` 和 `material_group_id`。
2. 同步创建/更新 AI 备用素材组时查询到该新增 body 的最新成功建议。
3. 根据新增 body 所在主组合创建或更新对应 AI 备用组合。
4. 如果 AI 备用组已存在，则只新增/更新受影响的备用组合；如果不存在，则创建 AI 备用组并生成组合。
5. 如果新增 body 没有成功建议，则跳过该 body，不影响主素材组提交。

新增 body 联动与组合方式联动统一收敛到同一个幂等方法：

```java
createOrUpdateAiBackupGroup(materialGroupId, operator, AI_BACKUP_MATERIAL_GROUP)
```

该方法每次基于当前主素材组、当前主组合、最新成功 AI 建议做同步，避免分别维护多套增量逻辑。

## 9. `/api/admin/material/listAll` 过滤

原未上线方案按 `source_type != 1` 过滤 AI 备用组。

调整为只按 `ai_suggest_type` 过滤：

```text
ai_suggest_type IS NULL
OR ai_suggest_type = ''
OR ai_suggest_type != AI_BACKUP_MATERIAL_GROUP
```

这样只过滤 AI 备用素材模版，不误伤其他潜在 `source_type = 1` 数据。

## 10. 发送侧查询 AI 备用素材组

原方法：

```java
AiBackupMaterialGroupVO getAiBackupMaterialGroup(Long primaryGroupId, String laneCode);
```

改为：

```java
AiBackupMaterialGroupVO getAiBackupMaterialGroup(Long primaryGroupId, String aiSuggestType);
```

查询条件：

```text
primary_group_id = primaryGroupId
ai_suggest_type = aiSuggestType
source_type = 1
```

不再使用泳道。

返回前仍保留稳定性评级判断：

- 读取 AI 备用素材组稳定性缓存；
- 低于配置门槛时返回 `null`；
- 达标时返回 AI 备用素材组及组合列表。

## 11. 补偿 Job

新增或调整补偿 Job，支持按 `materialGroupId` 手动生成 AI 备用素材模版。

Job 参数：

```json
{
  "materialGroupId": 100
}
```

执行：

```java
createOrUpdateAiBackupGroup(100L, "SYSTEM", "AI_BACKUP_MATERIAL_GROUP")
```

用途：

- 开关关闭期间未生成；
- 同步创建异常；
- 历史数据补偿；
- 人工指定某个主素材组重新生成 AI 备用素材组。

如果不传 `materialGroupId`，可保留扫描补偿能力：扫描存在 `AI_BACKUP_MATERIAL_GROUP` 成功建议但没有 AI 备用组的主素材组，逐个补偿。若担心范围过大，第一版可以只支持指定 `materialGroupId`。

## 13. 测试与验证

### 13.1 单元测试

1. `generate`：
   - 传泳道时查 `sourceLane + ALL` 规则；
   - 不传泳道时只查 `ALL` 规则；
   - 无泳道时不做白名单校验。
2. `feedback`：
   - 提交采纳/拒绝/评分反馈时只更新 `feedback_type`、`feedback_reason`、`user_score`；
   - 不更新 `status`。
3. `batchGenerate`：
   - 同一请求内 `clientMaterialKey` 重复时校验失败；
   - 批量成功后插入 `status=1`；
   - 批量失败后插入 `status=3` 和 `Generation failed`；
   - 返回缺失 key 时插入失败记录。
4. 状态接口：
   - 最新成功返回 `SUCCESS`；
   - 只有失败返回 `FAILED`；
   - 无记录返回 `PROCESSING`；
   - 多条成功取最新；
   - 大量 `clientMaterialKeys` 分批查询。
5. AI 备用素材组创建：
   - 不按泳道查询；
   - 只使用 `AI_BACKUP_MATERIAL_GROUP + status=1`；
   - 同 key 多成功取最新；
   - 无成功建议时跳过不抛异常。
6. 编辑联动：
   - 主组合方式变更后 AI 备用组 `combination_mode` 同步；
   - 新增 body 且有成功建议时新增/更新 AI 备用组合；
   - 新增 body 无成功建议时跳过。

## 14. 风险与降级

| 风险 | 处理 |
|---|---|
| AI 批量生成耗时较长 | 前端状态接口轮询，最多等待 30 秒 |
| AI 全部失败 | 前端提示“AI备用素材模版创建出现异常，本次AI备用素材模版暂时不可用”，仍提交主素材组 |
| 同步创建 AI 备用组异常 | catch 后记录日志，不影响主素材组 ID 返回 |
| 开关关闭 | 跳过 AI 备用组创建，主流程正常返回 |
| 主素材组新增 body 无 AI 成功建议 | 跳过该 body，不影响主素材组 |
| `clientMaterialKeys` 数量过大 | 分批 `IN` 查询 |
| 多次生成同一 key | 取最新成功记录 |

# AI 备用素材模版 v2：同步创建 + 异步替换 body 技术方案

日期：2026-08-27
状态：待评审

## 1. 背景与目标

原方案中，AI 备用素材模版的 body 依赖 `ai_material_suggestion` 异步生成完成后再创建，前端提交主素材模版时需要等待/轮询 AI 生成状态，体验较差。

新方案改为：

1. 前端提交主素材模版时**直接提交，不再等待 AI 生成**。
2. 后端创建完主用素材模版后，**同步创建 AI 备用素材模版**。
   - header / footer / buttons 照旧复制主用素材。
   - **body 直接复制主用素材的 body 内容**（不再依赖 `ai_material_suggestion` 的 body）。
3. AI 素材内容异步生成完成后，再**替换 AI 备用素材模版的 body 内容**。
   - 更新 `message_material.element.text`。
   - 若该备用组合的 `message_template` 已生成，同步更新其 `components` 中 BODY 的 `text`。

仅针对 `suggest_type = AI_BACKUP_MATERIAL_GROUP` 生效。

## 2. 核心链路

```text
前端提交主素材模版
  → 后端创建主用素材模版（原逻辑不变）
  → 同步创建 AI 备用素材模版
       body = copy 主用 body，element.source_type = 1(AI)
  → 返回 materialGroupId（同步创建失败仅记日志，不影响主流程）

AI 异步生成完成（batchGenerate，仅 AI_BACKUP_MATERIAL_GROUP）
  → 写入 ai_material_suggestion，status = 1(ACCEPTED_FOR_AI_BACKUP)
  → 同线程调用 applyAiBackupBody 替换 body
       成功 status = 4(APPLIED_TO_AI_BACKUP)
       失败 status = 5(APPLIED_TO_AI_BACKUP_FAILED)

Job 补偿
  → 扫描 suggest_type = AI_BACKUP_MATERIAL_GROUP 且 status in (1,5) 的记录
  → 重新执行 applyAiBackupBody
```

## 3. 数据模型

### 3.1 OpayTemplateComponent

新增字段（对应示例 JSON 中的 `source_type`）：

```java
private Integer source_type;
```

新建枚举 `SourceTypeEnum`，两个值：

| code | 枚举 | 含义 |
|------|------|------|
| 0 | MANUAL | 人工 |
| 1 | AI | AI |

适用范围：仅 AI 备用素材模版的 element 写入 `source_type = 1`；主用素材模版的 element 暂不写该字段。

### 3.2 AiMaterialSuggestionStatusEnum

在现有 3 个值基础上新增 2 个，共 5 个值：

| code | 枚举 | 含义 |
|------|------|------|
| 1 | ACCEPTED_FOR_AI_BACKUP | 生成成功，待替换 body |
| 2 | NOT_ACCEPTED_FOR_AI_BACKUP | 不接受用于 AI 备用模版 |
| 3 | GENERATION_FAILED | 生成失败 |
| 4 | APPLIED_TO_AI_BACKUP | 替换 body 成功 |
| 5 | APPLIED_TO_AI_BACKUP_FAILED | 替换 body 失败 |

### 3.3 AiBackupMaterialStatusRespDTO

去掉 `failedCount`、`processingCount`，保留 `totalCount`、`successCount`；`items[].status` 直接以 `AiMaterialSuggestionStatusEnum` 枚举名（字符串）展示。

## 4. 创建 AI 备用模版的 body 来源变化

`AiBackupMaterialGroupServiceImpl.syncBackupCombinations` 调整：

- 不再查询 `ai_material_suggestion` 来决定 body 内容。
- body 直接复制主用组合的 body 素材 `element`，并将 `element.source_type` 置为 `1(AI)`。
- header / footer / buttons 仍按现有逻辑复制主用素材。
- 以 `primaryCombinationId` 幂等：已有更新、无则新增、目标集合外的旧备用组合置 INACTIVE（保持现有语义）。
- `queryLatestAcceptedSuggestions` 不再用于创建备用模版，仅供替换 body 阶段定位/取最新内容使用。

## 5. body 替换逻辑（applyAiBackupBody）

输入：一条 `ai_material_suggestion`（`suggest_type = AI_BACKUP_MATERIAL_GROUP`）。

定位链路：

```text
suggestion.materialGroupId（主素材模版 ID）
suggestion.materialId（主用 body 的 message_material ObjectId，已由 backfill 回填）
  → 主用组合 message_material_combination（material_group_id + body_material_id）
  → 备用组合（primary_combination_id = 主用组合 id，source_type = 1）
  → 备用 body 的 message_material（备用组合.body_material_id）
```

替换动作：

1. `message_material.element.text` = `suggestion.suggestedContent`（`source_type` 保持 `1`）。
2. 若 `message_template` 已存在（`material_combination_id = 备用组合 id`），解析 `components`，找到 BODY 组件并将 `text` 更新为 `suggestion.suggestedContent`；不存在则跳过（后续新建 message_template 时自然读到新 body）。

前置条件：

- `suggestion.materialGroupId` 与 `suggestion.materialId` 必须已回填（否则无法定位）。未回填时视为可重试，保持 `status = 1`，由 Job 下一轮再处理。

状态：

- 成功：`status = 4`。
- 失败：`status = 5`。

## 6. 触发与补偿

### 6.1 实时触发

`AiMaterialSuggestionServiceImpl` 在 `batchGenerate` 异步生成并写入成功记录（status=1）后，同线程对 `suggest_type = AI_BACKUP_MATERIAL_GROUP` 的记录调用 `applyAiBackupBody`。

### 6.2 Job 补偿

扫描 `suggest_type = AI_BACKUP_MATERIAL_GROUP` 且 `status in (1,5)` 的记录，逐条调用 `applyAiBackupBody`。失败继续保留 `status = 5`，等待下一轮重试。

## 7. status 接口语义

`/api/admin/ai-suggestion/backup-material/status`：

- `totalCount` = 入参去重后的 clientMaterialKey 数量。
- `successCount` = 该 key「最新一条」`status != 2` 的数量（即 1/3/4/5 都计入成功）。
- 去掉 `failedCount`、`processingCount`。
- `items[].status` = 该 key 最新一条的实际 `AiMaterialSuggestionStatusEnum` 枚举名（例如 `APPLIED_TO_AI_BACKUP`）。
- 无记录的 key：不计入 `items`（也不计入 `successCount`）；`items` 仅返回有 `ai_material_suggestion` 记录的 key。

## 8. 并发策略

业务正常每个 clientMaterialKey 只有一条建议，故不处理「第二代替换第一代」的竞态。

实时触发与 Job 补偿可能并发处理同一条记录，但：

- body 替换内容相同，多次写入幂等；
- status 即便短暂互相覆盖，也会被 Job 下一轮 `status in (1,5)` 扫描自愈。

因此不引入分布式锁、不做 latest-wins；可选的廉价优化是在 status 更新时加 `WHERE status IN (1,5)` 条件，减少无谓覆盖。

## 9. 兼容性与非目标

- 不做第二代替换第一代的版本仲裁。
- 不引入批次任务表、批次进度表。
- 不使用 Redis 标记生成中状态，不使用 MQ 创建 AI 备用模版。
- 主用素材模版的 element 暂不写 `source_type`。

## 10. 测试与验证

- `SourceTypeEnum` 取值与序列化。
- `AiMaterialSuggestionStatusEnum` 新增 4/5。
- `applyAiBackupBody` 成功/失败下 status=4/5。
- `message_material.element` body 替换成功，`message_template.components` BODY 组件替换成功（存在时）。
- `backup-material/status` successCount 语义（status != 2），items 枚举名展示。
- `syncBackupCombinations` body 来自主用素材而非 suggestion。

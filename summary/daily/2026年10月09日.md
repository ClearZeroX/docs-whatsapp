### 1. 「工作日报/周报/月报」自动化链路从零搭建（主线）

1. **问题现象**：需要把 Codex 桌面端与 Trae SOLO CN 上的执行记录自动整理成日报，并进一步支撑周报/月报；此前没有任何采集或生成链路，且用户明确要求「严格限制，只能读取，不能修改」。
2. **根因或结论**
   - Codex 侧实时真源是 `~/.codex/sessions/**/rollout-*.jsonl`（续聊追加同一文件），sqlite（`state_5` / `thread_history_1`）只是派生视图。
   - Trae SOLO CN 的 `ModularData/ai-agent/database.db` 为 SQLCipher 加密，**对话正文不可读**，只能取会话元数据。
   - DSH 记录为 `session.v4.jsonl.zstd`，可解压读取；但**续聊/分叉会完整重放父会话历史事件**（`5e16d406` 建于 11:30 却含 10:02 起的 1099 条），须按 `time >= createdAt` 去重。
   - 消息流混入大量 harness 注入（`<system-reminder>`、`Time sampled while...`、`background job bash-N`），须按 `source.kind == "user"` 过滤（238 条里真人输入仅 72 条）。
   - `dsh headless` 无内置超时参数，超时须由外层包装实现。
3. **处理动作**
   - 新增只读采集器 `collect.py`：复制 sqlite 到临时目录后读取，采集 Codex/DSH/Trae 会话与命令、按作者过滤 git 提交。
   - 新增执行器 `run-work-report.py`：生成 daily/weekly/monthly 报告，落地 3 个 launchd 任务。
   - 实现**跨报告关联**：日报取最近日报、周报取最近周报 + 窗口内日报、月报取最近月报 + 窗口内周报/日报；模板新增「承接与延续」逐条对账章节。
   - 修复采集器 sqlite 打开方式：Codex sqlite 为 **WAL 模式**，`-wal`/`-shm` 缺失时 `mode=ro` 只读打开会因无法创建共享内存文件失败。
   - 修复报告命名与窗口两处 bug；将 `scripts/` 整体搬迁到 `whatsapp_crm_docs/scripts/` 并全路径改引用。
   - 按用户要求把 `scripts/` 细分为 `scripts/ai-news/`、`scripts/work-report/` 两个需求子目录，并修复超时提示文件把 `--mode` 填进报告文件名的 bug；用模拟 launchd 最小环境验证三种模式构建提示词均正常。

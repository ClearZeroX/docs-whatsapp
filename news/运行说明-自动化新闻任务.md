> **两个任务当前都使用模型：`deepseek-v4.1-flash`**（provider 为 `opay-gateway`，仅本任务固定使用，不影响 App 默认模型）

> 最后更新：2026-10-10
> 本文档说明两套自动化的底层运行逻辑、配置修改方式、以及停止/恢复方法：
> - **每日 AI 新闻**（每天 10:00，详见第 1–10 节）
> - **副业风口周报**（每周三 18:45，详见下方第 11 节）

## 1. 这套自动化做什么

- **任务**：每天 **10:00** 自动抓取 AI 行业热点，**国内外兼顾**（国内条目不少于 3 条），覆盖四类——① 产品发布/功能更新 ② 融资与并购 ③ 技术突破/论文 ④ 行业标准与规范；输出 5–8 条（标题前标注【国内】/【海外】+ 一句话摘要 + 来源 URL）+ 2–3 句趋势点评。
- **产物**：写入本目录下的 **`<年月>/<年月日>.md`**，例如 `2026年10月/2026年10月09日.md`。文件正文最前面（大标题之下）固定有一行 **`> 本次使用模型：deepseek-v4.1-flash`**，便于追溯当天的文章是哪个模型生成。
- **驱动方式**：macOS **launchd**，**不需要** DSH 桌面 App 保持打开，也不依赖任何聊天会话在线。
- **超时保护**：单次执行上限 **10 分钟**（`TIMEOUT_SECONDS = 600`）。超时会杀掉进程并把当天文档标记为 **`<年月日>-执行超时.md`**；此时可双击本目录的 **`重新执行新闻任务.command`** 手动重跑。详见 [7.2](#72-超时后会发生什么--如何手动重跑)。

## 2. 底层运行逻辑（完整链路）

```
launchd（每天 10:00 触发）
  └─ /usr/bin/python3 运行执行器脚本 run-daily-ai-news.py
       ├─ 看护子进程：超时则杀进程组，退出码 124
       ├─ 切换到工作目录 /Users/opay-20260271/code-temp/ai-md
       └─ 启动 DSH 无头模式（--patch 可叠加，后者覆盖前者）：
            dsh --profile headless \
                --patch ~/.dsh/profiles/desktop/cordis.patch.yml \
                --patch ~/code-temp/ai-md/whatsapp_crm_docs/scripts/ai-news/model.patch.yml \
                "<任务提示词>"
              ├─ 基础层提供 provider / Key / 可用模型列表（跟随 App 配置）
              ├─ 模型层把默认模型钉为 deepseek-v4.1-flash（仅影响本任务）
              ├─ 读取 ~/.dsh 凭据 → 调用模型（当前：deepseek-v4.1-flash，provider 为 opay-gateway）
              ├─ 模型用 curl 抓官方博客 / RSS / 媒体 / Google News RSS
              ├─ 核对每条发布日期，剔除旧闻与未证实传闻
              └─ 写出 Markdown 文件到 news/<年月>/<年月日>.md
  └─ launchd 把脚本输出收集到 out.log / err.log
```

### 四个关键设计点（出问题时优先看这里）

1. **为什么写入不需要审批。**
   DSH 的 `workspace-write` 沙箱没有"按目录加白名单"的能力，它的规则是：**会话的工作目录（cwd）就是写入边界**，只允许写该目录树及系统临时目录。所以本任务把工作目录设为 `/Users/opay-20260271/code-temp/ai-md`，产物落在它下面的 `whatsapp_crm_docs/news/` 里，天然在边界内 → 永久免审批，且放行范围很窄（只有这一棵树）。

2. **为什么必须加 `--patch`（而且是两层）。**
   无头模式若使用全新 profile，会默认走 `deepseek-official` 路由并报 `MISSING_CREDENTIAL`。第一层 `--patch` 指向桌面配置，接入你自己的 provider 与凭据；第二层 `--patch` 指向 `scripts/ai-news/model.patch.yml`，把默认模型钉为 `deepseek-v4.1-flash`。因为都是**引用**而非复制，所以 App 里换 provider / 加模型后任务自动跟随，而任务用哪个模型由我们自己的第二层说了算。

3. **为什么不用 `web_search` 工具。**
   `web_search` 是独立的搜索插件（`web-search-deepseek`），需要**搜索服务自己的** `DEEPSEEK_API_KEY`（或 DeepSeek 账号登录态），与聊天用的自定义模型是两套凭据。当前任务改用 `curl` + 官方 RSS + Google News RSS，无需任何搜索 Key。

4. **超时为什么会被"看得见"。**
   无头任务被超时杀死时不会留下报错，只有日志；所以执行器在杀进程后会把当天文档改名加 `-执行超时` 后缀（若本次没写出文件，则建一个同名提示文件）。这样在产物目录里一眼就能看出"这天没跑完"，而不用去翻日志。

## 5. 如何修改配置

### 5.1 改执行超时时间 ⏱

编辑 `/Users/opay-20260271/code-temp/ai-md/whatsapp_crm_docs/scripts/ai-news/run.py`，找到 CONFIG 段的这一行：

```python
TIMEOUT_SECONDS = 600       # 单位：秒。600 = 10 分钟（当前值）
```

改成你想要的秒数即可（如 `1800` = 30 分钟）。**保存即生效，不需要重新加载 launchd**，因为 launchd 每次触发都会重新读取脚本。

> 当前 10 分钟是按需求设定的。正常一次约 4–6 分钟，属于够用但有风险；如果经常触发超时标记，建议调到 900–1800 秒。

超时行为分三步：

1. 先发 `SIGTERM`，等待 15 秒（`KILL_GRACE_SECONDS`）；仍未退出则 `SIGKILL` 整个进程组（不会留下僵尸进程）。
2. 给当天文档**加后缀**：`2026年10月09日.md` → `2026年10月09日-执行超时.md`（详见 [7.2](#72-超时后会发生什么--如何手动重跑)）。
3. 脚本以**退出码 124** 结束。

临时测试而不改文件（只影响这一次）：

```bash
DSH_NEWS_TIMEOUT=5 /usr/bin/python3 /Users/opay-20260271/code-temp/ai-md/whatsapp_crm_docs/scripts/ai-news/run.py
```

### 5.2 改执行时间（例如改成工作日 9:30）

编辑 `~/Library/LaunchAgents/com.opays.dsh.daily-ai-news.plist` 的 `StartCalendarInterval`：

```xml
<!-- 每天 10:00 -->
<key>StartCalendarInterval</key>
<dict>
    <key>Hour</key><integer>10</integer>
    <key>Minute</key><integer>0</integer>
</dict>
```

改成**工作日 9:30**（Weekday：1=周一 … 5=周五，0 或 7=周日）：

```xml
<key>StartCalendarInterval</key>
<array>
  <dict>
    <key>Weekday</key><integer>1</integer>
    <key>Hour</key><integer>9</integer>
    <key>Minute</key><integer>30</integer>
  </dict>
  <dict>
    <key>Weekday</key><integer>2</integer>
    <key>Hour</key><integer>9</integer>
    <key>Minute</key><integer>30</integer>
  </dict>
  <!-- 3、4、5 依此类推 -->
</array>
```

改完 **必须重新加载**（plist 不像脚本那样自动重读）：

```bash
L=com.opays.dsh.daily-ai-news
P=~/Library/LaunchAgents/$L.plist
plutil -lint "$P"                                   # 先校验语法
launchctl bootout   gui/$(id -u)/$L 2>/dev/null || true
launchctl bootstrap gui/$(id -u) "$P"
launchctl print gui/$(id -u)/$L | grep -iE 'state|runs'
```

### 5.4 如何指定任务使用的模型 ⭐

**任务当前使用的模型：`deepseek-v4.1-flash`（provider 为 `opay-gateway`）。**

这套配置分两层，**只钉任务、不动 App 默认值**：

| 层 | 文件 | 作用 |
|---|---|---|
| 基础层 | `~/.dsh/profiles/desktop/cordis.patch.yml` | 定义 provider、Key 环境变量名、baseURL、可用模型列表。**跟随 App 配置**，你换 provider 或加模型时自动生效 |
| 模型层 | `scripts/ai-news/model.patch.yml` | 只覆盖 `agent-default-model` 一条，把任务钉在指定模型上 |

#### 换成别的模型（推荐做法，3 步）

1. 编辑 `/Users/opay-20260271/code-temp/ai-md/whatsapp_crm_docs/scripts/ai-news/model.patch.yml`，把最后一行的 `model:` 改成想用的 id：
   ```yaml
   - id: agent-default-model
     name: "@deepseek-ai/dsh-agent-default-model"
     config:
       provider: opay-gateway
       model: deepseek-v4.1-flash     # ← 改这里
   ```
2. 同步改两处"显示用"的地方（只为可读性，不改也不影响运行）：
   - 脚本里的 `NEWS_MODEL`（`scripts/ai-news/run.py`；生成文件顶部显示的 `NEWS_MODEL_LABEL` 直接取自它，只显示模型 id、不带 provider 前缀）
   - **本文档最顶部**那行「本任务当前使用的模型：…」

   > 每天生成的新闻文件顶部那行是**自动**从脚本的 `NEWS_MODEL_LABEL` 注入的，不用手动改。
3. **保存即生效**，无需重载 launchd（脚本和 patch 都在每次运行时重新读取）。

**可用的模型 id** 见基础层 `llm-pi-ai` 段的 `models` 列表，当前 opay-gateway 路由下有：

```
deepseek-v4-pro
deepseek-v4.1-flash
on-premise/deepseek-v4.1-flash
glm-5.3
glm-5.3-flash
on-premise/glm-5.3-flash
```

> 用到未列出的 id 会被网关拒绝；要新增模型，先在基础层（或 App 里）把模型加进 `models` 列表。

#### 核对实际生效的模型（强烈建议改完跑一次）

```bash
D=/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh
B=/Users/opay-20260271/.dsh/profiles/desktop/cordis.patch.yml
O=/Users/opay-20260271/code-temp/ai-md/whatsapp_crm_docs/scripts/ai-news/model.patch.yml

# 任务实际使用的配置（应为 deepseek-v4.1-flash）
"$D" --profile headless --patch "$B" --patch "$O" --dump-config | grep -A6 'id: agent-default-model' | grep -E 'provider:|model:'

# 对照：App 的默认值（不受任务影响）
"$D" --profile headless --patch "$B" --dump-config | grep -A6 'id: agent-default-model' | grep -E 'provider:|model:'
```

或看运行日志首行，已带模型名：

```bash
grep START /Users/opay-20260271/code-temp/ai-md/.dsh-news-logs/run.log | tail -3
```

#### 两个容易踩的坑

1. **App 里对"当前会话"临时切换的模型不会写进任何 patch 文件**，只影响那个会话。所以定时任务不会跟着变 —— 这正是我们要的效果（任务钉死、App 自由）。
2. 想让**所有任务/新会话**都用同一个模型（而不是只钉这个任务），才需要去改基础层的 `agent-default-model`。一般不建议，因为那会同时改变 App 新建会话的默认模型。

若模型 id 下架、baseURL 变更或 Key 过期，任务会在模型调用处失败，日志报 `MISSING_CREDENTIAL` 或 HTTP 4xx。

### 5.5 改日志位置

- 脚本级日志：改脚本 CONFIG 段的 `LOG_DIR`
- launchd 级日志：同步改 plist 的 `StandardOutPath` / `StandardErrorPath`，并重新加载

## 6. 如何停止 / 暂停 / 恢复

| 需求 | 命令 | 说明 |
|---|---|---|
| **临时停止**（本次开机期间） | `launchctl bootout gui/$(id -u)/com.opays.dsh.daily-ai-news` | 重启后 launchd 会自动重新加载，任务**会回来** |
| **持续停用**（跨重启保持停止） | `launchctl disable gui/$(id -u)/com.opays.dsh.daily-ai-news` 然后再 `bootout` | 停用状态被持久记录 |
| **恢复运行** | `launchctl enable gui/$(id -u)/com.opays.dsh.daily-ai-news` 然后 `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.opays.dsh.daily-ai-news.plist` | 恢复后按原时间触发 |
| **彻底卸载** | `bootout` 后删除 plist：`rm ~/Library/LaunchAgents/com.opays.dsh.daily-ai-news.plist` | 再执行 `disable` 清理停用记录更干净 |
| **只跳过某一天** | 无原生机制：当天先 `bootout`，过后再 `bootstrap` | 或临时把时间改到明天之后 |

只看状态、不做变更：`launchctl list | grep dsh`（第一列是 PID，`-` 表示当前没在跑）。

## 7. 退出码、超时标记与故障排查

### 7.1 退出码含义

| 退出码 | 含义 | 处理 |
|---|---|---|
| `0` | 成功 | 看 `run.log` 的 `END exit=0` |
| `124` | **超时被杀**（超过 `TIMEOUT_SECONDS`，当前 600 秒） | 文档已被标记为 `-执行超时`，手动重跑见 [7.2](#72-超时后会发生什么--如何手动重跑) |
| 其他非 0 | 运行失败 | 看 `dsh-output.log` 尾部 |

### 7.2 超时后会发生什么 / 如何手动重跑 ⭐

**超时后自动做的两件事**：杀进程组 → 给当天文档加后缀 `-执行超时`（加在 `.md` 之前）。

具体分两种情形：

| 情形 | 结果 |
|---|---|
| 本次运行**已经写过**当天文档（可能是半成品） | 把 `2026年10月09日.md` 重命名为 **`2026年10月09日-执行超时.md`** |
| 本次运行**还没写出**任何文档 | 新建一个提示文件 **`2026年10月09日-执行超时.md`**，内容说明超时原因和重跑方法 |
| 目录里只有**上一次**留下的完好文档 | 不动它（避免误标），另建上面的提示文件 |

判断依据是文件修改时间：只有「本次运行开始之后被写过」的文件才会被加后缀。

> 已知边界情况：如果文档其实**已经写完、只是进程迟迟没退出**而被超时杀掉，它同样会被加上后缀（执行器只能判断到"文件是否被本次运行写过"这一层）。遇到时打开文件确认内容是否完整；若完整，把文件名里的 `-执行超时` 去掉即可。

**手动重跑（超时/失败后）**

双击本目录下的 **`重新执行新闻任务.command`** 即可（Finder 里双击会打开终端窗口执行）。它会用**完全相同的链路**重跑一次：同一个执行器、同一个模型、同样的 10 分钟超时；结束时打印成功/超时/失败，并把窗口保留住方便你看结果。

不想双击也可以用终端：

```bash
/usr/bin/python3 /Users/opay-20260271/code-temp/ai-md/whatsapp_crm_docs/scripts/ai-news/run.py
```

重跑成功后，旧的 `-执行超时` 文件**不会自动删除**，确认新文档没问题后自行删除即可。

> 实现位置：`scripts/ai-news/run.py` 的 `mark_timeout()` 函数；后缀文案由 CONFIG 段的 `TIMEOUT_SUFFIX` 控制。

### 7.3 常见问题

- `MISSING_CREDENTIAL` / `no API key for provider route`：模型凭据失效。检查 `~/.dsh/.credentials.yaml`，或确认 `DSH_PATCH` 指向的文件存在。若提示 `deepseek-official`，说明 `--patch` 没生效。
- 重启后任务突然不跑：App 被移动/改名会导致 `DSH_CLI` 路径失效，更新脚本里的 `DSH_CLI`。
- `err.log` 里的 `codesign_util.cc: task_name_for_pid failure (5)`：Electron 的无害警告，可忽略。
- **睡眠/关机期间错过**：不执行；`StartCalendarInterval` 会在唤醒后补跑**最近一次**，不会逐日补齐。
- 想确认今天是否跑过：看 `run.log` 最后几行和本目录当天文件的时间戳。
- 经常出现 `-执行超时`：说明 10 分钟不够，按 [5.1](#51-改执行超时时间-) 调大 `TIMEOUT_SECONDS`。

## 8. 与 DSH App 内定时任务的关系

- 原先在 DSH App 里创建的会话级定时任务（`schedule-823ba787`）**已删除**，避免同一天跑两次。
- **App 内那套的局限**：它的写入边界固定为会话工作区（`default-workspace`），产物在本目录树之外，因此**每次写入都要人工审批**。这正是改用 launchd 无头模式的原因——无头任务的工作目录可控，从而做到"只放行该目录、且免审批"。
- 本任务与 App 内会话的权限策略相互独立：例如 App 会话当前若是 `danger-full-access`，不影响本任务；本任务始终按自己的工作目录（`ai-md`）执行 `workspace-write`。

## 10. 常见疑问（FAQ）

### Q1：用的是哪个模型？

**`deepseek-v4.1-flash`**（provider 为 `opay-gateway`，`openai-completions` 协议，baseURL `https://routers.opays.ai/api/v0/llm`，Key 来自凭据 `OPAY_GATEWAY_API_KEY`）。

它由**两层 `--patch`** 决定：基础层 `~/.dsh/profiles/desktop/cordis.patch.yml` 提供 provider 与可用模型列表；模型层 `scripts/ai-news/model.patch.yml` 覆盖 `agent-default-model`，把本任务钉在 `deepseek-v4.1-flash` 上。因此**任务模型固定、与 App 的默认模型（当前 `deepseek-v4-pro`）互不影响**。怎么改见 [5.4 如何指定任务使用的模型](#54-如何指定任务使用的模型-)。

注意：App 里对**当前会话**临时切换的模型不会写进任何 patch 文件，只影响那个会话，定时任务不受影响。

### Q2：不在运行阶段会占用内存吗？

**几乎不占用。** 这套机制是"一次性进程"模型：

- `launchd` 只在系统里保留一条极小的任务记录（配置 + 上次退出码），**没有常驻进程**；不运行时 `launchctl print` 显示 `state = not running`，`ps` 里也找不到它。
- 每次到点才由 launchd 拉起 `/usr/bin/python3` 执行器脚本，脚本再拉起无头 DSH；**任务结束后两者都完全退出**，内存全部释放，不留后台服务。

实测运行期间的内存占用：无头 DSH 主进程 RSS **约 98 MB**（Electron-as-Node 基线），加上抓取时短暂出现的 `curl` 子进程，峰值大致 **100–200 MB**，运行结束即归零。作为对比，DSH 桌面 App 自身常驻约 250 MB（那是 App 的开销，与本任务无关）。

### Q3：DSH 桌面端关闭时会自动运行吗？

**会。** 触发和执行全程由 `launchd` 负责，它直接以当前登录用户的身份拉起进程，**不连接、也不需要** DSH 桌面 App 或任何聊天会话：

- 关掉 App 窗口、甚至完全退出 App（⌘Q）→ 任务照常在 10:00 执行。
- 唯一与 App 有关的依赖是**磁盘上那份 App 安装包**：无头入口 `/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh` 是 App 包内的文件。只要 App 还在原路径，CLI 就能用；**移动、改名或卸载 App 会导致任务失败**（届时更新脚本里的 `DSH_CLI` 即可）。
- 反过来，也不需要为了这个任务而保持 App 打开；只有你**手动**在 App 里改模型/凭据时，才需要打开它。

> 说明：本次验证是在 App 打开的情况下做的（kickstart 由 launchd 拉起、与 App 进程无关）；关闭 App 后行为不变，因为进程父子关系上它与 App 没有任何关联。真正无法在此刻实测的是"退出 App"这一动作——那会同时结束当前对话。

## 11. 副业风口周报（每周三任务）

面向个人开发者的副业机会周报，帮你把当周 AI 热点转成"能落地的小项目方案"。

### 11.1 它做什么

每周根据**近 7 天热点**，精选 **3 个副业风口**，分三档各 1 条：

| 档位 | 定位 |
|---|---|
| 【A】轻量试水 | 每周 ≤5 小时、近零成本，快速上线验证，优先复用 Java 能力 |
| 【B】稳健副业 | 每周 5–15 小时、可少量成本，目标月入 2k–1w，愿维护 3–6 个月 |
| 【C】产品化 | 可做成收费 SaaS / 工具，接受更长周期与更高投入，奔着副业转主业 |

每条按**完整版九段结构**输出：机会点 → 为什么是现在 → 目标用户+具体痛点 → MVP 范围 → 技术方案（站 8 年 Java 视角）→ 变现方式 → 投入估算 → 风险与壁垒 → 第一步行动。结尾附"本周机会小结 + 建议优先做哪一个"。

### 11.2 调度、窗口与产物

| 项 | 值 |
|---|---|
| 触发时间 | 每周三 **18:45**（launchd `Weekday=3 / Hour=18 / Minute=45`） |
| 数据窗口 | 截至**周二**的前 7 天：`[运行日-7天, 运行日-1天]` |
| 产物目录 | `news/sidehustle/<yyyy>/`（英文目录、只到年） |
| 文件名 | `<起>YYYYMMDD-<止>YYYYMMDD.md`，如 `20261007-20261013.md` |
| 超时 | **900 秒**（`TIMEOUT_SECONDS`） |

### 11.3 素材来源

- **宏观方向锚**：窗口内每天的日报 `news/<年月>/<年月日>.md`（执行器自动读入，缺的日期会标记"当日无日报"）。
- **细粒度信号源**（由模型 curl 现抓，均已实测可用）：Hacker News、GitHub Trending、Product Hunt、V2EX、少数派、Reddit r/SideProject。
- 已确认抓不到：indiehackers.com（403）、掘金/即刻（SPA），提示词里已写明不要浪费时间。

### 11.4 文件清单

| 文件 | 作用 |
|---|---|
| `scripts/sidehustle/run.py` | 执行器：算窗口 → 读日报 → 拼提示词 → 调 dsh → 写周报；含超时看护/日志 |
| `scripts/sidehustle/model.patch.yml` | 模型层，把周报钉在 `deepseek-v4.1-flash` |
| `~/Library/LaunchAgents/com.opays.dsh.weekly-ai-sidehustle.plist` | launchd 定时（每周三 18:45） |
| `news/sidehustle/重新执行副业任务.command` | 手动补跑（双击即可） |

### 11.5 常用命令

```bash
# 手动立即跑一次（等价于双击 .command，只是无窗口）
launchctl kickstart -k gui/$(id -u)/com.opays.dsh.weekly-ai-sidehustle

# 立即跑 / 停止 / 启用
/usr/bin/python3 /Users/opay-20260271/code-temp/ai-md/whatsapp_crm_docs/scripts/sidehustle/run.py

# 停止（卸载，直到重新 bootstrap）
launchctl bootout gui/$(id -u)/com.opays.dsh.weekly-ai-sidehustle
```

### 11.6 改配置入口

- **超时 / 数据窗口 / 提示词 / 源清单**：`scripts/sidehustle/run.py` 顶部 `CONFIG` 段（`TIMEOUT_SECONDS`、`WINDOW_DAYS`、`PROMPT_TEMPLATE`）。
- **模型**：`scripts/sidehustle/model.patch.yml` 里的 `model` 字段。
- **产物目录/命名**：`SIDEHUSTLE_DIR` 与 `output_path()`。

### 11.7 去重规则

生成时会自动读取 `news/sidehustle/` 下**上一期**周报的方向标题，提示词要求"避开这些已写方向"，避免每周重复推同一种项目。

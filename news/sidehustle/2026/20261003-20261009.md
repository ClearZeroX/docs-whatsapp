## 【A】repo-detox：给长期跑 AI 编码的项目做「仓库体检」的 Java MCP Server / CLI

### 1. 机会点
用 AI CLI Agent（Claude Code / Codex 等）写代码超过三个月的项目，正在集体出现「结构 / 文档 / 元数据 / 一次性产物」四类慢性腐化，而现在缺的不是"再写一个清理 skill"，而是一套可重复执行、结果可审计的**项目定期体检工具**。

### 2. 为什么是现在
- **微观点（最直接的需求帖）**：V2EX 10-10 热帖《AI 编码项目时间一长，结构和文档越来越乱，有什么好用的 project clean / code clean skill 推荐？》（https://www.v2ex.com/t/1247565 ）把腐化拆成四层：结构腐化（每个会话都可能新增一份 utils / helpers / adapters，重复实现越攒越多、后期没人敢删）、文档腐化（README / DESIGN / 总结类 md 越写越多且互相矛盾）、元数据腐化（AGENTS.md / CLAUDE.md 越来越长、规则互相打架、agent 反而更不遵守）、一次性产物散落（调试脚本、测试输出、临时报告混进源码）。发帖人已经试过"规则层 + 流程层 + skill 层 + 死代码检测（Knip / Vulture）"，结论是**只能解决 code clean，解决不了结构与文档层面的腐化**——这正是工具缺位。
- **微观点（同一批人还有第二个痛点）**：V2EX《换一个客户端，你的 agent 就重新认识你一遍》（https://www.v2ex.com/t/1247554 ）说明项目级"记忆"（技术栈约定、重构上下文）目前锁死在各自客户端里，没有一个中立的、随仓库走的事实来源。
- **生态信号**：GitHub Trending 当日榜单里 agent skill / 工程治理类项目密集——`mattpocock/skills`（"Skills for Real Engineers"）、`addyosmani/agent-skills`（"Production-grade engineering skills"）、`alibaba/open-code-review`（阿里开源的混合架构代码评审工具）、`anthropics/knowledge-work-plugins`。说明"给 agent 装能力"已是被验证的入口，而**"给 agent 装体检能力"仍偏空白**。
- **宏观信号**：日报 2026-10-09 第 6 条「Harness 收购 AI 编码公司 Augment Code，打通从构想到部署的软件工程链路」（https://siliconangle.com/2026/10/08/harness-acquires-augment-code-to-bridge-software-engineering-from-idea-to-deployment/ ）——资本正在押注"AI 软件工程全链路"；同周日报 2026-10-08 第 5 条 Anthropic 发 Haiku 5.5 并把 Sonnet 缓存价砍半（https://siliconangle.com/2026/10/07/anthropic-releases-claude-haiku-5-5-small-model-and-halves-sonnet-5-5-cache-read-prices/ ），推理成本下降会让"长跑 agent"更普遍，腐化问题只会更严重。

### 3. 目标用户 + 具体痛点
- **主用户**：1–5 人小团队或个人开发者，主力用 Claude Code / Codex / Cursor 写 **Java（Maven/Gradle）或 TS** 项目，项目龄 3 个月以上。
- **具体到能直接搜出来的痛点**：
  1. `src/main/java/.../utils/` 下出现 `StringUtilsV2`、`OrderHelper2`、`CommonAdapterNew` 三份功能重叠的实现，没人敢删；
  2. `AGENTS.md` 超过 400 行，同时写着"必须写单测"和"不要为任务外代码补测试"，agent 行为不稳定；
  3. 仓库根目录躺着 `debug_tmp.py`、`fix_output.txt`、`test_report_1008.md` 等一次性产物；
  4. `docs/` 里 6 个 md 描述的是 3 个不同版本的架构，新会话的 agent 读到哪份全看运气；
  5. 每次新开一个客户端/会话，都要重新口述技术栈与约定。
- **一句话价值主张**：`mvn det:check`（或一条命令）输出「腐化体检报告 + 可执行的清理工单」，让 AI agent 按工单干活而不是自由发挥。

### 4. MVP 范围
**核心功能（4 个检查器 + 1 个出口）：**
1. `duplicate-scanner`：Java 用 JavaParser 抽 AST，做方法级/类级相似度聚类（先做 token 归一化 + 编辑距离，不上模型），输出疑似重复实现清单与保留建议；
2. `docs-drift`：JGit 取近 N 次 commit 变更的包/类，比对 `docs/**/*.md` 中被删/被改的符号名，标出"文档提到但代码里已不存在"的段落；
3. `agent-config-lint`：解析 `AGENTS.md / CLAUDE.md / .cursorrules`，抽取祈使句规则，检测**互相冲突**与**token 膨胀**（阈值可配），给出去重合并版本；
4. `junk-files`：按 gitignore 外的一次性产物模式 + 未被任何配置引用的脚本，列出可归档清单；
5. **出口**：一个 `detox-report.md`（人读）+ 一份 `detox-tickets.json`（agent 读，可直接投喂给 Claude Code 逐条执行），并暴露为 **MCP Server 的 3 个工具**：`detox_scan`、`detox_report`、`detox_ticket_next`。

**明确砍掉：**
- 不做自动改代码 / 自动删文件（只出工单与 diff 建议，安全第一，也避开"AI 误删"信任雷区）；
- 不做 Web UI / 账号体系（首版纯 CLI + MCP）；
- 不做 Python / Go 等语言的 AST 分析（先做 Java 主栈 + TS 的文本级降级方案）；
- 不做 CI 自动 PR（放到 B 阶段验证有人付费后再说）。

### 5. 技术方案（8 年 Java 视角）
- **形态**：一个多模块 Maven 工程，`detox-core`（纯逻辑，无框架）、`detox-cli`（Picocli）、`detox-mcp`（MCP Server），一次开发三处复用。
- **关键选型**：
  - 构建：Maven 3.9 + `maven-shade-plugin`（单 fat-jar，零依赖上手），后续可选 GraalVM native 到 20MB 级单文件；
  - CLI：**Picocli** + JLine（进度与彩色输出）；
  - 解析：**JavaParser**（`com.github.javaparser:javaparser-symbol-solver-core`）做 AST 与符号解析；TS/JS 用 `tree-sitter` 的 Java 绑定或退化为正则+规则；
  - Git：**JGit**（`org.eclipse.jgit`）读取 diff、blame、文件热度；
  - 配置与报告：Jackson（JSON/YAML）+ **Handlebars** 或 `j2html` 生成 Markdown 报告；
  - MCP：官方 **MCP Java SDK**（`io.modelcontextprotocol.sdk:mcp`），或用 **Spring AI MCP Server Starter**（`spring-ai-starter-mcp-server`）——注意 MCP server 只需要 stdio 传输，不必引入整个 Web 栈，Spring AI 版本仅在需要 SSE 时启用；
  - 测试：JUnit 5 + AssertJ，准备 3 个真实开源项目的 golden repo 做回归。
- **可复用的现成库/思路**：直接借鉴 `alibaba/open-code-review` 的"确定性流水线 + 模型只做解释"混合架构；死代码部分可封装 Google 的 `error-prone` 或调用 `mvn dependency:analyze`；文档漂移可参考 ASH（Architecture Semantic History）思路但用 JavaParser 自实现。
- **架构要点**：所有检查器实现同一个 `Check` 接口（输入 `RepoContext`，输出 `Finding[]`），报告与 MCP 工具只是 `Finding` 的两种渲染——这样加第 5、第 6 个检查器几乎零成本。

### 6. 变现方式
- **开源免费**（Apache-2.0）CLI：拉 GitHub star 与 MCP 目录曝光，不收费；
- **GitHub App「仓库体检」订阅**：对私有仓库按次/按月，¥29/月（1 仓库，每周自动体检 + 报告存档），¥69/月（5 仓库 + 历史趋势）；
- **一次性"深度体检报告"**：¥199 起，人工复核 + 定制清理工单（Java 老兵的差异化服务，也是获客钩子）；
- **企业内训 / 咨询**：¥3k–8k/次，"AI 编码项目的长期工程治理"半天工作坊；
- **渠道**：Maven Central、`awesome-mcp-servers` 列表、GitHub Trending、V2EX / 掘金 / 少数派投稿、Product Hunt。

### 7. 投入估算
- **时间**：MVP 约 30–40 小时，按每周 ≤5 小时折算 **6–8 周**；其中 core 的 4 个检查器 2 周、CLI 3 天、MCP 封装 3 天、文档与 golden 回归 1 周。
- **成本**：≈ **¥0/月**（纯本地运行，无服务端；若做 GitHub App 体检则 GitHub Actions 或一台 ¥40/月 VPS 即可，LLM 只用于"解释发现"，可让用户自带 Key）。

### 8. 风险与壁垒
- **风险**：同类 skill 生态迭代极快（Matt Pocock / Addy Osmani 随时可能覆盖部分能力）；"体检报告没人看"是最大失败模式；JavaParser 对 Lombok / 复杂泛型有解析坑。
- **壁垒**：把"跨会话、可重复、可审计"做到位——skill 是个体自觉，工具是组织约束；积累 **golden repo + 腐化模式库**（哪些"重复"其实是刻意的、哪些文档漂移是正常的）是时间越久越难被抄的资产；中文社区的信任与口碑同样构成护城河。
- **对策**：不跟 skill 抢"清理"，只专注"发现问题 + 出工单"，并让报告的首屏直接给出"预计能删多少行 / 省多少 agent token"这种可量化收益。

### 9. 第一步行动（本周就能做）
用 2 小时写一个最小 `duplicate-scanner`：在本地 `~/.m2` 或 GitHub 上挑一个自己用 AI 写了 3 个月以上的 Java 项目，用 JavaParser 扫 `utils`/`helper`/`adapter` 包，按"方法名 + 参数类型 + 归一化方法体 token"聚类，终端打印疑似重复组。**先把真实项目里的重复组跑出来截图发到 V2EX / 掘金**，用这条帖子验证"有多少人愿意为一个能出工单的体检工具付费"——有 ≥30 个有效回复再投入 CLI 与 MCP 封装。

## 【B】LaunchPilot：出海发布雷达——目录提交 + AI 搜索引用监控一体化投放台

### 1. 机会点
"做出来"已经不难了，**难的是被找到**：独立开发者把产品做完后，要在几百个导航站/目录站填几百张字段各异的表单，还不知道自己在 ChatGPT / Gemini / Perplexity 的答案里到底有没有被引用——把这两个动作合并成一个可交付月费的工具，正好卡在当下最大的痛点缺口上。

### 2. 为什么是现在
- **微观点（原话级痛点）**：V2EX「搜索引擎优化」节点帖《目录交了一圈，GSC 外链还是 0》（https://www.v2ex.com/index.xml ）——手动提交到怀疑人生却毫无反馈；同周 V2EX《分享创造》里刚有人做了 `QueryWin`：「同一份产品资料，按每个目录和社区的表单拆开」（https://www.v2ex.com/index.xml ），说明"按表单拆分资料"已经不是猜测，而是有人正在做的刚需；r/SideProject 首页热帖标题直接是 **"Building got easier. Finding real users feels like the hard part now."**（https://www.reddit.com/r/SideProject/.rss ）。
- **宏观信号**：日报 2026-10-08 第 1 条 GPT-6 向全体用户开放，并同步上线 **Intelligent UI**——回答不再只是文字，而是内嵌图表、示意图、**表单和可点击按钮**（https://openai.com/index/gpt-6-for-everyone ，The Verge https://www.theverge.com/ai-artificial-intelligence/1007276/openai-chatgpt-intelligent-ui-gpt-6 ）。分发入口正在从"蓝链 SERP"迁移到"AI 答案 + 答案内交互"，传统 SEO 工具（Ahrefs/Semrush）对"我有没有被 AI 引用"几乎无解，这就是窗口期。
- **另一条侧证**：日报 2026-10-08 第 7 条提到 Meta、Walmart、Stripe、Sierra、Genesys、Decagon 正联合推进 AI Agent 电商互操作标准（https://techcrunch.com/2026/10/06/the-next-hurdle-for-ai-agents-getting-websites-to-let-them-in/ ）——跑在 AI Agent 前面的商家/工具，接下来必须让 agent"读得到、放得进"自己的结构化信息，与目录/GEO 是同一条能力的延伸。

### 3. 目标用户 + 具体痛点
- **主用户**：独立开发者与小团队 SaaS（1–5 人），产品主要面向英文市场或有出海意向，预算有限、时间极度碎片。
- **具体痛点（可直接做成功能清单）**：
  1. 手上 200+ 个导航站，每个站字段不同（有的要 tagline、有的要 "What problem does it solve"、有的要 3 张截图 + 演示视频链接），人工填一个平均 8–15 分钟；
  2. 提交后没有统一台账，忘了哪个提交过、哪个拒了、哪个还"pending 审核"；
  3. GSC 里外链数永远是 0，无法区分"提交没成功"和"提交成功但没被收录"；
  4. 不确定目标客户现在问 ChatGPT / Perplexity 时，答案里引用的是竞品还是自己；
  5. 每次改定位都要把 200 个站点的文案重填一遍，纯体力活。
- **一句话价值主张**：一份产品资料库，一处填写，自动适配到各目录表单并跟踪状态；同时每周告诉你"AI 答案里有没有提到你"。

### 4. MVP 范围
**核心功能（5 个模块）：**
1. **资料库（Profile Hub）**：产品名、一句话 tagline、痛点/解决方案长文案、Logo、截图、定价、分类标签，一次录入；支持多语言（中/英）。
2. **目录库**：先精编 **100 个**可验证的目录站（含提交入口 URL、字段 schema、是否有 DR 值、审核周期、是否免费），做成可运营的数据资产；字段 schema 用 JSON Schema 描述。
3. **表单自动映射**：用 LangChain4j 把资料库字段映射到每个目录的表单字段，生成"可直接复制粘贴的填充包"（首版**半自动**：打开站点、逐字段高亮"该填这里"），并在低风险站点上做 Playwright 全自动提交。
4. **提交台账**：状态机（未开始 / 已提交 / 审核中 / 已收录 / 被拒 / 需人工补充），带提醒与留存证据（提交截图/链接）。
5. **AI 可见性监控（差异化核心）**：固定 20–50 个目标查询（如 `best screenshot API for indie devs`），每周调用 ChatGPT / Gemini / Perplexity / Claude，记录答案中是否出现品牌、出现位置、引用链接，产出"AI 引用率"趋势图与竞品对比。
6. **arXiv 式周报邮件**：本周新增收录、外链、AI 引用变化，一键转发。

**明确砍掉：**
- 不做验证码/反爬绕过（法律与封号风险，坚决不碰，只做官方提交入口与半自动）；
- 不做站群/批量反向链接买卖；
- 不做全站技术 SEO 审计（那是另一个成熟赛道）；
- 不做社媒自动发帖（X/Reddit 自动化封号风险高）；
- 首版不做团队协作与权限。

### 5. 技术方案（8 年 Java 视角）
- **后端**：**Spring Boot 3.3**（Web + Validation + Scheduler）+ PostgreSQL 16；ORM 直接用 JOOQ 或 Spring Data JDBC（比 JPA 更贴合报表型查询）。
- **抓取与自动化**：**Playwright for Java**（`com.microsoft.playwright`）做需要登录/JS 渲染的站点，**Jsoup + OkHttp** 覆盖纯表单站点（大多数目录站是简单 HTML form，不要一上来就上浏览器，成本差 10 倍）；调度用 Spring `@Scheduled` 或 Quartz，任务级灰度开关。
- **LLM 编排**：**LangChain4j**（`dev.langchain4j`）做三件事——字段映射、文案改写、AI 可见性答案判定；模型侧走 Haiku 5.5 / GPT 低阶档（日报 10-08/10-09 持续降价，成本可控），用 `ChatLanguageModel` 抽象 + 多供应商路由；结构化输出用 JSON Schema 模式约束。
- **向量/检索**：pgvector 存"历史提交文案 → 目录反馈"的相似案例，做复用推荐（可选，MVP 可先用 PostgreSQL 全文检索）。
- **前端**：首版用 **Thymeleaf + HTMX**（8 年 Java 老兵的最短路径，不折腾前端构建），或直接 `Spring Boot + Vue3`；报表用 ECharts。
- **SDK/集成**：Google Search Console API（外链与收录）、Playwright 截图归档、Resend/SES 发周报。
- **支付**：Stripe（海外）+ 微信/支付宝（国内）；用 **Paddle/Lemon Squeezy** 做 MoR 可省掉大部分税务合规工作。
- **可复用现成件**：目录数据集可参考 `awesome-*` 系列与 Product Hunt 的 topics；Playwright Java 有官方 codegen 可辅助生成提交脚本。

### 6. 变现方式
- **定价**：
  - Starter **¥99/月**（1 项目、100 目录、周报、AI 可见性 20 个查询）；
  - Pro **¥299/月**（5 项目、无限目录、AI 可见性 100 查询 + 竞品对比）；
  - Lifetime **¥999** 限量发售（早期冲现金流 + 积累种子用户）；
  - 年付 8 折；出海用户按 $19 / $49 定价。
- **渠道**：V2EX / 即刻 / 少数派 / 小报童专栏做内容获客；Product Hunt 自举 launch；与"出海导航""独立开发周报"互推；把"每周 AI 引用率报告"做成可公开分享的卡片，自带传播。
- **附加收入**：代客提交服务 ¥499/次（人工兜底，验证付费意愿最快的路径）。

### 7. 投入估算
- **时间**：每周 8–12 小时，**3–4 个月**到可收费 MVP（资料库+目录库+半自动填充+台账 约 60h；AI 可见性监控 约 30h；支付与落地页 约 20h；目录库整理是持续投入）。
- **成本**：**¥200–500/月**（¥40–80 VPS + LLM 调用 ¥50–150 + 代理/邮箱/域名 ¥100 + Paddle 手续费）；首月可压到 ¥100 以内。
- **回本线**：Starter 定价下 **3–5 个付费用户**即覆盖成本，10 个 Pro 用户即接近月入 3k。

### 8. 风险与壁垒
- **风险**：
  1. 目录站反自动化与 ToS 限制——对策：默认半自动/官方表单，全自动仅限明确允许的站点，并保留用户手动确认；
  2. 目录库会持续失效（约每月 5–10% 链接腐烂）——对策：把"目录库新鲜度"当作核心运营指标，做众包纠错；
  3. **LLM 可见性测量噪声大**（同一次查询两次答案不同）——对策：固定温度、多次采样取命中率、明确标注"估算"而非"精确排名"，避免过度承诺；
  4. 赛道拥挤（提交类工具有一堆一次性脚本）——对策：不卖"提交"，卖**"提交 + 台账 + AI 引用率"闭环**，竞争维度从数量转向可验证结果。
- **壁垒**：高质量结构化目录库（字段 schema + 审核反馈）与"品牌在 LLM 答案中引用"的历史时间序列，前者靠运营、后者靠时间，都不容易被一夜复制；中文出海人群的本地化体验（微信支付、中文客服、时区）是海外工具懒得做的部分。

### 9. 第一步行动（本周就能做）
不要写代码：先用手工方式跑通闭环并收款。**用 4 小时手动为 10 个真实的出海导航站整理"提交字段清单"，拿 3 个愿意付 ¥99 的独立开发者朋友，人工帮他们提交并建立台账，同时用脚本每周跑 20 条查询记录"AI 答案里是否提到他们的产品"**。一周后交付一份 PDF 周报。如果 3 个人都愿意续费，说明"监测 + 台账"比"提交"更值钱，再开发自动化。

## 【C】AgentGate：给长尾站点用的 AI 智能体身份验证与授权网关

### 1. 机会点
AI Agent 马上就要大规模"替用户逛网站、下单、办事"，但海量中小站点既没有 Cloudflare 企业版、也没有安全团队，**无法分辨来访的到底是合法智能体还是恶意爬虫，更无法给不同 agent 发放"可读商品 / 可下单 / 可退款"的分级权限**——这是一个正在被巨头定义标准、却没人服务长尾的空白市场。

### 2. 为什么是现在
- **宏观信号（标准正在形成，这是最关键的时机）**：日报 2026-10-08 第 7 条明确指出，Meta、Walmart、Stripe、Sierra、Genesys、Decagon 等正在联合推进 AI Agent 电商互操作的开放标准，**用于区分"替用户办事的合法智能体"与恶意爬虫、反机器人系统**（TechCrunch：https://techcrunch.com/2026/10/06/the-next-hurdle-for-ai-agents-getting-websites-to-let-them-in/ ）。标准一旦落定，长尾站点需要的是"开箱即用的合规端点"，而不是自己读 RFC。
- **宏观信号（agent 已有独立身份，权限问题被摆上台面）**：日报 2026-10-09 第 2 条 Google Cloud 发布统一的 **Gemini Agent**，它拥有**自己的工作身份（独立 Gmail、Calendar、Drive）**，可自主规划、跨系统执行、把任务路由给子智能体甚至外部 Claude（https://blog.google/innovation-and-ai/infrastructure-and-cloud/google-cloud/gemini-at-work/ ，The Verge https://www.theverge.com/tech/1007904/google-gemini-ai-agent-enterprise ）。当 agent 有了"身份"和"被委派的能力"，站点侧必须有对应的验证与授权机制。
- **宏观信号（治理与合规压力外溢）**：日报 2026-10-09 第 3 条 Anthropic 发布 Cyber Mission、CIDP（首批聚焦电力、水务、交通等 OT）并更新 2026 Usage Policy 禁止模型滥用（https://www.anthropic.com/news/anthropic-cyber-mission ）；日报 2026-10-08 第 7 条同时给出 Cantwell 的前沿 AI 六点治理框架。**安全与可审计正在从"加分项"变成"采购门槛"**。
- **微观点 / 资本信号**：HN 首页同周出现《Cloudflare acquires Deno》（https://deno.com/blog/cloudflare ）——边缘运行时成为大厂必争之地，说明"跑在流量入口的中间件"价值极高；Product Hunt 当日榜单里 `AgentSDR`、`Gemini Agent for Google Cloud`、`OpenPilot`（"open-source desktop AI agent for any model you choose"）等 agent 类产品密集上榜（https://www.producthunt.com/feed ）；r/SideProject 里也有"冷启动外呼工具被 OpenAI / DeepMind 高管回复"的帖子，说明 agent 触达业务正在真实发生。

### 3. 目标用户 + 具体痛点
- **主用户**：GMV 在百万到千万级的中小独立站 / 电商 SaaS / 内容平台 / API 服务商（技术负责人 1–5 人，无专职安全）。
- **具体痛点（做成功能清单）**：
  1. 日志里一堆自称 `ChatGPT-User` / `PerplexityBot` / `ClaudeBot` 的 UA，**无法验证真伪**，只能一刀切封禁或全放行；
  2. 想接住 agent 带来的订单，但不敢给"下单 / 改地址 / 申请退款"这类写操作开放接口；
  3. 同一个人格化 agent 可能一秒发 200 个请求，缺少**按 agent 维度的限流与预算**；
  4. 出问题时无法举证"这个操作是哪个 agent、代表哪个用户、在什么授权范围内做的"（客诉与合规都要求）；
  5. 好不容易接入了某个新标准，标准一升级又要重做。
- **一句话价值主张**：在站点前面加一层边缘中间件，**验证 agent 身份、按 scope 授权、按 agent 计费限流、全程留痕**，让商家敢开门迎 agent。

### 4. MVP 范围
**核心功能（6 个模块）：**
1. **Agent 身份验证**：基于 **HTTP Message Signatures（RFC 9421）** 与 **Web Bot Auth**（Cloudflare/OpenAI 等推动的目录化公钥机制）验证请求签名，支持已知 agent 的公钥目录与自注册 agent 的 JWKS。
2. **Scope 授权**：站点声明资源能力（`catalog:read` / `cart:write` / `order:create` / `order:refund`），agent 注册时申请 scope，店主在后台一键批准/撤销；签发短期 **JWT / SD-JWT-VC**。
3. **策略引擎**：per-agent 限流（令牌桶）、并发上限、日预算（如"这个 agent 今天最多下 5 单"）、敏感操作二次确认。
4. **审计与回放**：全量记录 agent 身份、调用方用户、scope、请求摘要、决策结果；提供"这个订单是哪个 agent 下的"查询页与导出。
5. **接入 SDK**：3 种交付形态——① 反向代理（Caddy/Nginx 模块或独立 Go/Rust 边缘进程，Java 侧提供配置生成器）；② **Cloudflare Worker / Deno Deploy** 版中间件；③ 站点端 Java Filter / Spring Boot Starter（`@EnableAgentGate` 一行接入）。
6. **人读看板**：哪些 agent 来了、被拦了多少、带来多少订单、误拦申诉入口。

**明确砍掉：**
- 不做通用 WAF、不做 DDoS 防护（交给 Cloudflare）；
- 不做支付清算与资金托管（只做授权与风控信号）；
- 不做 agent 侧的编排/规划（那是 OpenAI/Google/Manus 的战场）；
- 首版不碰 OT / 关键基础设施（Anthropic CIDP 那种面向的是大厂合作，个人开发者进不去）。

### 5. 技术方案（8 年 Java 视角）
- **控制面（SaaS 后台）**：**Spring Boot 3.3 + WebFlux**（响应式，天然适合代理流量的高并发 I/O），PostgreSQL + Redis。
- **数据面（真正跑在流量路径上的代理）**：性能敏感，推荐 **Quarkus + Vert.x / GraalVM native image**（冷启动 20ms 级、内存占用低，适合边缘容器）；若不想引入第二套栈，可用 Spring Boot 3 + `spring-boot-starter-webflux` 的 Netty，先扛住百万级日请求再考虑下沉。**Java 老兵做这个的最大优势是：可以自己写一个 Nginx/Envoy 的 ext_authz 扩展或独立 sidecar，而不是被迫用 Node 写边缘函数。**
- **关键库**：
  - 签名/JWT：**nimbus-jose-jwt**（JWS/JWT/JWKS）、`io.github.hotstone/http-message-signatures` 或按 **RFC 9421** 自实现（`Content-Digest`、`Signature-Input`、`Signature` 三个头，Java 的 `java.security.Signature` 足够）；
  - 公钥目录/缓存：JWKS 缓存 + Redis，定期刷新 agent 目录；
  - 限流计费：**Bucket4j**（Redis 后端做分布式令牌桶）；
  - 审计：PostgreSQL 分区表 + Kafka（日志解耦），导出用 Parquet；
  - 可观测：Micrometer + OpenTelemetry + Prometheus/Grafana；
  - SDK：Spring Boot Starter + `spring-boot-configuration-processor`，提供 `AgentGateFilter`。
- **接入体验（决定成败）**：目标是一行配置 + 一个 DNS CNAME。控制面下发配置到边缘（定期轮询 + 长连接推送），站点无需改动业务代码即可先跑"仅观测模式"（只记录不拦截），这是降低采用门槛的关键设计。
- **可复用现成件**：Cloudflare 的 Web Bot Auth 规范与公钥目录、RFC 9421 参考实现、Envoy `ext_authz` 协议、Stripe 的 agentic commerce 文档（用来对齐 scope 命名）。

### 6. 变现方式
- **定价（按站点 + 流量）**：
  - Free：单站点、1 万请求/月、仅观测模式（用于获客与建立信任）；
  - Basic **¥199/月**：10 万请求、身份验证 + 审计；
  - Growth **¥999/月**：100 万请求、scope 授权 + 限流预算 + 看板；
  - Enterprise：按量报价 + 私有化部署（¥5 万/年起）；
  - 增值：按 agent 成交订单抽成 0.5%–1%（需与其支付/结算打通，第二阶段）。
- **渠道**：核心代理**开源**（GitHub，Apache-2.0）建立信任，云托管收费；上架 **Cloudflare Marketplace / Deno Deploy / Vercel Integrations**；与 Shopify / 有赞 / 微店 / Shopline 的插件市场、出海建站服务商合作分销；面向"独立站安全""agentic commerce"做技术内容营销。
- **销售抓手**：免费提供一份"你的站点被多少未验证 agent 访问过"的免费扫描报告（用公开 UA 日志或提供一段 JS 埋点），转化率极高。

### 7. 投入估算
- **时间**：每周 12–20 小时，**6–9 个月**做到可售卖（RFC 9421 验证 + 代理内核 约 80h；scope 授权与策略引擎 约 60h；控制面与看板 约 60h；SDK 与文档 约 40h；标准跟进与合规是持续成本）。
- **成本**：前期 **¥1,000–3,000/月**（边缘部署 + 数据库 + 公网带宽 + 域名/证书 + 观测工具；带宽是最大变量，建议免费档严格限流）。
- **里程碑假设**：30 个免费站点 → 5 个 Basic → 1–2 个 Growth，约 6 个月达到月流水 ¥3k–5k，验证后再考虑全职。

### 8. 风险与壁垒
- **风险（必须正视）**：
  1. **标准尚未定型**：Web Bot Auth / RFC 9421 能否成为电商 agent 事实标准仍有变数——对策：把签名验证做成可插拔策略（Strategy 模式），同时始终支持"仅观测模式"，标准变了也不白干；
  2. **巨头下场**：Cloudflare、Visa/Mastercard、Shopify 都可能把身份验证做成默认能力——对策：巨头的方案服务"协议两端的头部"，长尾站点的**配置成本、中文支持、私有化与定制策略**是留给独立开发者的空间；
  3. **信任门槛极高**：把流量交给一家个人 SaaS 需要勇气——对策：核心开源、可自托管、默认只观测不拦截、公开审计与安全白皮书；
  4. **误拦影响商家生意**：一次错误拦截可能就是几百单损失——对策：任何拦截都可回滚、可申诉、有灰度与 dry-run；
  5. **合规与责任边界**：涉及支付与退款授权，需要清晰的服务条款（本产品只提供授权与风控信号，不承担交易责任）。
- **壁垒**：一旦成为多个站点的 agent 入口，就掌握了"agent 行为画像 + 授权关系图谱"这一网络效应资产；加上开源社区与自托管生态，迁移成本会随接入深度上升。这是三个方向里唯一有机会长成基础设施的，也因此周期最长、验证最贵。

### 9. 第一步行动（本周就能做）
用 3 小时做一次 **"Agent 流量体检"最小实验**：在自己的域名/服务器上挂一段反向代理日志中间件（Java 写 100 行 Servlet Filter 即可），跑一周记录所有 UA 含 `GPT` / `Claude` / `Perplexity` / `bot` 的请求，统计"自称为 AI agent 的流量占比与行为特征"。然后**写一篇《我的站点一周内被 37 个自称 AI Agent 的爬虫扫过，没一个能验证身份》的技术贴发到 V2EX / HN / 独立站社群**，文末附一句"如果你想给自己的站点做同样的体检，留邮箱"。用这篇文章验证需求强度并收集前 20 个种子站点，再决定是否投入签名验证模块。

## 本周机会小结 + 建议优先做哪一个

本周三条主线——**GPT-6 的 Intelligent UI 把交互式答案变成默认分发形态**、**AI Agent 从"能干活"走向"有身份、要权限"**、**治理与溯源从自愿声明变成合规义务**——共同指向一个结论：模型能力在快速商品化，真正稀缺的是**"接缝处"的产品**：agent 与代码库的接缝（A）、产品与分发渠道的接缝（B）、agent 与站点权限的接缝（C）。同时对个人开发者有一个好消息：推理成本持续下降（Haiku 5.5 降价、Sonnet 缓存砍半）与开源权重模型（Mistral Large 4）意味着 B、C 类产品的边际成本已被压到个人可承受。

三档对照：**A 是"验证认知"**（成本≈0，用来测试自己的判断并积累开发者受众），**B 是"验证收款"**（3–5 个付费用户即回本，是最快产生现金流的方向），**C 是"押注基础设施"**（周期最长、天花板最高，但需要等标准进一步明朗）。

**建议优先做【A】repo-detox。** 理由有三：① 它是三者中唯一能在本周就产出可展示成果的（一个 duplicate-scanner 截图就能发帖验证），失败成本几乎为零；② 它 100% 复用你 8 年的 Java 能力（JavaParser、JGit、Maven、Spring AI MCP），不需要补前端或安全领域知识；③ 它天然带来**精准的开发者受众**——而这批人恰恰就是【B】的目标客户，A 的社区沉淀可以直接变成 B 的冷启动流量。**执行顺序建议：本周启动 A 并在 2 周内发出第一篇验证贴；A 稳定运行后（约 6–8 周）把精力转到 B 做现金流；C 保持关注 Web Bot Auth / RFC 9421 的标准化进展，等到有 3 家以上头部电商明确表态支持后再投入，是最稳妥的节奏。**

## 【A】ContextProbe：长上下文 / RAG「位置偏置」自检 CLI

### 1. 机会点
用一个能在 CI 里跑的 Java CLI，把「同一份资料换个位置、答案就变了」这个长上下文暗礁，变成可量化的位置热力图、相位周期检测和回归基线——让 AI 应用上线前有据可依，而不是靠用户投诉发现「昨天答对、今天答错」。

### 2. 为什么是现在
- **最直接的宏观锚**：日报 2026-10-10 第 2 条，字节 Seed 团队发布论文指出 DeepSeek-V4 系列长上下文「时强时弱」并非随机，而是由信息在输入中的位置决定、并以每 4 个 Token 为周期波动；128K「大海捞针」测试中同一信息换位置可让检索准确率拉开 **40.2 个百分点**，根因是分块 KV 缓存压缩带来的相位敏感性（量子位：https://www.qbitai.com/2026/10/502364.html ）。这是一个被公开命名、却几乎没人给开发者提供检测工具的工程问题。
- **影响面只会更大**：日报 2026-10-12 第 5 条，OpenAI 把 Codex / Work 环境下 GPT-6.1 Sol 的默认上下文从 272k 提升到 500k，并取消长上下文计费（IT之家：https://www.ithome.com/1/011/736.htm ）；上下文越长、位置影响越不可忽略。
- **成本纪律带来买单理由**：日报 2026-10-09 第 1 条，OpenAI 年化收入被曝比市场预期低约 200 亿美元，AI 芯片与算力股集体下挫（SiliconANGLE：https://siliconangle.com/2026/10/08/ai-stocks-crumble-on-report-that-openais-annualized-revenue-is-much-lower-than-previously-believed/ ）。当「堆 token、堆模型」不再无条件被信任，「可量化的可靠性」才好卖。
- **工程框架被证明能放大模型能力**：日报 2026-10-11 第 7 条，联想 TianxiCode + DeepSeek-v4.1-Flash 在 SWE-bench-Live 以 71% 登顶，官方强调跨文件检索、自主规划、测试驱动自愈（量子位：https://www.qbitai.com/2026/10/502422.html ）——「评测与回归」本身就是增值环节。
- **细粒度信号（品类正在成形）**：Product Hunt 本周出现 **Tiden（Intent verification for coding agents）**（https://www.producthunt.com/products/tiden ）、**Epherem（Find login and database flaws in your AI-built app）**（https://www.producthunt.com/products/epherem ）、**Reason（A state-of-the-art coding agent for cost efficiency）**（https://www.producthunt.com/products/dereference-the-100x-ide ），说明「验证 / 体检 / 成本」类开发者工具正在被市场接受（https://www.producthunt.com/feed ）。
- **社区真实抱怨**：V2EX 本周有开发者做「本地导演台」专门防止模型补台词胡言乱语（https://www.v2ex.com/t/1248880 ），以及「不同的模型，如何选择模型的客户端」这类选型困惑（https://www.v2ex.com/t/1248861 ）——可靠性与选型是开发者日常。

### 3. 目标用户 + 具体痛点
- **主用户**：1–5 人 AI 应用 / 小团队，做 RAG 知识库、合同审阅、研报分析、代码库问答，模型用 OpenAI 兼容 API、DeepSeek、Qwen 或本地 Ollama。
- **细化的痛点**：
  1. 合同的关键免责条款放在 200 页 PDF 的最后，模型答「未提及」；
  2. 同一批资料，调换两段顺序后答案自相矛盾，但没人知道是检索还是模型的问题；
  3. 上线前只测了 10 条问题、且都把关键信息放在开头，等于没测；
  4. 用户报「同一个问题昨天答对今天答错」，团队无法在 5 分钟内复现或定位；
  5. 选型时只有厂商排行榜，没有「在**我的**文档上、**我的**位置分布下」的鲁棒性数据。
- **一句话价值主张**：`ctxprobe run` 输出一张「准确率 × 信息位置」热力图 + 相位检测结论 + 与上次基线的 diff，直接挂进 CI。

### 4. MVP 范围
**核心功能（5 个模块）：**
1. **声明式测试集**：YAML 描述「问题 + 标准答案 / 判定规则 + 关键片段（needle）」，支持从真实文档摘录；
2. **位置扫描器**：把关键片段插入到 0% / 25% / 50% / 75% / 100% 位置，并支持按 Token 做每 N（默认 4）相位偏移的细粒度扫描；
3. **判定器**：精确匹配 / 关键词 / 正则 / 可选 LLM-as-judge（低成本模型）三档，输出每条用例的通过与否；
4. **分析与报告**：位置准确率曲线、相位周期检测（自相关 + 简化 FFT）、失败样例归档，生成 HTML + Markdown 报告；
5. **CI 出口**：`--baseline` 对比上次结果，准确率下降超阈值即非零退出；暴露 2–3 个 MCP 工具供 Claude Code / Codex 调用。

**明确砍掉：**
- 不做自动改 prompt / 自动调参（只诊断、不治疗，避免背「越改越差」的锅）；
- 不做生产环境在线监控大盘（那是 B/C 的事，首版只做离线与 CI）；
- 不实现向量库或检索框架（假设用户已有 pipeline，工具只负责「喂文档 + 问 + 判 + 报」）；
- 不做 Web 账号体系，首版纯 CLI。

### 5. 技术方案（8 年 Java 视角）
- **形态**：Maven 多模块，`ctxprobe-core`（扫描 / 判定 / 报告，纯逻辑）、`ctxprobe-cli`（Picocli）、`ctxprobe-mcp`（可选 MCP Server）。
- **关键选型**：
  - 运行时 Java 21，HTTP 用内置 `java.net.http.HttpClient`（自带连接池，够用且零新依赖）；
  - CLI：**Picocli** + JLine；测试集与基线用 Jackson YAML / JSON；
  - 模型接入：优先自写 **OpenAI-compatible client**（覆盖 OpenAI / DeepSeek / Qwen / 阶跃 / Ollama，一份代码全兼容）；若要多供应商统一抽象再用 **LangChain4j** 的 `ChatLanguageModel`；
  - 报告：**j2html** 生成 HTML + Handlebars 生成 Markdown；热力图直接用内联 SVG 或 ECharts CDN，避免引入前端构建；
  - 相位分析：自己实现自相关即可，需要 FFT 时用 **JTransforms**；
  - MCP：官方 **MCP Java SDK**（`io.modelcontextprotocol.sdk:mcp`，stdio 传输，无需 Web 栈）；
  - 打包：maven-shade-plugin 出 fat-jar；有余力再上 GraalVM native（单文件、秒级启动，对 CI 很友好）。
- **可复用现成件**：OpenAI-compatible API 生态（DeepSeek / Qwen / Ollama 全兼容）、`awesome-mcp-servers` 的接入惯例、JTransforms、Picocli。**8 年 Java 的差异化在「稳、可打包、能进企业 CI 和 Maven 生态」，而不是跟 Python 脚本比快。**

### 6. 变现方式
- **开源引流**：CLI 以 Apache-2.0 开源，冲 Maven Central + GitHub + MCP 目录曝光，不收费；
- **Pro 订阅 ¥39/月**：云端保存基线、历史趋势、团队共享报告、私有文档不入云（只存指标）；
- **一次性「长上下文体检报告」¥299 起**：人工复核 + 针对其文档分布给优化建议（Java 老兵的个人服务，也是最快验证付费意愿的路径）；
- **团队版 ¥199/月**：GitHub App / CI 集成 + 多项目 + 阈值告警；
- **渠道**：V2EX / 掘金 / 少数派投稿、MCP Server 目录、GitHub Trending、Maven Central、AI 应用开发者社群。

### 7. 投入估算
- **时间**：MVP 约 20–30 小时，按每周 ≤5 小时折算 **4–6 周**（扫描器与判定器 ~10h、报告 ~6h、CI/MCP ~6h、文档与样例 ~4h）。
- **成本**：**≈ ¥0/月**。纯本地运行，无服务端；调用模型时让用户自带 Key，自己的演示用 DeepSeek / 阶跃等低价模型即可，一次全量扫描成本在几角到几元。

### 8. 风险与壁垒
- **风险**：① OpenAI / Anthropic 官方 eval 工具持续增强，可能顺带覆盖位置测试——对策是绑定「中文长文档 + 多供应商对比 + CI 回归」这些官方不做的场景；② 上游厂商可能直接修复相位问题，需求变窄——对策是把它升级成通用的「上下文鲁棒性」检测（位置、噪声、顺序、跨语言混排），不押注单一 bug；③ 工程师小众、付费意愿弱——用开源 + 报告/订阅分层来筛出少数愿意付钱的人。
- **壁垒**：积累的是「golden 长文档测试集 + 各模型相位特征库 + 与上游 bug 的对应关系」。这份数据越跑越准，后来者很难一夜复制；报告一旦进了 CI，迁移成本会随团队流程上升。

### 9. 第一步行动（本周就能做）
用 2 小时写一个 100 行的最小脚本（甚至先不上 CLI 框架）：拿一份自己的中文长文档（合同 / 研报 / 开源项目 README），设计 3 个「答案必须依赖某个深埋片段」的问题，把关键片段分别插到文档 0%、50%、100% 位置，跑 3 个模型（如 DeepSeek、GPT 低阶档、本地 Ollama），把「位置 × 模型 × 正确率」画成一张热力图，**发到 V2EX / 掘金并配一句「你的长上下文可能也在以 4 个 Token 为周期抽风」**。有 ≥30 个有效回复或 ≥5 个「求工具」再投入真正的 CLI 封装。

## 【B】LocalDesk：合规敏感行业的「内网 AI 会议纪要 + 知识助手」私有化交付套件

### 1. 机会点
给「数据一律不许出内网」的律所、会计师事务所、医疗器械与制造业研发、国企二级单位，交付一套可离线运行的会议纪要 + 企业知识问答私有化套件，装在他们自己的机器上，按年收 License 与维保费——这是 8 年 Java 老兵在「企业内网交付」上的主场。

### 2. 为什么是现在
- **端云协同被微软定义为新常态**：日报 2026-10-08 第 6 条，微软发布 Windows「Hybrid Intelligence」，Copilot 可读取本地文件、跨系统执行操作，端侧与云侧模型协同调度（The Verge：https://www.theverge.com/tech/1007113/microsoft-windows-copilot-ai-control-search-hybrid-intelligence ）。「本地优先」从极客主张变成了平台叙事。
- **大厂亲自验证本地优先会议笔记**：日报 2026-10-09 第 7 条，Google 发布本地优先的 **AI Edge Foresight（Mac）**，可在完全离线情况下转写会议、生成笔记并回答问题（TechCrunch：https://techcrunch.com/2026/10/08/google-releases-a-new-local-first-granola-competitor/ ）。它只做 Mac、只做英语圈个人用户——**留给中小机构中文私有化部署的空间正好被空出来**。
- **端侧算力跨过可用线**：日报 2026-10-12 第 7 条，华为麒麟 9050 Pro 的 NPU 支持在端侧部署 **30B 参数 MoE** 大模型（IT之家：https://www.ithome.com/1/011/756.htm ）；HN 首页同期也有《LFM2.5-24B-A2B: Built for fast on-device agents》（https://www.liquid.ai/blog/lfm2-5-24b-a2b ）。端侧跑 30B 从「玩具」变成「能交付」。
- **合规压力是需求来源本身**：日报 2026-10-12 第 6 条，联合国 AI 专家组警告 AI 发展速度已超越监管能力，路透调查称中国 AI 实验室仅对约 3.6% 的模型版本披露安全测试结果（Reuters / 财联社）。机构对「录音、病历、报价不出内网」的要求只会更硬。
- **政策是顺风而非逆风**：日报 2026-10-10 第 4 条，中共中央、国务院《关于发展新质生产力的意见》明确「全面实施『人工智能+』行动」、用 AI 改造传统产业，同时严令防泡沫、不搞一哄而上（中国政府网：https://www.gov.cn/zhengce/202610/content_7082820.htm ）。务实、能落地、算得清 ROI 的传统行业 AI 项目正是被鼓励的方向。
- **细粒度信号（私有化确有市场）**：Product Hunt 本周 **CSuite（All-in-one suite for AI content creation, fully private）**（https://www.producthunt.com/products/csuite ）、**T-Scriptor（讲座自动记笔记）**（https://www.producthunt.com/products/t-scriptor ）、**SlashDocs by Razorpay（Self-hosted collaboration layer for agent-written HTML）**（https://www.producthunt.com/products/razorpay ）；V2EX 上「浏览器纯本地处理、支持离线」的视频剪辑工具也拿到不少反馈（https://www.v2ex.com/t/1248908 ）——「本地 / 私有」正在成为卖点。

### 3. 目标用户 + 具体痛点
- **主用户**：50–500 人的律所 / 会计师事务所 / 医疗器械企业 / 制造业研发中心 / 国企二级单位的信息化负责人或业务负责人（不是 CTO，是「被合规和效率同时夹住」的那个人）。
- **细化的痛点**：
  1. 想把会议录音丢给飞书妙记 / 通义听悟，法务一句「客户信息不得上传公有云」直接否掉；
  2. 会议里混着客户隐私、报价、病历、专利草稿，任何一段外泄都可能是执业事故；
  3. 内网已经有十几年的 Word / PDF / 工单，找一份旧合同要靠老员工记忆；
  4. 现成 AI 产品不接本地 LDAP / AD，不做离线模型升级，断网就废；
  5. 采购要一次性/按年付款、要发票、要有人上门兜底部署和故障处理——纯 SaaS 的独立开发者接不了。
- **一句话价值主张**：一根网线都不出内网的一体机/服务，完成「录音 → 纪要 → 待办 → 入库 → 问答」，且全程可审计。

### 4. MVP 范围
**核心功能（6 个模块）：**
1. **一键离线安装包**：Docker Compose（或 Windows 服务）封装 Ollama + 量化模型 + whisper.cpp / faster-whisper + Web 服务，提供离线镜像 tar 与安装脚本；
2. **本地会议纪要**：上传/导入录音 → 本地转写 → 说话人分离 → 结构化输出「结论 / 待办 / 责任人 / 时间点」；
3. **本地知识库问答**：导入 PDF / Word / 扫描件（OCR），本地向量化，回答**必须带原文出处页码**；
4. **敏感信息脱敏**：内置身份证 / 手机号 / 银行卡 / 金额 / 客户名的正则 + 本地 NER 打码，转写与问答前先脱敏；
5. **内网 Web 界面 + 本地账号**：任务列表、纪要归档、知识库管理，支持 LDAP / AD 对接；
6. **审计日志与许可**：所有访问与导出留痕；离线 License 文件按年/按席位激活。

**明确砍掉：**
- 不做实时会议机器人（先做「录音文件导入」，躲开会控/权限与稳定性大坑）；
- 不做移动端与小程序；
- 不做公网 SaaS（首版只做私有化，避免和合规诉求自相矛盾）；
- 不做模型训练/微调（只用现成量化模型）；
- 不做通用 OCR 平台（用成熟开源组件，只做与知识库的衔接）。

### 5. 技术方案（8 年 Java 视角）
- **后端**：**Spring Boot 3.3 + PostgreSQL 16 + pgvector**（托管版能落地的行业就上 pgvector，追求性能再换 Qdrant）；鉴权用 Spring Security + LDAP / AD。
- **LLM 运行时**：统一走 **Ollama / llama.cpp 的 HTTP 接口**（不要引入 JNI，交付和排障都会噩梦），Java 侧用 **LangChain4j** 做 RAG 编排（切分、检索、重排、prompt 组装、引用回链）。
- **ASR / 说话人分离**：`faster-whisper` 或 `whisper.cpp` 容器 + `pyannote` 容器，Java 只做编排与结果落库；中文场景优先选带标点的中文微调权重。
- **文档解析**：**Apache Tika + PDFBox**（PDF/Word/Excel），扫描件走 PaddleOCR 容器；脱敏 NER 首版可用正则 + 词典，后续换本地小模型。
- **前端**：**Thymeleaf + HTMX**（8 年 Java 老兵最短路径，交付时不需要 Node 构建环境），报表/统计用 ECharts。
- **交付工程（成败关键）**：Docker Compose + 离线镜像 tar + `install.sh` / `install.ps1`；License 用非对称签名文件离线激活；提供「客户机器体检脚本」自动检测 GPU / 显存 / 磁盘并推荐模型规格。
- **可复用现成件**：Ollama、whisper.cpp、faster-whisper、pyannote、PaddleOCR、LangChain4j、pgvector、Tika。**8 年 Java 的真正护城河是：Windows/Linux 混合内网、AD/LDAP、离线升级、发票与维保——这些恰是 Python/JS 独立开发者最弱、最不愿做的环节。**

### 6. 变现方式
- **私有化 License**：¥8,000–30,000 / 年（按并发或座位分档），首年含部署与培训；
- **首次部署实施费**：¥3,000–8,000（含现场/远程调试、模型选型、知识库初始化）；
- **维保与模型升级**：¥2,000 / 年（离线模型包季度更新、故障响应）；
- **轻量 SaaS 版**：对「数据可上云」的客户收 ¥299 / 座位 / 年，作为低价入口；
- **渠道**：本地系统集成商 / 办公设备服务商 / 行业软件代理商分销（给 30–40% 返点）；律协、会计协会、行业协会活动做技术分享；知乎 / 公众号写「我如何让一家律所的数据一步都不出内网」的落地案例；老客户转介绍。
- **现金流路径**：2 个 ¥8k 私有化客户 ≈ 月均 ¥1.3k；5 个 ≈ 月均 ¥3.3k，已进入 2k–1w 目标区间。

### 7. 投入估算
- **时间**：每周 8–12 小时，**3–5 个月**到可交付（转写 + 纪要流水线 ~40h；RAG 知识问答 ~40h；脱敏 ~20h；安装包与 License ~25h；界面与文档 ~25h）。
- **成本**：开发期 **¥200–500/月**（一台带 GPU 的测试机可本地或按量云，模型与软件全开源）；**强烈建议第一单先卖 PoC、用客户现场机器跑通再交付**，把硬件风险转移出去。

### 8. 风险与壁垒
- **风险**：① 飞书 / 钉钉 / 企业微信 / 华为也在推私有化，可能以生态优势碾压——对策是只做 2–3 个垂直行业，靠「行业模板 + 本地集成 + 上门服务」守住大厂不愿做重的部分；② 交付重、非产品化、毛利受实施拖累——对策是把安装包与体检脚本做到极致，把「交付」压到 1 天内；③ 客户硬件算力不足、模型效果不达预期——对策是提前做机器体检 + 明确 SLA 与模型规格；④ 行业销售周期长、回款慢——对策是要求 PoC 付费、首付 50%。
- **壁垒**：真正的资产是「行业模板库」（律所纪要格式、尽调清单、医疗病例脱敏规则）+「离线交付工具链」+「客户信任与维保关系」。软件会被抄，行业 know-how 与本地服务关系很难被抄。

### 9. 第一步行动（本周就能做）

## 【C】Agent BlackBox：智能体行为审计、意图校验与「紧急刹车」平台

### 1. 机会点
给已在生产环境跑 Agent 的企业装一个「黑匣子」：完整记录每一步工具调用与授权依据、运行时校验意图、越界自动刹车、一键生成可提交监管的安全事件报告——把「智能体可控性」从一句口号做成有日志、有证据、能过审的基础设施。

### 3. 目标用户 + 具体痛点
- **主用户**：已在客服、运营、研发、金融流程里跑 Agent 的中型企业（200–2000 人）；买单人是技术负责人、安全负责人或合规负责人，而不是开发者本人。
- **细化的痛点**：
  1. Agent 调了哪些 API、读了哪些数据、以**谁的权限**、在什么授权下做的，日志散在应用日志 / 网关 / 数据库三处，拼不出完整链路；
  2. 出现越权或误操作时，只能事后翻日志，**没有任何实时叫停手段**；
  3. 监管要求「立即上报」，但没人知道报告该写什么、证据在哪、时间线怎么还原；
  4. 无法向审计证明「高危动作经过了人工审批」，只能口头解释；
  5. 给 Agent 配的 API Key 权限过大，没有「按任务签发的临时授权」，一次泄露就是全量权限。
- **一句话价值主张**：在 Agent 与外部世界之间加一层可观测、可审批、可刹车的执行层，并把整条链路变成一份能交给监管和审计的证据包。

### 4. MVP 范围
**核心功能（6 个模块）：**
1. **零侵入接入**：三种交付形态——`spring-boot-starter-agentblackbox`（一行自动装配）、LangChain4j `ChatModelListener` 监听器、通用 HTTP 反向代理（非 Java 栈的 Agent 也能接）；
2. **全链路 Trace**：session → 计划 → 工具调用 → 入参 → 返回 → 授权凭证 → 成本，形成可回放时间线；
3. **策略引擎**：高危动作规则（转账 / 删数据 / 发邮件 / 提交表单 / 访问 PII / 调用生产写接口）+ 人工审批（飞书 / 企微 / 邮件按钮回执）；
4. **运行时刹车**：按规则命中、预算超限、异常调用速率自动暂停 / 降级 / 收回权限；
5. **事故报告生成器**：按白宫强制上报要求与 Cantwell 框架、EU AI Act 透明度结构，一键导出「时间线 + 证据包 + 影响评估 + 已采取措施」PDF；
6. **防篡改审计库**：append-only + 哈希链（每条记录 `hash(prev + record)`），提供对外可验证的完整性证明。

**明确砍掉：**
- 不做通用 APM / 日志平台（对接 OpenTelemetry 即可，不重造）；
- 不做 Agent 编排框架（只做「套在框架外面」的治理层）；
- 不做模型训练与红队服务（第三方可合作，首版只做工具）；
- 首版不做自动修复（只告警、刹车、出报告）；
- 坚决不碰 OT / 关键基础设施（Anthropic CIDP 那种是大厂合作，个人开发者进不去）。

### 5. 技术方案（8 年 Java 视角）
- **控制面**：**Spring Boot 3.3 + WebFlux**（治理流量以 I/O 为主），PostgreSQL（按时间分区）+ Redis；对象存储用 S3 / MinIO 存证据附件。
- **数据面（真正拦在调用路径上的一层）**：首版用 Spring Boot 3 + Netty 做轻量代理；若要下探到边缘，用 **Quarkus + Vert.x / GraalVM native**（冷启动 20ms 级，适合 sidecar 与边缘容器）。**Java 老兵的优势是能自己写 Envoy `ext_authz` 扩展或独立 sidecar，而不是被迫用 Node 写边缘函数。**
- **可观测**：**OpenTelemetry（GenAI semantic conventions）** 作为 trace 标准 + **Micrometer**，采集侧 Kafka / Pulsar 解耦，Micrometer 指标接 Prometheus / Grafana。
- **日志防篡改**：自研 append-only 存储 + 哈希链（`SHA-256` + 前序哈希），定期把根哈希写到客户自己的时间戳服务或另一处存储，形成不可抵赖证明。
- **策略引擎**：首版用 YAML → AST 的自研规则 DSL（易交付、好审计），规则复杂后再引入 **Drools**；限流 / 预算用 **Bucket4j**（Redis 后端）。
- **审批集成**：飞书 / 企微的 Webhook 与交互卡片回调（可复用现有 IM 集成能力），邮件兜底；审批状态回写 trace。
- **SDK**：Spring Boot Starter + `@AgentAction` 注解 + `spring-boot-configuration-processor`；LangChain4j 侧挂 `ChatModelListener` 捕获 tool call。
- **报告导出**：openhtmltopdf / iText 生成 PDF。
- **可复用现成件**：OpenTelemetry Java agent、Micrometer、LangChain4j 的监听机制、Bucket4j、Envoy `ext_authz` 协议。

### 7. 投入估算
- **时间**：每周 12–20 小时，**6–9 个月**做到可售卖（接入 SDK 与 trace ~70h；策略引擎与刹车 ~60h；审批集成 ~30h；防篡改日志 ~25h；报告生成器 ~35h；控制面与看板 ~60h；标准跟进与合规文档是持续成本）。

### 8. 风险与壁垒
- **必须正视的风险**：
  1. **标准尚未定型**：白宫强制上报的具体罚则未明确，Cantwell 框架与 EU 规则仍在演进——对策：接入层与报告模板全部可插拔，标准变了只换模板不推翻架构；
  2. **云厂商下场**：Microsoft / AWS / Google 很可能把 Agent governance 做成默认能力——对策：只做「跨云、跨框架、可私有化、能对接本地审批与中文合规报告」的部分，这是大厂最不灵活的角落；
  3. **信任门槛极高**：把自己 Agent 的所有调用轨迹交给一家个人 SaaS 需要勇气——对策：核心 SDK 开源、支持完全自托管、默认「只观测不拦截」、公开安全设计；
  4. **误刹车影响生意**：一次错误暂停可能损失真实订单——对策：默认 dry-run 模式、任何拦截可回滚、保留人工申诉通道；
  5. **责任边界**：必须写清「本产品提供工具与证据，不承担合规责任」，避免被当作出事后的背锅方。
- **壁垒**：一旦接入多家企业的 Agent 执行链路，就掌握了「Agent 行为模式库 + 行业事故案例库 + 审批关系图谱」。这三样随时间复利，且直接决定规则命中率与误报率——这是后进入者最难追的部分。

## 【A】ModelCanary：LLM 端点「降智 / 抖动」合成监控与状态页

### 1. 机会点

给靠 LLM API 吃饭的团队做一套"合成监控"：用固定金标任务定时打你的端点（官方 / 中转 / 自建 / 本地），量化今天有没有变笨、变慢、变贵，异常时 10 分钟内告警，并自动生成一份能发给老板和客户的月度质量报告。

### 2. 为什么是现在

- **同一家厂商在同一周给出"便宜但慢"与"快但贵"两个档。** 11 月 9 日 Anthropic 发布 Fable 5.2 / Mythos 5.2，标准 API 价降到每百万输入 8 美元、输出 40 美元，较 5.1 下调 20%；同时上线可选的快速模式，速度最高为标准模式 2.5 倍、单价 2 倍（[少数派 11-10 早报](https://sspai.com/post/118854)）。选型从"选哪个模型"变成"选哪套延迟/成本组合"。
- **低价模型进入主力池。** 11 月 9 日 Meta 发布 Muse Ember，定位"低价、高并发的 agent 任务"（[Product Hunt](https://www.producthunt.com/products/meta-ai)）。便宜模型到底够不够用，只能测。
- **分层路由已经是个人开发者的日常。** 11 月 10 日 V2EX 分享创造里有人写"用 myco 把重活交给云端 Claude、糙活交给本地 DeepSeek，省 80% token"（[v2ex 1255859](https://www.v2ex.com/t/1255859)），同一天还有人发帖"想看看大家现在能有多烧 Token"（[v2ex 1255917](https://www.v2ex.com/t/1255917)）。省钱的另一面是质量损失，但没人量化。
- **真实调用链路是混合的，质量不可观测。** 11-11 抓取的 V2EX 首页上，"封号 / 降智 / 倍率"讨论和"0.03x、0.6 折"的中转站推广挨在一起（[多模型网关](https://www.v2ex.com/t/1256242)、[高可用路由聚合](https://www.v2ex.com/t/1256229)）。中转偷偷换模型、缓存计费不透明、降智无法复现，是这个群体的日常。
- **端点只会越来越多。** 11 月 10 日 HN 首页"Apple 将推出让本地跑 AI 模型变简单的 Mac App"抓取时 267 分、228 条评论（[HN](https://news.ycombinator.com/item?id=50446520)）；同一周的 GitHub Trending（11-11 抓取）上，shadcn/improve 单日 +333，做的就是"用最强模型审计代码库、写计划给便宜模型执行"（[GitHub Trending](https://github.com/trending)）。

### 3. 目标用户 + 具体痛点

**用户一：3-30 人的出海 AI SaaS / 工具团队。** 产品里有 1-3 个 LLM 功能，月账单 200-5000 美元，官方 key 和中转混着用。痛点非常具体：用户说"今天回答变蠢了"，你复现不出来；中转说自己是满血 Opus，你没有证据；切到 fast mode 后 P95 延迟变了，但没人知道；老板问这个月为什么涨了 40%，你只能答"量大了"。

**用户二：API 中转 / 聚合服务商。** V2EX 上一抓一把。痛点是信任：客户质疑"你是不是掺了便宜模型"，退款纠纷说不清；需要一个第三方白标状态页挂在官网上，证明"我们没降智"。

**用户三：企业 AI 平台 / 采购方。** 季度供应商考核没有数据，SLA 条款签了但无法验证，出了事故无法复盘。

一句话：他们不缺日志，缺的是"用同一组问题、在同一时间、打不同端点"的对照实验。

### 4. MVP 范围

**做：**

- 端点管理：`base_url + key`（AES-GCM 加密落库）、模型名、价格表、超时与重试。
- 金标集：5 类 × 4 条 = 20 条，覆盖结构化抽取（带 JSON Schema）、长文摘要（要点覆盖率）、代码修复（单测通过率）、多轮指令跟随、中文业务问答（关键实体命中）。
- 双频调度：轻探针每 5 分钟跑 3 条便宜任务；质量探针每 1 小时跑满 20 条。
- 指标：成功率、TTFT P50/P95、输出 tokens/s、JSON Schema 合规率、拒答率、答案漂移（与 7 天基线比 embedding 相似度）、单次成本。
- 告警：连续 2 次失败、P95 超基线 2 倍、合规率跌破 90%，推飞书 / Slack / Telegram / Webhook。
- 公开状态页：可 iframe 嵌入、带 RSS，给中转商做白标。
- 月报 PDF：端点对比、事故时间线、成本变化。

**明确砍掉：**

- 不做全链路 tracing / APM（那是 Langfuse、Helicone 的地盘，做不过也不该做）。
- 不做 prompt 管理与版本控制。
- 不做自动切流（先只告警，切流要客户授权）。
- 不做私有化、不做移动端、不做多租户计费。

### 5. 技术方案

**选型：Java 21 + Spring Boot 3.3 + PostgreSQL 16 + Flyway + Spring Scheduling（起步）/ Quartz（多实例）+ Resilience4j + Micrometer + Thymeleaf/HTMX 状态页 + jTokkit + networknt JSON Schema Validator + OpenPDF + Docker Compose。**

一个反直觉的建议：**探针核心不要用 LangChain4j**。探针要的是"可复现的原始 HTTP 行为"——自定义 header、超时、流式分块、异常码，框架会把这些细节吃掉。直接用 JDK 21 的 `HttpClient` + Jackson，代码更少、行为更可控；LangChain4j 留给后面的"裁判模型"和 RAG 类断言。

**关键模块：**

- `probe-runner`：Java 21 虚拟线程并发打点，每个端点独立信号量限速（≤6 次/分钟），失败指数退避。
- `assertion-engine`：JSON Schema、正则、数值容差、关键词命中、embedding 相似度；断言与任务一起版本化（改题必须留痕，否则历史不可比）。
- `baseline`：滚动 7 天中位数 + MAD，只报"相对自身基线的漂移"，避免跨模型绝对分误导。
- `incident`：抖动抑制（连续 N 次才建事件）、事件合并、恢复通知。
- `reporter`：状态页、月报 PDF、Webhook 卡片。

**可复用：** OpenAI / Anthropic 官方 Java SDK（或直接 HTTP）、Resilience4j、jTokkit、Flyway、Testcontainers；客户已有 Langfuse 的，做一条"结果回写"集成即可。

### 6. 变现方式

| 档位 | 价格 | 内容 |
|---|---|---|
| Free | $0 | 1 端点、15 分钟粒度、公开状态页 |
| Starter | $19/月 | 3 端点、5 分钟、告警、30 天历史 |
| Team | $79/月 | 10 端点、质量分、飞书/Slack、月报、5 成员 |
| Agency | $199/月 | 20 端点、白标状态页、API、SLA 报告 |

年付 8 折；第 6 个月后再接私有化（¥2-3 万/年），前期不做。渠道：公开状态页吃 "xxx degraded / down" 长尾 SEO；V2EX 程序员节点、Reddit r/LocalLLaMA、HN Show HN；给 3 家中转商免费做一个月"质量认证"，换案例和转发。

### 7. 投入估算

- MVP：3 个周末，约 40-50 小时。
- 上线后：3-5 小时/周（看告警、补金标任务、写月报）。
- 现金成本：12-25 美元/月（2C4G VPS 约 8 美元 + 探针 token 5-15 美元，靠便宜模型 + 缓存压）。

### 8. 风险与壁垒

- **被判滥用 / 封号**：严格限速、优先用客户自己的 key、失败退避、遵守各家 rate limit 条款。这是这个方向最大的运营风险。
- **质量分主观**：只承诺"相对漂移"，不承诺"绝对智商"；横向对比标注样本量与置信区间；提供人工复核入口。
- **被 observability 平台覆盖**：Langfuse / Helicone 做的是"你调用之后"的 tracing，主动合成监控 + 第三方证明是另一件事；真被覆盖，就退到"中转商白标 + 行业质量报告"。
- **客户价格敏感**：纯薅羊毛用户不服务，主攻有付费能力的 SaaS 团队和中转商。
- **壁垒**：不是代码，是金标集、历史基线和状态页信任；做满 6 个月可以出"季度模型质量报告"做品牌。

### 9. 第一步行动

本周就能做：用 Spring Boot 写一个 300 行左右的 probe runner，对 3 个端点（Anthropic 官方、一个中转、本机 Ollama）每 10 分钟跑 10 条金标任务，结果落 SQLite，HTMX 出一个单页，接一条飞书告警。跑满 24 小时后，把结果写成《同一个 prompt，三个端点差多少》发到 V2EX 和 r/LocalLLaMA，文末放 waitlist。目标：20 个邮箱、5 个明确说"愿意付 19 美元/月"的回复。

## 【B】SlopGate：Java 团队「AI 生成代码」的增量质量门禁

### 1. 机会点

一个只审 PR 新增行的 Java 质量门禁：抓 AI 生成代码特有的坏味道——事务失效、循环查库、吞异常、复制粘贴、空断言、依赖膨胀——每条给出"为什么错 + 怎么改 + 可粘贴的 patch"，直接回帖到 PR。

### 2. 为什么是现在

- **提效的红利归公司，review 的成本落在资深工程师身上。** 11-11 V2EX 热帖《ai 只是提效了，并没有让程序员更轻松 反而更加累了》：裁员后活没少、人少了，领导动不动就说"你用 AI 一下"，但就是不给 token（[v2ex 1256221](https://www.v2ex.com/t/1256221)）。
- **团队已经在形成 AI 工作流，但流程里没有"验收"。** 同一天《大家是怎么使用 AI 来做开发的》在讨论 plan mode、spec、agent 编排（[v2ex 1256241](https://www.v2ex.com/t/1256241)），讨论的全是"怎么让 AI 写得更多"，很少有人讨论"怎么判断它写得好不好"。
- **"AI 产出"正在被拆成生成 / 审计 / 修复三段，并且开始单独定价。** 11-11 GitHub Trending 上 shadcn/improve 单日 +333（用最强模型审计代码库、写计划给便宜模型执行）、addyosmani/agent-skills +465、OpenAI 的 codex-security 也上了榜（[GitHub Trending](https://github.com/trending)）。安全有 Codex 和 gitleaks，风格有 Sonar 和 Checkstyle，**"AI 代码的可维护性"没人专门做**。
- **规范正在变成 agent 可执行的资产。** 11 月 5 日 Product Hunt 的 Skillbox 做的是"一个 skills 库，同步到所有 agent"（[Product Hunt](https://www.producthunt.com/products/skillbox-5)）。规范既然能喂给 agent，就一定能被检查器闭环。
- **模型越会写，review 越贵。** 11-09 Fable 5.2 把编程能力又抬了一档（[少数派 11-10 早报](https://sspai.com/post/118854)），PR 只会更多、更大。

### 3. 目标用户 + 具体痛点

**用户一：10-50 人 Java 团队的技术负责人 / 架构师。** Copilot、Claude Code、Cursor 全面铺开，PR 数量涨 30-50%，资深工程师一天 3 小时在看完 diff。他不是不想 review，是 review 变成了橡皮图章。

**用户二：外包 / 项目制公司。** 交付要过甲方验收，AI 生成的部分最容易在事务、并发、异常上埋雷，返工一次就吃掉项目利润。

具体到能一眼认出的点：

- `@Transactional` 标在 private / final 方法上，或同类自调用——事务根本不生效，线上出脏数据；
- Service 的 for 循环里调 Repository——100 次查询，压测才暴露；
- `catch (Exception e) { log.error("", e); }`——任务静默失败，第二天对账才发现；
- 同一个 `BeanUtils.copyProperties` 包装工具在 5 个模块各有一份；
- 测试只有 `assertNotNull`，或者干脆没有断言；
- 为一个小工具引入 3 个新依赖，pom 一个月胖一圈；
- `@Async` 自调用、`ThreadLocal` 没 remove、`CompletableFuture` 异常丢失、DTO/VO/Entity 三份互转混用。

Sonar 报的是"认知复杂度 27"，不会告诉你"这段代码是 AI 糊的，下周一定出事"。

### 4. MVP 范围

**做：**

- GitHub App + CLI 两种入口，只分析 PR diff 的新增行（Java），支持 Java 8-21 语法。
- 20 条规则，重点 8 条：事务自调用/非 public、循环内 DB/HTTP 调用、异常吞掉、跨文件重复代码指纹、空断言测试、`@Async` 自调用、`ThreadLocal` 未清理、pom 新增依赖预警。
- 输出：PR 行内评论，包含规则说明、事故场景、修复建议和可粘贴 patch；`--fail-on` 可阻断；`--baseline` 只看新增。
- 误报治理：一键"忽略并记住"（按文件指纹 + 规则），团队级白名单。
- 规则可配置：严重级别、是否阻断、阈值。

**明确砍掉：**

- 不做通用 SAST、CVE、依赖漏洞（有 Dependabot / CodeQL）。
- 不做代码风格（Spotless / Checkstyle 已经很好）。
- 不做 Java 以外的语言。
- 第一版不自动改代码，只给 patch 建议。
- 不做 Dashboard、不做私有化（第 4 个月再说）。

### 5. 技术方案

**选型：Java 21 + JavaParser（AST + Symbol Solver）+ PMD 7 自定义规则 + Spoon（跨文件调用链，可选）+ JGit（diff）+ GitHub App（JWT + installation token）+ Spring Boot 3（webhook，HMAC 校验）+ PostgreSQL + 虚拟线程。**

- `diff-filter`：JGit 拿新增行区间，只对落在新增行上的 AST 节点报错，避免"历史债"淹没 PR。
- `rule-engine`：PMD 的 XPath 规则覆盖 60% 的简单场景；跨文件（重复代码、调用链）用 JavaParser + Spoon 自己写 visitor。
- `fixer`：每条规则配一个模板化 patch（例如把 `@Transactional` 从 private 方法移到 public 入口），不调 LLM——LLM 只用来生成"事故解释"文案，可选。
- `reporter`：GitHub Review Comment API，按文件聚合，单 PR 最多 20 条，避免刷屏。
- `billing/quota`：按 repo 维度限流，GitHub App 免费额度内先跑。

**可复用：** JavaParser、Spoon、PMD、jgit、kohsuke github-api、Error Prone（想做编译期规则时）、Testcontainers。

**关键指标：** 在 5 个真实 Spring Boot 仓库上回测，把误报率压到 15% 以下再上线；宁可少报，不可乱报。

### 6. 变现方式

- 开源 CLI（Apache-2.0）：免费，规则可社区贡献，负责引流和建立"Java AI 代码质量"的话语权。
- Cloud：$9/repo/月；$79/月/组织（≤10 repo、全部规则、PR 评论、Slack 周报）；年付 $790。
- 私有化：¥1.8-3 万/年，含 2 次规则定制，走集成商 / 外包公司。
- 规则包订阅：「Spring 事务与并发 30 条」¥499/年，按季度更新。
- 服务：交付前体检 ¥2000/项目，给外包公司做现金流。

渠道：掘金、公众号、V2EX、Java 用户组；每一条规则写一篇"事故复盘"式文章（比功能宣传有效得多）；给开源项目免费扫，换 star 和案例。

### 7. 投入估算

- MVP：6-8 周 × 10-12 小时 ≈ 70-90 小时。
- 前 3 个月：8-12 小时/周（规则打磨 + 内容 + 客户支持）。
- 现金成本：20-40 美元/月（服务器 + 数据库），GitHub App 本身免费。

### 8. 风险与壁垒

- **SonarQube / CodeRabbit / Sourcery 覆盖**：差异是"只查增量 + Java 语义级规则 + 可执行 patch"，不是又一个通用 reviewer。
- **误报杀死信任**：先回测再上线；默认只警告不阻断；每条规则必须有真实事故案例背书。
- **规则可被抄**：代码不是壁垒，规则库、事故案例库、客户定制和品牌才是。
- **GitHub App 审核与权限**：最小权限（读代码、写 PR 评论），企业版走私有部署。
- **预算科目问题**："AI 代码质量"还不是很多团队的预算项，所以先用免费 CLI + 体检服务切入，再转订阅。

### 9. 第一步行动

本周就能做：挑 3 个真实 Spring Boot 仓库（自己手上的 + GitHub 上 2 个），用 JavaParser 写 3 条规则——事务自调用、循环内 Repository 调用、空断言测试——跑出真阳性 / 误报清单。把结果写成《AI 写的 Java 代码，最容易在这 5 个地方出事》发 V2EX 和掘金，文末放"免费体检 10 个项目"的表单。目标：10 个仓库提交、3 个愿意语音聊 20 分钟。

## 【C】MetricDock：信创环境下的私有化「指标语义层 + 问数」底座

### 1. 机会点

给中型企业交付一套私有化问数底座：把指标口径、维度、行级权限固化成语义层，LLM 只负责"翻译"不负责"定义"，SQL 经 Calcite 校验、限额、审计后才能执行，配套 50-100 条评测集，离线 Docker 包交付，适配达梦 / 人大金仓 / Oracle。

### 2. 为什么是现在

- **通用数据分析正在被大厂做成标配。** 11 月 10 日登上 HN 首页的"Claude Whiteboards, Claude Sheets, and Claude Data"抓取时 233 分、166 条评论（[HN](https://news.ycombinator.com/item?id=50443716)、[原文](https://claude.com/resources/articles/sheets-whiteboards-data)）。通用能力越便宜，企业愿意付钱的就越只剩"自己的口径 + 权限 + 合规"。
- **一周内两个平台退场，平台锁定被真实教育。** 11 月 9 日腾讯元器停止服务，2027 年 1 月 9 日后不再受理数据导出并删除用户数据（[少数派 11-10 早报](https://sspai.com/post/118854)）；11 月 10 日 HN 上 Val Town 关停，抓取时 387 分、97 条评论（[HN](https://news.ycombinator.com/item?id=50443427)）。"不要把企业资产锁在别人的 SaaS 里"从口号变成了采购问题。
- **合规成为采购前置项。** 11 月 10 日国家网信办上线统一备案系统（[少数派 11-10 早报](https://sspai.com/post/118854)）。本地部署、审计日志、数据不出网，从加分项变成门槛。
- **"LLM + 数据出结论"的需求已经被验证，但产品是玩具级。** 11-11 GitHub Trending 上 ZhuLinsen/daily_stock_analysis 单日 +960，做的是 LLM 驱动的多市场分析、零成本定时运行（[GitHub Trending](https://github.com/trending)）。个人玩股票可以这样，企业报表不行——差的是口径、权限、可追溯。
- **企业内 Agent 落地加速，第一个卡点就是查库。** 11-11 V2EX 有人开源并已商用的多 Agent 调度平台（[v2ex 1256245](https://www.v2ex.com/t/1256245)）。Agent 要干活就得读数据，而绝大多数企业不敢把生产库交给一个会自由写 SQL 的模型。

### 3. 目标用户 + 具体痛点

**用户一：200-2000 人的制造 / 零售 / 物流 / 能源企业的 IT 或数字化部门。** 已有 Oracle、MySQL、达梦、金仓，BI 有一堆固定报表，但业务方要的是"一句话问数"。

**用户二：系统集成商 / 行业软件厂商。** 客户点名要 AI 问数，自己团队做不动，需要有人分包。

痛点逐条：

- demo 在 30 张表上能用，上到 300 张表准确率就崩；
- "销售额"有 4 种口径（含税 / 不含税 / 发货 / 回款），模型每次选的不一样，业务方不敢用；
- 行级权限：大区经理只能看本区，Text2SQL 直接绕过权限；
- 一条没加 LIMIT 的 SQL 把生产库拖垮；
- 答错了无法追责，没有"当时用了哪些表、哪些指标、什么过滤条件"的记录；
- 采购要求私有化、等保、审计、国产数据库适配——通用 SaaS 一个都满足不了。

### 4. MVP 范围

**做：**

- 语义层：YAML 定义指标（口径 SQL 片段）、维度、同义词、默认过滤、行级权限表达式。
- 三路召回：表/列注释 + 指标名 + 历史正确 SQL 样例。
- SQL 生成：**指标 → 模板 → LLM 填参**为主，自由生成兜底；方言适配（先做客户现有的一种）。
- 安全护栏：Calcite 解析，只读、单语句、强制 LIMIT、超时、扫描量上限、权限谓词注入。
- 结果解释：列出用到的指标、过滤条件、时间范围，附"口径说明"。
- 反馈纠错：业务方点"不对"，把正确 SQL 存回样例库。
- 评测集：50 条真实问题 + 期望结果，每次改 prompt / 换模型都跑一遍。
- 审计日志：谁问的、生成了什么 SQL、查了哪些表、耗时多久。

**明确砍掉：**

- 不做通用 BI、不做报表设计器、不做 ETL。
- 不做多租户 SaaS（第一期就是单客户私有化）。
- 不做 AutoML、不做语音问数、不做移动端。
- 第一版只支持一种数据库，客户用什么就支持什么。

### 5. 技术方案

**选型：Java 21 + Spring Boot 3 + Apache Calcite + LangChain4j + JDBC + MyBatis + pgvector + Flyway + Vue 3（或先 HTMX 做内部工具）+ Docker 离线镜像。**

- `semantic-core`：指标定义、口径 SQL 宏展开、同义词、权限表达式；这是产品的真正核心，不是 prompt。
- `retriever`：schema 向量（pgvector）+ 指标倒排 + 历史样例，三路合并去重。
- `planner`：问题改写 → 选指标 → 选表 → 生成 SQL；低于置信阈值直接拒答，转人工。
- `guard`：Calcite 解析 + 方言校验 + 只读 + LIMIT + 超时 + 扫描量估算；任何一条不过就不执行。
- `evaluator`：结果集对比 + 关键数字容差 + LLM 裁判（可选）+ 人工复核。
- `audit`：全链路留痕，满足等保和事后追责。

**可复用：** Apache Calcite、LangChain4j、WrenAI（开源语义层，可参考设计，商用前先确认其 AGPL 协议边界）、Superset（客户已有就对接）、达梦 / 金仓 JDBC 驱动。

**一个关键取舍：** 先做"20 个核心指标 + 模板化 SQL"，再谈自由问数。前者准确率能做到 80%+ 并且可解释，后者在 300 张表上大概率翻车。这个顺序决定了项目能不能验收。

### 6. 变现方式

- 项目制：8-15 万/客户（1 个数据源 + 50 条评测 + 2 个月调优），年维护 15%。
- 轻量版：3.8 万/年（≤50 用户、1 个数据源、标准规则包）。
- 渠道：集成商分包（返点 20-30%）、行业软件厂商 OEM、老客户转介绍；不投广告，不做直客陌拜。
- 目标：第一年 3-5 个客户、30-50 万收入；第二年视情况转主业。

### 7. 投入估算

- MVP：3 个月 × 12-15 小时/周 ≈ 150-180 小时。
- 首个客户交付：6-8 周（含 3-5 天驻场）。
- 现金成本：服务器 / 数据库约 500 元/月 + LLM API 300-800 元/月 + 差旅 2000-5000 元/客户。

### 8. 风险与壁垒

- **准确率不达标（最大风险）**：只承诺 Top 20 高频问题；低于阈值拒答转人工；评测集和验收标准写进合同。
- **大厂与开源夹击**：WrenAI、Vanna、Quick BI 都在做；差异化在私有化 + 国产库 + 口径治理 + 交付，不打价格战。
- **回款慢、关系型销售**：先做分包不直客；合同按 3-4-3 付款；不垫资。
- **数据安全**：模型不出网、数据脱敏、审计留痕；等保材料提前准备。
- **壁垒**：行业指标模板 + 方言适配 + 交付方法论，做得越久越厚；单纯"套一个 LLM"没有壁垒。

### 9. 第一步行动

本周就能做：找 1 家你认识的、用 Oracle 或达梦的中型企业 IT 负责人，要一份脱敏 schema + 20 个真实业务问题，手工写出"标准 SQL + 期望结果"，用 GPT / Claude 跑一遍，统计准确率。把结果做成一页纸《你们现在的问数准确率大概是多少》，约 30 分钟当面讲。目标：拿到一句"如果准确率能到 80%，我们可以立项"的口头承诺——这句话比写三个月代码值钱。

## 本周机会小结 + 建议优先做哪一个

三个方向的共同点：**都不再生成内容，而是给 AI 的产出做验收。** A 验收"外部模型今天还行不行"，B 验收"AI 写的代码能不能维护"，C 验收"企业问数的数字对不对"。这也是本周信号最一致的地方：供给端越便宜、越花哨，验收就越值钱。

- **A（ModelCanary）验证最快**：3 个周末能上线，公开状态页天然带流量，适合先拿到真实付费信号；缺点是付费方价格敏感，容易被 observability 平台顺手覆盖。
- **B（SlopGate）最匹配 8 年 Java 的能力复利**：JavaParser / PMD / Spring 语义是你的主场，规则库和事故案例会越攒越厚，客户是技术负责人、付费理由直接（review 成本），后续还能复用到 C 的 SQL 审计。
- **C（MetricDock）天花板最高**：单客户 8-15 万，但周期长、依赖关系型销售，不适合作为第一个动作。

**建议优先做 B，把 A 当作 2 周的低成本实验，C 用"客户意向"当启动开关。**

具体节奏：

1. 第 1-2 周：A 的 MVP 跑起来，发一篇《同一个 prompt，三个端点差多少》拿 waitlist；同时开始 B 的 3 条规则（事务自调用、循环查库、空断言）。
2. 第 3-8 周：B 的 CLI + GitHub App 上线，免费体检 10 个项目，积累第一批真实仓库和误报数据；A 只维护告警，不投入新功能。
3. 第 9-12 周：看两个数字决定加码——A 的付费转化 ≥5 个，或 B 的体检转化 ≥3 个付费组织。哪个先到，哪个就是主线；都没到，说明问题定义错了，回去改访谈而不是加功能。
4. C 不排期，只在拿到"可以立项"的口头承诺后启动；没有客户意向就先不写代码。

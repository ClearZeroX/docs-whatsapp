## 【A】AgentLeak：AI 编程工具链「凭据泄露」自查与修复 CLI

### 1. 机会点

做一个本地优先、一条命令跑完的 CLI，专门扫描 Claude Code / Cursor / Codex / MCP 配置文件里被写死的数据库密码、API Token、SSH 私钥和内网地址，并给出可执行的轮换与清理步骤。

### 2. 为什么是现在

这不是「猜需求」，是本周已经发生的可量化事故。少数派 11 月 11 日早报引用 AI 安全公司 Apiiro 的披露：事件发生在 11 月 9 日，公开 GitHub 仓库中有超过 10 万个 Claude Code 的 `.claude/settings.local.json` 文件，其中约 1,100 个、来自 63 个组织的文件含有密钥，且 215 个密钥没有被 gitleaks 和 TruffleHog 识别（[少数派早报](https://sspai.com/post/118905)）。根因很具体：用户在审批 shell 命令时选择「Yes, and don't ask again」，Claude Code 会把命令原样写进本地设置文件，数据库连接串、`curl -H "Authorization: Bearer ..."`、`mysql -p...` 都可能被记录；文件被误提交后，即使删除，密钥仍可能留在 fork 里。

第二层信号是「AI 安全工具在加速发现问题，但修复环节没人接住」。HN 11 月 10 日首页 400 分的讨论 [Tracking Anthropic-discovered vulnerabilities](https://news.ycombinator.com/item?id=50447074) 引用 VulnCheck 的统计：Anthropic 的 AI 漏洞扫描项目 7 个月报告了 37,966 个发现，只有 7,349 个公开、217 个被标记修复，维护者被大量低质量报告淹没（[VulnCheck 原文](https://www.vulncheck.com/blog/anthropic-glasswing-november-update)）。这说明「发现」正在商品化，「在开发者本地、在提交之前完成修复」反而是空白。

第三层是配置文件的爆炸。GitHub Trending 11 月 11 日抓取中，`anthropics/skills` 单日 +1,679 stars、`mattpocock/skills` +1,225 stars（[GitHub Trending](https://github.com/trending)），Agent Skills、MCP server、权限规则正在成为每个项目的标配文件。文件越多、权限越大，误提交的面就越大。Product Hunt 11 月 4 日的 Nadhif（检查 Mac/服务器/网站安全）和 11 月 7 日的 Levo（AI 帮你判断 Mac 上什么能安全删除）也说明，独立开发者愿意为「帮我清理风险」的小工具付费（[Product Hunt feed](https://www.producthunt.com/feed)）。

### 3. 目标用户 + 具体痛点

**用户一：2-10 人的独立开发/小团队。** 同时用 Claude Code、Cursor、Codex，项目根目录有 `.claude/settings.local.json`、`.mcp.json`、`.env`。为了省事，把测试库连接串直接写进 MCP server 的 `env`；为了让 Agent 跑 migration，把生产只读库地址也塞进去。某次 `git add .` 之后仓库变公开，或者 fork 给朋友看，密钥就出去了。痛点是：不知道哪些文件会被提交、不知道哪些 key 已经泄露、不知道怎么轮换。

**用户二：接私活/外包的 Java 开发者。** 客户代码不能出内网，但交付时把整个项目目录（包括 `.claude/`、`.cursor/`、本地 shell 历史）打包发走；客户仓库里还留着上一任开发者配置的 MCP token。痛点是：删除文件不等于删除历史；客户审计时要求提供「已清理」的证据，而不是一句「我删了」。

**用户三：20-100 人团队的技术负责人。** 需要给团队定「AI 编程工具使用规范」，但现有 gitleaks/TruffleHog 只覆盖通用代码规则，不认 Claude Code 的 permission 命令、不认 MCP 的 `env` 块、不认 `.claude/settings.local.json` 这种「配置里嵌命令」的格式。痛点是：需要一个 5 分钟能跑完、能出报告、能接 CI 的检查，而不是再买一个重型 SAST。

### 4. MVP 范围

**做：**

- `agentleak scan [path]`：默认扫描当前目录，识别 `.claude/settings.local.json`、`.claude/settings.json`、`.mcp.json`、`.cursor/mcp.json`、`.env*`、`CLAUDE.md`、`AGENTS.md`、shell 历史、以及 Git 已跟踪文件。
- 规则包：Anthropic/OpenAI/GitHub/AWS/Slack/Stripe 等 40+ provider 格式、私钥、JWT、数据库 URI、内网 IP、高熵字符串；额外识别「权限命令里嵌密钥」和「MCP env 里的明文凭据」。
- 上下文判断：只报 Git 已跟踪或 `--git-history` 中出现的文件，尊重 `.gitignore`，跳过 `node_modules`、`target`、`dist`，把误报压到可接受。
- 输出：表格 / JSON / SARIF；每条给文件、行号、脱敏预览、严重级别、修复建议；`--fail-on high` 接 CI；`--baseline` 只报新增。
- 修复辅助：生成 `.gitignore` 补丁、`git filter-repo` 清理命令、轮换清单、pre-commit hook、GitHub Action。
- 本地优先：默认零网络请求，不上传任何文件内容；密钥只显示前后各 4 位。

**明确砍掉：**

- 不做自动轮换密钥（风险太高，做错一次就失去信任）。
- 不做在线密钥有效性验证（会把密钥发给第三方）。
- 不做完整 SAST、不做依赖漏洞扫描、不做容器镜像扫描。
- MVP 不做团队 Dashboard、不做 Windows GUI、不做多租户 SaaS。
- 第一版不接 LLM；规则和上下文判断足够，LLM 只会增加隐私顾虑和误报。

### 5. 技术方案

**选型：Java 21 + Picocli + Jackson + JGit + Maven Shade，GraalVM native-image 作为可选分发。** 这是 CLI，不是 Web 服务，不建议上 Spring Boot：冷启动、内存、打包体积都不划算；但核心扫描模块可以做成纯 Java library，后续给 Spring Boot 团队版复用。Quarkus native 是备选，如果 GraalVM 反射配置太痛再换。

**关键模块：**

- `scanner-core`：目录遍历、`.gitignore` 解析、Git 跟踪状态判断、文件大小/二进制过滤。
- `detectors`：正则规则 + 熵检测 + provider 校验位（如 GitHub token 前缀）；规则用 YAML 描述（`id`、`provider`、`regex`、`entropy`、`paths`、`severity`、`remediation`），方便社区贡献。
- `config-parsers`：JSON/YAML/TOML/shell 的轻量解析；重点是 `.claude/settings.local.json` 的 `permissions.allow` 命令数组和 `.mcp.json` 的 `mcpServers.*.env`。
- `reporter`：table/JSON/SARIF；SARIF 直接对接 GitHub Code Scanning。
- `fixers`：`.gitignore` 补丁、pre-commit hook、GitHub Action 模板、轮换 checklist。
- `cli`：`scan`、`rules list`、`rules test`、`init` 四个命令。

**可复用现成库/框架：** JGit（历史与跟踪状态）、Jackson（JSON/YAML/TOML）、Picocli（命令行）、JUnit 5 + AssertJ（规则 fixture 测试）、GraalVM（原生二进制）、GitHub Actions（矩阵构建与发布）。OS keychain 通过 `security`（macOS）/`secret-tool`（Linux）调用，不自己实现加密存储。

**工程要点：** 规则 fixture 仓库要覆盖「误报」和「漏报」两类样本；对每个 provider 做前缀/长度/字符集校验，降低熵检测误报；输出必须默认脱敏；发布签名和 SBOM，避免自己成为供应链风险。

### 8. 风险与壁垒

**风险：**

- Anthropic 已表示在考虑内置密钥扫描；gitleaks/TruffleHog/Apiiro 也可能补上 `.claude` 规则，纯扫描功能会被商品化。
- 误报会快速消耗信任；一次把正常配置误报成「高危」就可能导致卸载。
- CLI 付费意愿低，用户习惯免费安全工具；靠买断很难形成稳定收入。
- 扫描客户代码涉及合规，必须默认不上传、不联网，并在 README 里写清楚。

**壁垒：**

- 对 AI 编程工具配置格式的持续跟踪（Claude Code、Cursor、Codex、MCP 各自不同，且每月在变）。
- 「发现 + 修复」闭环：轮换步骤、Git 历史清理、CI 门禁、团队规范模板，而不是一个正则列表。
- 中文团队/外包交付场景的合规模板，是通用国际工具不会重点做的。
- 先发内容资产：公开报告、规则库、误报案例，会形成搜索和信任复利。

**止损线：** 4 周内拿到 100 次真实扫描、至少 3 个付费用户；达不到就停止独立发展，把扫描能力并进 B 作为「安全前置检查」功能。

### 9. 第一步行动

本周做一件具体的事：用 Java 21 + Picocli 写一个 300 行左右的 `scan` 命令，只支持 `.claude/settings.local.json` 和 `.mcp.json` 两个文件、10 条规则；在 GitHub 上找 20 个公开仓库跑一遍，把结果脱敏后写成一篇 1,500 字的「AI 编程工具泄露自查报告」，配 2 分钟演示视频，发给 5 个用 Claude Code 的 Java 开发者，请他们各自在自己的项目上跑一次。成功标准不是 star 数，而是至少 3 个人回复「我确实扫出了一个真密钥」。

## 【B】JVM Ops MCP：给编码智能体的 Java 生产环境「只读安全通道」

### 1. 机会点

把 Spring Boot 的 Actuator、Prometheus 指标、Loki/ELK 日志、只读 SQL 解释计划封装成受策略约束的 MCP 工具，让 Claude Code / Cursor 能查生产问题，但拿不到写权限、看不到明文敏感字段、每一步都有审计。

### 2. 为什么是现在

「让 Agent 接入系统」已经从演示走进日常。GitHub Trending 11 月 11 日抓取中，`homeassistant-ai/ha-mcp` 单日 +790 stars、`vercel-labs/agent-browser` +780 stars、`anthropics/skills` +1,679 stars（[GitHub Trending](https://github.com/trending)）：MCP 不再是极客玩具，而是 Agent 接触真实系统的标准接法。Product Hunt 11 月 10 日的 Mitra MCP 直接把「给你的 AI Agent 一条个人电话线」作为卖点，11 月 5 日的 Skillbox 做「一个库，同步到所有 Agent」，11 月 9 日的 SideKick 做「Claude，但专门服务于你的产品」（[Product Hunt feed](https://www.producthunt.com/feed)）。这些产品都在证明一件事：Agent 的价值不在聊天，而在「能操作某个具体系统」。

但接入的反面是风险。HN 11 月 10 日 400 分的 VulnCheck 讨论（[链接](https://news.ycombinator.com/item?id=50447074)）说明，AI 发现漏洞的速度已经超过维护者修复的速度；把 Agent 接到生产环境，如果没有权限边界和审计，等于把「发现」升级成「利用」。V2EX 11 月 11 日抓取时也有两个很典型的信号：一个是[开源多 Agent 调度平台](https://www.v2ex.com/t/1256245)，一个是[浏览器插件让 Agent 直接操作日常 Chrome](https://www.v2ex.com/t/1256238)。中文开发者已经在把 Agent 往真实系统里接，但 Java 生产环境这一层，仍然缺少「安全的接法」。

Java 生态的缺口很具体：通用的 Postgres MCP server 要一个能 `SELECT *` 的账号；文件系统 MCP server 要一个能读整台机器的权限；Actuator 虽然暴露了 health/metrics，但它是 HTTP/JSON，不是 Agent 友好的工具语义，也没有字段脱敏、行数限制、审计。on-call 工程师现在的做法是：把 200 行日志复制到聊天框，把慢 SQL 粘贴给模型，把数据库密码临时写进 MCP 配置。这个过程既低效，又不可审计。

### 3. 目标用户 + 具体痛点

**用户一：20-200 人的 Java 团队，3-10 个 Spring Boot 服务，跑在 K8s 上，监控用 Prometheus + Loki/ELK，数据库 MySQL/PostgreSQL。** 有 1-2 个 SRE 或平台工程师，但没有专职可观测性团队。

**用户二：on-call 后端工程师。** 凌晨两点收到告警，Claude Code 能读代码，但读不到当前实例的线程状态、最近 30 分钟的 P99、错误日志里的 traceId。他只能手动复制粘贴，既要小心别把手机号/身份证号带出去，又要小心不要把生产库密码发到模型上下文里。痛点是「Agent 看不见运行时」，而不是「Agent 不会写代码」。

**用户三：后端负责人/平台工程负责人。** 想推广 AI 辅助排障，但安全团队会问三个问题：Agent 能执行写操作吗？能拿到哪些字段？谁在什么时候查了什么？如果答不上来，工具就进不了生产。痛点是「缺少一个能过安全评审的 MCP 接入层」。

**用户四：给客户做私有化交付的外包/集成商。** 客户内网不能连外网，不能把日志传到 SaaS；需要一个能本地部署、能出审计报告、能限制到「只看某个 namespace 的某个服务」的套件。

### 4. MVP 范围

**做：**

- 一个独立部署的 Spring Boot 应用，同时支持 MCP over stdio（本地开发）和 Streamable HTTP（团队共享）；可以作为 sidecar 跑在服务 Pod 里，也可以独立部署。
- 六个只读工具：
  1. `service_health(service)`：Actuator health/readiness、uptime、build version、实例列表。
  2. `query_metrics(service, metric, start, end, step)`：Prometheus `query_range`，只允许白名单指标，返回聚合值而非原始高基数标签。
  3. `search_logs(service, query, start, end, limit)`：Loki/ELK 查询，强制时间窗和条数上限，返回前 200 行，自动脱敏手机号/身份证/邮箱/银行卡。
  4. `thread_dump(service)`：Actuator threaddump，只返回 blocked/waiting 最多的前 50 个线程栈，不返回全量。
  5. `explain_sql(service, sql)`：只允许 `SELECT`/`EXPLAIN`，用 JSqlParser 做 AST 白名单，只读数据源、5 秒超时、最多 100 行。
  6. `config_snapshot(service)`：Spring Environment 的白名单 key，敏感值统一打码。
- 策略引擎：YAML 配置 `services`、`tools`、`environments`、`masking`、`limits`、`rbac`；默认拒绝，生产环境需要 OIDC 组权限。
- 审计：JSONL 记录 actor、tool、参数（脱敏）、耗时、返回行数、拒绝原因；可选输出 OTel。
- 交付：Docker 镜像 + Helm chart + `docker-compose` 演示（一个 Spring Boot demo + MySQL + Prometheus + Loki），10 分钟能跑起来。

**明确砍掉：**

- 不做写操作：不重启、不扩容、不回滚、不执行 DDL/DML。
- 不做自动修复/自动根因分析；Agent 是客户端，产品只提供「安全的工具」。
- MVP 不做多集群、不做多租户 SaaS、不做 Web UI。
- 不做 JFR 录制（启动 JFR 是写动作，放二期做「读取已有 recording」）。
- 不在服务端内置 LLM；需要总结时让客户端 Agent 做，避免把日志再传给第二个模型。

### 5. 技术方案

**选型：Java 21 + Spring Boot 3.5（或团队现有 3.x 版本）+ Spring AI MCP Server Boot Starter（或官方 MCP Java SDK）+ Actuator + Micrometer。** 这是最贴合 8 年 Java 经验的一套：Actuator 直接复用，OIDC/配置/健康检查都是现成的，团队也容易接手。Quarkus native 可以作为「低内存 sidecar」的备选，但不建议第一版就上，native 的反射/序列化坑会拖慢交付。LangChain4j 只用于二期的「日志摘要/变更说明」可选功能，不放进核心链路——这个产品的核心是协议、权限和审计，不是 Agent 框架。

**关键模块：**

- `mcp-server`：工具注册、参数校验、JSON Schema、错误码；stdio 和 HTTP 两种 transport。
- `connectors`：Actuator（HTTP）、Prometheus（HTTP API）、Loki（HTTP API）、JDBC（HikariCP 只读连接池）。
- `policy`：YAML 解析、默认拒绝、环境/服务/工具三级白名单、RBAC 映射。
- `masking`：正则 + 字段名规则；手机号、身份证、邮箱、银行卡、token；支持自定义脱敏规则。
- `audit`：JSONL + 可选 OTel；参数只记录 hash 或脱敏值；支持按天轮转。
- `auth`：OIDC（Keycloak/Okta/飞书）、本地 token（开发用）。
- `helm`/`compose`：一键演示与部署。

**可复用现成库/框架：** Spring Boot Actuator、Micrometer、Prometheus HTTP API、Loki HTTP API、HikariCP、JSqlParser、Caffeine（限流）、Resilience4j（超时/熔断）、Logback JSON encoder、OpenTelemetry、Testcontainers。

**安全设计（这是产品的生命线）：**

- 数据库必须用单独的只读账号；连接初始化执行 `SET SESSION TRANSACTION READ ONLY`；语句超时 5 秒；最大返回 100 行。
- SQL 用 AST 做白名单：只允许 `SELECT`/`EXPLAIN`，禁止 `INTO OUTFILE`、存储过程、多语句、注释注入；对 `information_schema` 只开放表/列元数据。
- 日志查询限制时间窗（默认 30 分钟，最大 24 小时）和条数；返回前做 PII 脱敏；响应体大小上限 1 MB。
- 每个 actor/tool 做令牌桶限流；生产环境默认需要 OIDC 组；拒绝原因也写审计。
- 镜像签名 + SBOM；网络出口白名单（只允许 Prometheus/Loki/DB）；配置里不允许出现明文密码，走 Secret 挂载。
- 企业版前做一次第三方威胁建模/渗透测试，预算 ¥10,000-30,000；这不是可选项，是卖企业版的门票。

## 【C】LegacyContext：Java 遗留系统的「AI 可改造上下文包」引擎

### 1. 机会点

把 5-15 年的 Spring/MyBatis 单体自动编译成一份 Agent 可查询的「系统说明书 + 变更影响图 + 特征测试缺口」，让 AI 改得动、改得对，而不是只会生成看起来能编译的代码。

### 2. 为什么是现在

Agent 写代码的能力已经够用，瓶颈转移到了「上下文」。HN 11 月 10 日 368 分的 [Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives](https://news.ycombinator.com/item?id=50443812) 说得很直接：Agent 会默认写出过时的 JavaScript，因为它的上下文里没有「这个项目现在的最佳实践」；GoogleChrome 为此专门做了一个 guidance 仓库（[modern-web-guidance](https://github.com/GoogleChrome/modern-web-guidance)）。前端尚且如此，一个 10 年历史、混合了 Spring XML、MyBatis XML、AOP、MQ、定时任务的 Java 单体，问题只会更严重。

第二层信号是「上下文/技能」正在成为独立的产品层。GitHub Trending 11 月 11 日抓取中，`anthropics/skills` 单日 +1,679 stars、`mattpocock/skills` +1,225 stars、`ranxianglei/billion-context` +375 stars（[GitHub Trending](https://github.com/trending)）；Product Hunt 11 月 9 日的 Inspo by Context.dev 做「给编码 Agent 的真实网站灵感」，11 月 5 日的 Skillbox 做「一个库，同步到所有 Agent」（[Product Hunt feed](https://www.producthunt.com/feed)）。这说明「把私有上下文打包给 Agent」已经被验证是一个需求，只是目前集中在前端/设计/通用技能，Java 遗留系统几乎没人认真做。

第三层是开发者的真实抱怨。V2EX 11 月 11 日抓取时，[「大家是怎么使用 AI 来做开发的」](https://www.v2ex.com/t/1256241) 在讨论 plan mode、spec、Agent 编排；[「AI 只是提效了，并没有让程序员更轻松，反而更加累了」](https://www.v2ex.com/t/1256221) 则在说：工具变多了，但上下文、验证、回归的成本都压回到了人身上。HN 11 月 10 日 231 分的 [Claude Whiteboards, Claude Sheets, and Claude Data](https://news.ycombinator.com/item?id=50443716) 也说明模型厂商在往通用知识工作扩张，但「你公司那套 10 年没写文档的系统」仍然只能靠自己补上下文。

### 3. 目标用户 + 具体痛点

**用户一：20-200 人研发团队里的架构师/技术负责人。** 手里有一套 5-15 年的 Java 单体，Spring MVC/Boot + MyBatis/Hibernate + RabbitMQ/Kafka + Quartz/XXL-Job，测试覆盖率低，核心开发只有 2-3 个人。痛点是：想让 AI 帮忙做需求/修 bug，但 AI 只看到当前文件，不知道改一个订单状态字段会影响 7 个 MQ consumer、3 个定时任务、2 个报表 SQL；改完编译通过，线上回归炸了。

**用户二：刚接手遗留系统的 Tech Lead。** 架构图是 3 年前的 PPT，注释一半失效，老员工即将离职。痛点是：新人上手要 2-4 周；每次评审都要靠「谁记得」；想把系统迁移到新框架，但不知道边界在哪。

**用户三：做企业软件交付/现代化的集成商。** 客户要求「用 AI 提升改造效率」，但代码不能上传 SaaS，交付周期又被压缩。痛点是：评估靠人肉读代码，报价靠拍脑袋；需要一个能本地跑、能出报告、能证明「哪些地方 AI 不能碰」的工具。

**具体痛点可以细到：**

- 「订单状态字段 `status` 在 14 个类里被读写，其中 3 个是反射调用，静态分析看不到。」
- 「`@Transactional` 有 200 多处，事务边界、幂等、重试逻辑散在注解、XML 和注释里，Agent 读不懂。」
- 「MyBatis 的 SQL 写在 XML 里，表名是动态拼接的，Agent 改完 Java 代码不知道 SQL 也要改。」
- 「不敢把代码传到 Cursor/SaaS；本地模型又不够聪明，需要把上下文压缩成它能用的形式。」

### 4. MVP 范围

**做：**

- `legacycontext index --repo . --out .legacycontext`：本地索引，输出一个目录（可直接 gitignore）。
- 解析：Java AST（JavaParser + Symbol Solver）、Spring 注解（`@RestController`、`@Service`、`@Transactional`、`@Scheduled`、`@KafkaListener`、`@RabbitListener`）、MyBatis XML、JPA、Flyway/Liquibase DDL、Maven/Gradle 依赖。
- 图模型：模块/类/方法/表/topic/job 节点，边包括调用、读写表、生产/消费消息、定时触发、HTTP 入口。
- 生成物：
  - `repo-map.md`：模块、包、入口、配置、外部依赖。
  - `AGENTS.md` / `CLAUDE.md`：项目约定、禁用模式、关键不变量、「不要碰」清单。
  - `impact.md`：给定符号，列出受影响端点、表、topic、job、测试。
  - `test-gaps.md`：核心流程中没有测试覆盖的环节，按风险排序。
- MCP server：`search_symbol`、`get_callers`、`get_table_usage`、`get_change_impact`、`get_invariants`。
- 置信度：每条边标记 `static` / `inferred` / `unknown`；反射、AOP、动态 SQL 明确报「未知」，不假装全知。

**明确砍掉：**

- 不做自动重构/自动改代码；第一版只提供上下文和影响分析。
- 不做运行时 tracing/APM；静态图 + 现有日志/调用链先够用。
- 不做多语言（先 Java/Spring/MyBatis），不做前端、Go、Python。
- 不做托管 SaaS/Web UI；第一版本地 CLI + MCP，解决「代码不能出内网」。
- 不做全自动测试生成；只生成测试缺口报告和 3-5 个关键流程的 Testcontainers 测试骨架。

### 5. 技术方案

**选型：Java 21 + JavaParser + Symbol Solver + Picocli + SQLite（递归 CTE）+ MCP Java SDK。** 8 年 Java 的优势在这里最大：AST、Spring 生命周期、MyBatis、Maven/Gradle、Testcontainers，都是日常工具。Quarkus native 可以作为 CLI 分发备选；Spring Boot 适合后续做团队版服务端/UI。LangChain4j 只用于把图数据润色成人类可读的文档，不参与事实判定——图的边必须来自 AST/配置，不能来自模型幻觉。

**关键模块：**

- `parser-java`：JavaParser + Symbol Solver，解析类/方法/字段/调用；对无法解析的符号标记 unknown。
- `parser-spring`：注解扫描、Bean 依赖、事务边界、MVC 入口、定时任务、消息监听。
- `parser-mybatis`：XML mapper、动态 SQL、`resultMap`、表/列映射；把 SQL 里的表名抽出来。
- `graph`：SQLite 节点/边表 + 递归 CTE；数据量大时换 Kuzu 嵌入式图数据库。
- `impact`：从符号出发做 1-3 跳影响分析，按「入口/表/topic/job/test」分组，输出置信度。
- `docgen`：Mustache 模板生成 `AGENTS.md`/`repo-map.md`/`test-gaps.md`；确定性输出，可 diff。
- `mcp`：把图查询暴露成 MCP 工具，让 Claude Code/Cursor 在改代码前先查影响。
- `testgen`：只为 3-5 个关键流程生成 Testcontainers 骨架（MySQL/PostgreSQL/RabbitMQ/Kafka），不追求全量。

**可复用现成库/框架：** JavaParser、Spoon（更深的语义分析备选）、Spring Boot、MyBatis、SQLite、Kuzu、Mustache、MCP Java SDK、LangChain4j（可选，本地 Ollama）、Testcontainers、Maven/Gradle API。

**工程要点：**

- 增量索引：按 Git diff 只重算受影响文件；大仓库首次索引控制在 10 分钟内。
- 置信度：静态分析不可能 100% 准确，必须把「unknown」当成一等公民；影响报告要写「以下 3 处为反射调用，需人工确认」。
- 本地优先：默认不上传代码；所有 LLM 调用走本地 Ollama 或客户自己的网关；输出目录默认加入 `.gitignore`。
- 可复现：同一 commit 的索引结果 deterministic；文档生成带版本号和 commit hash。

## 本周机会小结 + 建议优先做哪一个

本周日报 7 天全空，没有强宏观催化，反而适合做「窄而深」的验证。三个方向其实是一条价值链：**A 守住入口**（AI 编程工具的密钥/配置安全），**B 打开出口**（让 Agent 安全地看生产运行时），**C 补上大脑**（让 Agent 理解遗留系统）。它们分别对应「提交前」「运行时」「改造前」三个时间点，彼此不重叠。

**建议优先做 B（JVM Ops MCP），而不是 A 或 C。** 理由有三点：

1. **和 8 年 Java 经验的复合度最高。** Spring Boot Actuator、Micrometer、JVM 线程/内存、Hikari、MyBatis、Prometheus/Loki，这些是你已经会的；不需要重新学一套前端或算法，优势可以直接变成产品深度。
2. **付费场景最具体。** on-call 排障、安全评审、私有化交付，都是企业已经在花钱的地方；A 的付费意愿偏弱，C 的销售周期偏长。B 只需要 1-5 个 Team 客户就能到月入 2k-1w，3-6 个月是够得着的。
3. **有安全壁垒，不容易被通用工具一夜替代。** 通用 MCP proxy 只能解决「连得上」，B 解决的是「敢不敢连」：只读、脱敏、限流、审计、私有化。这些是安全评审真正卡的点。

**具体节奏建议：**

- **第 1 周：** A 的 CLI 先做出来（周末 5 小时），当作获客内容；同时搭 B 的 `docker-compose` demo。
- **第 2 周：** B 完成 3 个工具（health / explain_sql / search_logs），录 3 分钟视频，约 5 个 Java 团队负责人聊；A 发一篇泄露自查报告。
- **第 3 周：** 挑 1-2 个愿意给反馈的团队做免费设计伙伴，部署到他们的测试环境；A 根据反馈补规则，但不投入超过 5 小时/周。
- **第 4 周：** 把设计伙伴转成付费 pilot（¥1,999/月，或一次性 ¥5,000 实施费）；如果转不动，就缩小到「慢 SQL 解释器」单点，再验证一次。

**C 不要现在重投入。** 它天花板最高，但需要企业信任、案例和 3-6 个月的前置投入；更适合作为「期权」：等 B 带来 3 个企业对话、你手里有 2 个真实案例之后，再把 C 的 context pack 作为 B 的增值模块推给同一批客户。这样既不影响主线，也不会错过遗留系统改造的长期机会。

**统一止损标准：** 30 天内，B 拿到 10 个有效对话、3 个设计伙伴、1 个付费 pilot；A 拿到 100 次扫描、3 个付费用户。任何一个指标明显达不到，就先砍功能、缩场景，而不是继续堆代码。副业最贵的不是开发时间，是「做了六个月才发现没人付钱」。

# 印尼 WhatsApp CRM 测试与生产诊断 MCP 技术设计方案

> 文档日期：2026-10-30  
> 状态：测试环境和印尼生产环境工具均已实现；测试环境 Apollo 已改为按需只读查询，生产日志通过 Chrome 页面桥接查询  
> 范围：印尼 WhatsApp CRM 测试与生产环境的日志、MySQL、MongoDB、Apollo 配置只读排查

## 1. 背景与目标

现有 `business-diagnostic-mcp` 面向测试环境，独立的 `idn-production-diagnostics-mcp` 面向印尼生产环境。测试日志存储在测试环境 `test_log` 表中，生产日志位于 Kibana Discover，测试和生产业务数据均通过各自的数据访问层查询。本方案统一记录两套诊断工具的边界和协作方式，目标是：

1. 测试工具只能访问测试环境，生产工具只有在用户明确说明“印尼生产”时允许调用。
2. 支持测试和生产日志、MySQL、MongoDB、Apollo 配置证据的只读查询。
3. 日志、数据库和 Apollo 工具可以独立使用，也可以根据问题上下文联合排查。
4. 不开放任意 KQL、SQL 或 MongoDB 命令。
5. 通过固定实例、实时 schema 校验、查询上限、批量拆分和服务端环境确认降低误操作风险。
6. 通过独立 MCP、独立工具名和服务端环境校验区分测试环境与生产环境。

## 6. 按问题上下文选择数据源

工具不会因为用户提到一个模板名、任务 ID 或 traceId 就自动读取所有数据源。统一判断顺序如下：

1. 先理解问题涉及的业务流程、服务和代码调用点；
2. 如果需要确认执行链路、异常和处理结果，查询对应环境日志；
3. 如果需要确认持久化状态、模板状态、消息状态或任务数据，查询对应环境 MySQL/MongoDB；
4. 如果代码显示某个开关、阈值、路由、策略或灰度配置可能影响结论，再读取相关 Apollo 配置证据；
5. 如果配置已经迁移到 `resource_lane_config`，查询数据库镜像；如果需要确认运行时变更或日志中的配置证据，再查询相关日志；
6. 如果无法从代码、schema 或已确认数据来源定位配置，不猜表名、字段名或 namespace，直接返回需要补充定位的信息。

测试和生产都采用这套按需原则，但数据源和工具必须保持对应环境。

## 7. 生产日志工具

工具名称：`idn_prod_query_logs`

### 7.1 输入约束

支持：

- `environmentConfirmation`：必须为 `idn-prod`；
- `keyword`：业务关键词；
- `traceId`：完整链路标识；
- `timeStart`、`timeEnd`：查询时间段。

`keyword` 和 `traceId` 必须恰好提供一个。

### 7.2 时间范围

支持相对时间：

```text
now-30m -> now
now-9h  -> now
now-2d  -> now
```

支持带时区的 ISO-8601 绝对时间。约束：

- 开始时间和结束时间必须同时存在；
- 绝对时间必须包含时区；
- 开始时间不能晚于结束时间；
- 单次范围最大 7 天；
- 不擅自用默认时间替代用户明确指定的范围。

### 7.3 关键词与 traceId

用户说“模板aaa”时，日志检索关键词是 `aaa`，“模板”只是排查上下文。

日志查询不开放任意 KQL，只由工具内部生成固定结构：

```text
时间范围 + message match_phrase(keyword 或 traceId)
```

日志消息中的 `traceId:[...]` 用于提取 traceId 并按链路分组。不能简单写死“创建模板只查 job”，应根据 traceId、模板 ID、任务 ID、消息 ID、服务和时间关系判断 API、job、mq 等链路是否相关。

### 7.4 返回标识

日志结果包含：

```json
{
  "environment":"idn-prod",
  "source":"kibana-discover",
  "readOnly":true
}
```

超过查询上限时返回 `truncated: true`。

### 7.5 当前状态

- 请求构造、时间解析、关键词和 traceId 解析已有本地测试；
- 已通过已登录 Discover 页面实际查到一个指定 trace 的日志；
- 已通过 Chrome 页面桥接实际查询指定 trace 日志；
- 扩展未加载、桥接未运行或 Kibana 登录态失效时，工具会明确报错；

### 8.2 结构化查询

不接受原始 SQL，只接受结构化请求：

```json
{
  "table":"message_template",
  "columns":["id","name","status"],
  "where":[{"field":"name","op":"eq","value":"example-template"}],
  "orderBy":[{"field":"id","direction":"desc"}],
  "limit":10
}
```

工具内部生成完整 SQL 后提交 DBS。

### 8.3 允许和禁止的操作

只允许：

```text
SELECT
COUNT
EXPLAIN SELECT
```

拒绝：

```text
INSERT、UPDATE、DELETE、REPLACE
CREATE、ALTER、DROP、TRUNCATE
CALL、SET、事务控制、多语句、SQL 注释
INTO OUTFILE、INTO DUMPFILE
FOR UPDATE、LOCK IN SHARE MODE
```

### 8.4 Schema 获取规则

工具中不维护“业务对象 → 表/字段”的映射表。正确流程是：

```text
用户提供业务线索
  -> 阅读实体、Mapper、SQL 定位目标表
  -> idn_prod_get_schema 后台执行 SHOW FULL COLUMNS
  -> 从真实 schema 确认字段
  -> 生成结构化只读查询
```

`idn_prod_get_schema` 的 MySQL 路径已实际验证：通过 DBS 后台执行：

```sql
SHOW FULL COLUMNS FROM `message_template`
```

不需要打开页面，返回 `schemaSource: "show-full-columns"`。

已确认的 `message_template` 关键字段：

```text

name                 -- 模板名称

shadow_status

```

此前使用 `template_name`、`waba_template_name` 属于错误假设，已废弃。

### 9.2 查询结构

MongoDB 必须生成 DBS 接受的以下结构：

```javascript
db.message_record.find(
    {"template_name":{"$in":["name-a","name-b"]},"send_time":{"$gte":ISODate("2026-10-22T00:00:00+08:00"),"$lt":ISODate("2026-10-28T00:00:00+08:00")}},
    {"task_id":1,"msg_status":1,"send_time":1}
).sort({"send_time":-1}).limit(5)
```

固定顺序：

```text
find(filter, projection).sort(sort).limit(limit)
```

时间条件使用 `ISODate(...)`。无时区或非法时间直接拒绝。

### 9.3 允许和禁止的操作

只允许：

```text
find
countDocuments
explain
```

拒绝：

```text
insert、update、delete、aggregate
$where、$function、$accumulator、$out、$merge
```

### 9.4 集合与字段确认

当前集合：

```text
message_record
sub_task_data
sub_task_data_20250731
business_phone_stats
message_material
whatsapp_task_metrics
```

MongoDB 当前没有像 MySQL `SHOW FULL COLUMNS` 一样可用的通用 schema 查询。`idn_prod_get_schema` 返回代码模型或已确认字段白名单，并标记：

```json
{
  "schemaSource":"code-model-allowlist",
  "schemaVerified":false
}
```

Mongo 字段应从实体、Mapper、已有日志或已确认查询结果确定，不能根据业务名称猜测。

`$in`、`$nin` 超过 500 个值时自动分批。

## 11. 只读与脱敏

测试环境和生产环境都采用工具层只读保护，但账号权限和连接方式分开管理：

- 测试 MCP：MySQL JDBC 会话设置为只读，并在执行前通过 `ReadOnlyGuard` 校验；MongoDB 只生成 `find`、`countDocuments` 和 `explain`；Apollo 只查询数据库镜像或日志。
- 生产 MCP：MySQL/MongoDB 通过 DBS 发送前再次校验；生产日志只调用固定 Kibana 搜索接口；Apollo 只查询已确认的数据库字段或有限日志证据。
- 两套 MCP 都不接受原始写 SQL、MongoDB 写命令、Apollo 发布/修改/删除/回滚参数。


只读保护包括：

1. 测试 MCP 和生产 MCP 都只暴露读取工具；
2. 生产 MCP 强制 `environmentConfirmation=idn-prod`，测试 MCP 拒绝生产环境名称；
3. MySQL 只生成 SELECT、COUNT、EXPLAIN，以及受限的 schema 读取；
4. MongoDB 只生成 find、countDocuments、explain；
5. Apollo 只读取已确认的数据库镜像字段或有限日志证据，不调用 Apollo 写接口；
6. 表、字段、集合、操作符经过校验；
7. 单次查询有返回上限，大批量条件强制分批；
8. HTTP 客户端只允许固定 HTTPS 域名和路径。

默认脱敏字段：

```text
phone、mobile、business_phone、customer_phone、phone_number、email、openid、open_id
```

### 11.1 只读不等于账号只读

实际 `SHOW FULL COLUMNS` 结果显示，当前 DBS 账号对 `message_template` 具备 `SELECT,INSERT,UPDATE`。工具只能约束自身行为，不能撤销账号已有权限。

### 11.2 当前脱敏缺口

- 普通数据库列已按列名脱敏；
- `mongodballdata` 嵌套 JSON 尚未递归脱敏；
- 日志不自动落盘；后续如增加报告落盘，必须重新设计日志敏感信息处理。

## 15. 已知限制

### 15.1 Apollo 配置按需只读查询

Apollo 不再通过 SDK 读取，也不调用 Apollo 发布、修改、删除或回滚接口。业务代码定位到配置 namespace/key 后，工具按需读取与当前问题相关的 `resource_lane_config` 行或有限日志证据；该表字段已通过测试和生产数据库 schema 确认。对于没有数据库镜像、日志也没有相关证据的配置，工具返回无法确认，不猜测其他表或字段。工具拒绝没有上下文范围的全量读取，配置值中的密钥、token、密码等内容默认脱敏。

### 15.2 Kibana 使用本机页面桥接

日志 MCP 不再通过 `browser_cookie3` 读取 Chrome Cookie。MCP 在 `127.0.0.1` 启动只读桥接服务；Chrome 扩展轮询桥接请求，自动复用或创建 `log.rupiahcepatweb.com` 标签页，并在该页面上下文中使用当前登录态调用固定 Kibana 搜索接口。

桥接服务会拒绝非 HTTPS 日志域名、非 `/internal/search/es` 路径、非 `*whatsapp*` 数据视图、超限结果和认证头转发。扩展不申请 `cookies` 权限，令牌通过请求头传递。用户不需要手动打开 Discover 页面或把日志页切到前台。

### 15.3 MongoDB 嵌套 JSON 脱敏不完整

`mongodballdata` 是 DBS 自动附加的原始文档 JSON，可能包含 `customer_phone`、`business_phone` 等敏感字段。当前只对独立列脱敏，尚未递归处理该 JSON。

### 15.4 MongoDB schema 非实时

MySQL 可通过 `SHOW FULL COLUMNS` 读取实时字段。MongoDB 没有同样可用的通用 schema 查询，必须结合实体、Mapper 和已确认查询结果。

### 15.5 工具只读不等于账号只读

当前 DBS 账号权限包含写权限。工具层只读约束必须保留；若后续能申请专用只读账号，应优先切换。
